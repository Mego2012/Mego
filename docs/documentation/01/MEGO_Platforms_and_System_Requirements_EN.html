Purpose and scope

This document states on which platforms MEGO runs, what a user's device and browser need, which hosted services the product depends on (and their free-tier limits), and what an owner's or developer's computer needs to set up, build and test MEGO. It separates what has been tested from what is only expected to work.

2.1 Installing on Android

  1. Open https://mego2012.github.io/Mego/ in Chrome.
  2. Menu ⋮ → Add to Home screen / Install app (Samsung Internet: menu → Add page to → Home screen).
  3. Start MEGO from the icon: it opens full screen without a browser bar.
  4. Settings → Data & backups shows whether "Persistent storage granted" is on. The app requests persistent storage at start-up (requestPersistentStorage in src/lib/db.ts), but the browser decides.

4. Storage, offline use and network

 Device (browser)                                   Internet (when available)
 +-------------------------------+                 +-----------------------------+
 | IndexedDB                     |  sign-in, sync  | Firebase Auth + Firestore   |
 |  guest: mego-nutrition        | <-------------> | (Spark, me-central2)        |
 |  account: mego-u-<uid>       |                 +-----------------------------+
 | Cache Storage (service worker)|  owner Hub sync | Apps Script -> Google Sheet  |
 |  app shell, usda.json,        | <-------------> | Apps Script -> Gemini (AI)  |
 |  photos, fonts (on first use) |  barcode lookup | Open Food Facts             |
 | localStorage (small markers)  | --------------> | Google Fonts                |
 +-------------------------------+                 +-----------------------------+
  • Works offline: diary, foods (including the USDA database), recipes, planner, reports, progress, habits, cardio and workouts, backups to file.
  • Needs a connection: registration and sign-in, cloud sync (changes are queued and uploaded later), owner Hub sync, AI scanner, Open Food Facts lookup, first display of a food photo or font.
  • Data loss risk: guest data lives only in the browser. On 10 Nov 2026 an Android phone lost its IndexedDB; signed-in accounts were recoverable by signing in again (fix in src/lib/cloudSync.ts), guest data would not be. Regular backup files are recommended for guests.

When a free limit is reached the service stops (it cannot bill) and the app shows a message. MEGO does not promise unlimited usage. Note: docs/ARCHITECTURE.md mentions a global AI limit of 200/day; the current code default is 40.
