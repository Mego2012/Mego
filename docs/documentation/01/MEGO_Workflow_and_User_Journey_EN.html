Purpose and scope

This document describes how people move through MEGO: from the first launch, through daily, weekly and training-day routines, to multi-device use, recovery and administration. Each journey lists the screens involved, what the app does behind the scenes and the rules that protect the user's data. It describes the current code; detailed button-by-button instructions are in the user guides (folder 02).

  1. Morning: open the Dashboard — Goal − Food = Remaining, macro bars, water, today's training card.
  2. Log meals: in the Diary pick the meal (breakfast, lunch, dinner, snacks) and add foods by search, barcode, photo, saved meal or recipe. Copy yesterday or a meal when eating the same thing (the app asks before adding into a day that already has entries).
  3. Water: quick buttons on Dashboard, Diary or Water & habits.
  4. Close the day: "Mark day complete". Past days with entries count as fully logged automatically when they reach ≥ 60 % of the calorie target (configurable). A day without entries is never counted as zero.

5. Logging with the AI meal scanner

  1. Tap "Take a photo" or "Upload from gallery".
  2. The phone checks and compresses the image and sends it to the owner's Apps Script backend, which asks Gemini (free tier) to identify the items.
  3. The review sheet shows each item with grams (and range), state, cooking method, matched database food and a confidence chip. Uncertain items must be ticked as checked; the user can edit, swap the matched food, add or remove items.
  4. Nutrition is computed by the app from the database. Items not in the database are marked as AI estimates and can only be logged after an explicit choice.
  5. Confirm saves the entries; nothing is saved before. If Google is busy, the app retries after 3 s and 8 s and keeps the photo for a manual retry.

  • The training coach is local, rule-based logic — no AI service. It suggests; the user decides.

8. Recipes and meal planning

  1. My Recipes → Library (101 recipes) or Suggestions (fits what is left today) or Cook ("What can I cook today?").
  2. Open a recipe → add to diary, add to plan, or save as an editable recipe.
  3. Planner → suggest a week plan or build it by hand → shopping list → log the plan → compare planned vs actual.

9. Multi-device use and recovery

  • Second device: sign in with the same account; data downloads and stays in sync live. Older copies never overwrite newer ones.
  • Offline: logging continues; changes upload when the connection returns.
  • Browser storage lost (incident 10 Nov 2026): an Android phone lost its IndexedDB. After the fix, a missing local database resets the sync markers, empty tables download in full and settings are always re-read. The user signs in again and the data returns. Guest data cannot be recovered this way — guests should download backup files.
  • Backups: automatic on-device snapshots (last 10), a pre-update snapshot once per release, manual backup file and merge-only restore in Settings; Settings → Data check compares record counts with the pre-update backup (read-only).
  • Leaving: export data, then delete the account after password confirmation.

10. Owner and administrator workflows

10.1 Owner

  1. On the laptop: node scripts/laptop-setup.mjs (Hub + Apps Script + optional Gemini key) and --cloud for Firebase.
  2. Connect the owner device to the Hub in Settings; foods import from the sheet; changes sync every minute with automatic retry.
  3. Backend updates: git pull && node scripts/laptop-setup.mjs --update-backend.

10.2 Administrator

  1. The owner registers in the app, then runs node scripts/laptop-setup.mjs --cloud <e-mail> again to write admins/{uid}. Not done yet — no administrator exists.
  2. Admin dashboard (#/admin): user counts, account list, suspend/reactivate, review submitted foods, error reports.
