Purpose and scope

This guide explains how your MEGO data is protected and how you can take it out of the app: automatic and manual local backups, the backup file (JSON) and restoring it, exports to CSV / Excel (XLSX), the read-only Data check, the owner's Hub backups, and how a signed-in account recovers its data from the cloud after the phone's browser storage is lost. The technical and operational backup procedures for administrators are in MEGO_Data_Backup_and_Recovery.

1. Where your data lives

ModeLocal database on the phoneCopy outside the phone
GuestIndexedDB mego-nutritionNone automatically. Data exists only on this device unless you download a backup file (or, on the owner's device, connect the Google Sheets Hub).
Signed-in accountIndexedDB mego-u-<account id> (one per account)Cloud Firestore under your account (owner-only access); every change is synced

Synced and backed-up tables: foods, entries, recipes, templates, plans, plannedDays, body, days, settings, foodChanges, kv (cardio, check-ins, workouts, programs, shopping ticks …) and fasts. Not included: progress photos and the local backups themselves.

Important: the automatic local backups are stored inside the same browser database as your data. If the browser deletes the site's storage, those backups are lost too — that is why an external copy (cloud account or a downloaded file) matters.

2. The "Data & backups" area in Settings

Settings → chip Data & backups contains three cards:

  1. Data & backups: persistent-storage status, Download backup file, Restore from backup file, Export full diary (CSV).
  2. Data check: Run check (section 6).
  3. Automatic backups on this phone: the list of local backups with Restore per row and Back up now.

Persistent storage: the app asks the browser to keep its storage. The card shows "✓ Persistent storage granted" or "Persistent storage not granted by the browser (install the app to improve this)". Installing MEGO to the home screen can help; it is the browser's decision.

3. Automatic local backups

A local backup is a full snapshot of all synced tables stored in the device database.

Retention: the last 10 backups are kept, and in addition the 3 most recent "Before app update" backups are never rotated away. Each row shows date, time, reason and size (KB). A line "Pre-update snapshots" lists older pre-migration copies if the database schema was ever upgraded.

Restoring a local backup: tap Restore → confirm "Restore this backup? Current data is backed up first and records are merged (newer wins)." → the result says "Restored: n records merged."

4. Backup file (JSON) and restore

4.1 Download

Download backup file saves mego-nutrition-backup-YYYY-MM-DD-HH-MM-SS.json to the phone's downloads. It contains all synced tables (format mego-nutrition-backup, version 1). The sync connection settings (Hub URL and token) are removed from the file and never exported. Store the file somewhere safe (e.g. your own cloud drive); it contains your personal health data.

4.2 Restore

  1. Tap Restore from backup file and choose the .json file.
  2. MEGO checks the file: it must be valid JSON in the MEGO backup format, every record must have its key, and diary entries must contain nutrition values. An invalid file is rejected without changing anything.
  3. A "Before restore" local backup is saved.
  4. Records are merged: a record from the file is written when it does not exist locally or when its updatedAt is the same or newer. Nothing is deleted. The settings record from the file replaces the local settings, but this device's sync connection is kept.
  5. The app reports "Restored: n records merged."

For a signed-in account, restored records are synced to the cloud like any other change.

7. Owner device: Hub and Google Drive backups

On a device connected to the owner's Google Sheets Hub (Settings → MEGO Nutrition Hub — sync & backup), additional buttons are available:

  • Backup to Google Drive — sends a snapshot to the owner's Apps Script, which saves mego-backup-<date_time>.json in the Drive folder "MEGO Nutrition Backups".
  • Upload everything — queues all records and pushes them to the Hub.
  • Restore from sheet — saves a "Before sheet restore" local backup, then pulls all records from the Hub and merges them.

The backend also copies the Hub spreadsheet once per day before the first food write-back. Details: MEGO_Google_Sheets_Integration_and_Sync.

8. Recovering a signed-in account after storage loss

On 10 Nov 2026 an Android phone lost its browser database (records and sign-in session) while other browser storage survived. The app showed the welcome screen, and after signing in again it stayed empty, because the download started from "last seen" markers that had survived, and a fresh default settings record outranked the saved settings. This had happened once before. It is fixed and live (src/lib/cloudSync.ts, account.ts, repo.ts):

  • The markers were renamed (mego.cloud2.), so every device re-downloads its account in full once.
  • If the account's local database is missing at start-up, the markers are reset; an empty local table is always downloaded in full.
  • Settings are always re-read from the cloud, and untouched default settings never outrank the account's saved settings.
  • One unreadable record never stops the rest of the download.
  • Two weigh-ins for the same date (e.g. re-entered after a loss) keep the newer one on the device; the other stays untouched in the cloud.
  • Newer local copies are never overwritten by older cloud copies.

8.1 What to do if your data seems gone

Signed-in account?
 ├─ yes ─► open MEGO ─► Sign in with the same e-mail and password
 │          └─► keep the app open and online ─► data downloads from the cloud
 │               └─► Settings ─► Data check ─► review counts and "Possible duplicates"
 └─ no (guest) ─► data existed only on this phone
                  └─► Restore from backup file (if you downloaded one), or a local backup if the database still exists
  1. Do not re-enter your old data before signing in — wait for the download first. If you already re-entered some, use Data check → Possible duplicates and delete extra copies yourself.
  2. If something is still missing after the download, check Settings → Automatic backups on this phone (only if the local database survived) or restore your latest backup file.

Lesson: signed-in accounts are recoverable by signing in again; guest data lives only on the device — download a backup file regularly or create an account.

9. Recommended routine

  • Use a signed-in account if you want an automatic copy outside the phone.
  • Download a backup file at least once a week (more important for guests) and keep it outside the phone.
  • Run Data check after an app update or after any suspected data loss.
  • Keep your own copies of progress photos; they are not backed up.
