Purpose and scope

This document describes every source of food data in MEGO, the exact data structures used to store foods, and how a food from a read-only reference source becomes part of a user's own food list. All structures are copied from the code (src/lib/types.ts, src/lib/refFoods.ts, src/lib/barcode.ts, src/lib/mealScanner.ts, scripts/build-food-db.mjs, apps-script/Code.gs).

2. The user foods table (Food record)

Every food the user can log lives in the local table foods (guest database mego-nutrition or per-account database mego-u-<uid>). The interface from src/lib/types.ts:

FieldTypeMeaning
idstringUnique id (crypto.randomUUID)
nameAr / nameEnstringArabic and English names (at least one required)
categorystringFree-text category
per100MacrosNutrients per 100 g (kcal, protein, carbs, fat, optional fiber, sugar, sodium mg, satFat)
state'raw' | 'cooked' | 'other'Weighing state
stateLabelstringOriginal state label (e.g. «مطبوخ/مصنّع»)
prep, notesstringPreparation method; notes (source notes, warnings)
pieceGrams?numberWeight of one piece / slice
gramsPerMl?numberDensity; when absent 1 ml = 1 g
servingsCustomServing[] {id, name, grams}Named servings
favoritebooleanFavorite flag
source'sheet' | 'custom' | 'openfoodfacts' | 'usda'Origin
sourceRef?stringWhere values come from, shown to the user
barcode?, brand?stringPackaged products
sheetKey?, sheetRow?string, numberHub record key and row used for sync
incompletebooleanTrue when kcal, protein, carbs and fat are all 0 (isIncompleteMacros)
archivedbooleanSoft-hidden
version, createdAt, updatedAtnumberRecord versioning (ms timestamps)
lastUsedAt?, useCountnumberUsage statistics for recents/sorting

Creation rules (createFood in src/lib/repo.ts): values must pass validateMacros; a name is required; unless allowDuplicate is set, a food with the same normalized Arabic or English name and the same state is rejected as DUPLICATE:<id>; default source is custom; every creation is written to the change log (foodChanges) and the sync outbox.

Diary snapshots: when a food is logged, its basis (per100, pieceGrams, gramsPerMl, servings) is copied into the diary entry (EntryBasis). Later edits to the food never change past entries.

3. Owner's Google Sheets Hub (160 foods)

The owner's personal food list is kept in the native Google Sheet "MEGO Nutrition Hub", tab Food_Database, which holds 160 foods with stable ids F0001… (verified live: 160 foods, 0 numeric problems). The columns written by apps-script/Code.gs:

food_id, name_ar, name_en, category, kcal_100g, protein_100g, carbs_100g, fat_100g,
fiber_100g, sugar_100g, sodium_mg_100g, piece_g, state, state_label, prep, source,
verification, barcode, notes, active

The app parses this tab with parseStructuredFoods (src/lib/sheetImport.ts). Required columns: food_id, name_ar, kcal_100g, protein_100g, carbs_100g, fat_100g. Rows with active = no are skipped. A blank or unreadable required value marks the food missingValues (imported but blocked from logging). Notes containing ⚠, «غير محقق», «تقريبي», «تقديري» or «للمراجعة» raise the issue flaggedInNotes. The verification column takes values verified-usda / estimated / unverified / user (docs/HUB.md). Food values are owned by the Sheet: the app does not overwrite them unless the owner enables write-back. This source is only used on the owner's/guest device connected to the Hub, not by Firebase accounts.

4. USDA FoodData Central reference database (usda.json)

Built by node scripts/build-food-db.mjs <usda-dir> from the official CSV downloads. Values are copied exactly as published (per 100 g edible portion); nothing is estimated or "fixed"; foods without a published energy value or without protein/fat/carbs are skipped. The file's meta block (as shipped):

meta fieldValue
format / versionmego-fooddb / 1
builtAt2026-11-06
sourcesS = USDA FoodData Central — SR Legacy (release 2018-04); N = USDA FoodData Central — FNDDS (Survey foods) (release 2024-10-31); license: Public domain (U.S. Government work)
basisper 100 g edible portion
statssr 7,448 · fndds 5,431 · skippedNoEnergyOrMacros 1 · energyFlagged 211
rows12,879
categories195 (24 SR Legacy food groups + 171 FNDDS WWEIA categories)

SR Legacy groups "Quality Control Materials" and "Baby Foods" are excluded. Row format (type RefRow):

[id, name, categoryIndex, kcal, protein, carbs, fat, fiber|null, sugar|null,
 satFat|null, sodiumMg|null, portions[[label, grams]...], energyFlag 0|1]

Example:
["S171477","Chicken, broilers or fryers, breast, meat only, cooked, roasted",10,
 165,31.02,0,3.57,0,0,1.01,74,
 [["1 cup, chopped or diced",140],["1 unit (yield from 1 lb ready-to-cook chicken)",52],
  ["0.5 breast, bone and skin removed",86]],0]
  • id: "S" + FDC id (SR Legacy) or "N" + FDC id (FNDDS).
  • Energy: nutrient 1008 (kcal), falling back to Atwater energy 2048 then 2047. Sugar: 2000, fallback 1063.
  • Portions: up to 6 distinct USDA household measures (label ≤ 60 characters, grams rounded to 0.01).
  • energyFlag = 1 when kcal > 40 and |4P + 4C + 9F − kcal| / kcal > 25%. Flagged values are not changed.
  • Coverage of optional nutrients in the shipped file: fiber 12,347 rows, sugar 11,125, satFat 12,560, sodium 12,796; 12,582 rows have at least one portion.

The app loads the file once (loadRefFoods), checks meta.format === 'mego-fooddb', and the service worker caches it for offline use.

5. Extra nutrients file (usda-extra.json)

Format mego-fooddb-extra, version 1, basis per 100 g, one array per reference id (12,879 entries). Used by Food Intelligence rankings, loaded on demand. Columns:

mufa g, pufa g, ALA 18:3 n-3 g (or total 18:3 when n-3 not reported), EPA g, DHA g, DPA g,
calcium mg, iron mg, magnesium mg, potassium mg, zinc mg, vitamin A µg RAE, vitamin E mg,
vitamin C mg, vitamin B12 µg, folate µg DFE,
essential amino acids g/100 g food [His, Ile, Leu, Lys, Met, Cys, Phe, Tyr, Thr, Trp, Val]

Missing values are null. The amino-acid array is present only when all 11 values exist (4,789 foods).

6. Open Food Facts (barcode and text search)

  • Barcode lookup: https://world.openfoodfacts.org/api/v2/product/<code>.json; text search: /cgi/search.pl (page_size 20). No API key.
  • Manual barcodes are validated (EAN-8, UPC-A/EAN-13/14 check digit). The local foods table is searched first (findLocalByBarcode).
  • Mapping (toProduct): kcal = energy-kcal_100g, or energy_100g (kJ) / 4.184; protein, carbs, fat, fiber, sugars, saturated-fat per 100 g; sodium g × 1000 → mg; serving_quantity → serving grams.
  • A product is "complete" only when kcal, protein, carbs and fat are all published; text search drops incomplete products.
  • Values are community data and are labelled external; stored with source = 'openfoodfacts', barcode and brand.

7. Custom foods and AI estimates

Custom foods are entered in the food editor (source = 'custom'). Users can export their non-sheet foods as JSON (format mego-custom-foods, version 1) and import them back; invalid rows are rejected and duplicates (same name + state) are skipped.

AI estimates: the Gemini meal scanner matches photographed items to the user's own database first; database values are always primary. For items not in the database it may give an estimated per-100 g basis (estPer100), always labelled as an estimate. The scanner never auto-saves. If the user chooses to add such an item as a new food, it is created with category «تقدير من صورة» and the note «⚠ تقدير ذكاء اصطناعي من صورة — غير محقق، يُرجى المراجعة / AI photo estimate — unverified, please review».

8. Materializing a reference food into user foods

Reference foods are read-only. When the user logs one, materializeRefFood copies it once into the foods table so diary snapshots, recipes, sync and reports work unchanged:

  1. Look for an existing non-archived food with source = 'usda' and the same sourceRef; if found, reuse it.
  2. Otherwise create a food: nameAr '' , nameEn = USDA name, category = USDA category, per100 copied unchanged (optional nutrients only when not null), state inferred from the name, stateLabel نيء / مطبوخ / محضّر, servings = USDA portions (ids p0, p1, …), notes = sourceRef plus "⚠ calories vs macros differ in the source data" when energyFlag = 1.
