Purpose and scope

This document explains what MEGO does when a food is missing (not found, incomplete, or a recipe ingredient without verified values) and how it prevents, detects and resolves duplicates (foods and diary entries). Core principle: a missing value is shown as missing and is never invented; a possible duplicate is reported, never deleted automatically. Sources: src/lib/repo.ts, src/lib/recipeEngine.ts, src/lib/recipeRefMap.ts, src/lib/libraryFoods.ts, src/lib/foodNames.ts, src/lib/refFoods.ts, src/lib/foodIntel.ts, src/lib/sheetImport.ts, src/lib/customFoods.ts, src/lib/barcode.ts, src/lib/dataCheck.ts, src/components/FoodPicker.tsx, src/pages/RecipeLibrary.tsx.

1. Principles

  • No estimated or "typical" values are ever filled in for a missing food, nutrient or ingredient.
  • Adding foods never changes existing foods; imports and completion features add only.
  • Duplicates are blocked at entry where the match is certain (same name and same raw/cooked state) and only reported where it is not.

2. A food is not found when searching

The food picker searches in this order and offers the next step when nothing fits:

 My foods (incl. Hub foods)  →  USDA reference DB (12,879, Arabic/English search)
        │ not found / not right
        ▼
 [+ Create "…" as my food]   — food editor pre-filled with the search text as name;
                               values typed per 100 g, per 100 ml or per serving (converted to per 100 g)
 [Search Open Food Facts]    — packaged products; only products with kcal, protein, carbs and fat are listed
 [Barcode]                   — local food with that barcode first, else Open Food Facts; if not found,
                               an empty product form opens for the label values

A USDA food picked from search is copied once into "My foods"; the next pick reuses that copy.

3. Incomplete foods

A food with all four main values 0, or imported with an empty/unreadable required value, is marked incomplete. It stays in the list (counted in Foods → Issues) but cannot be logged (INCOMPLETE_FOOD) and is not used in recipes. The user completes it by editing the food with the label values.

4. Missing recipe ingredients

For each ingredient of a library recipe, computeLibraryRecipe resolves the nutrition in this order:

OrderSourceLabel in the recipe
1The user's own food with the same Arabic name (exact or normalised), not incompleteMy food
2Hand-checked USDA match in recipeRefMap.ts (68 entries)USDA
3Nothing reliable (map value null, or reference DB not loaded offline)Missing

A missing ingredient contributes nothing to the totals. The recipe shows "Incomplete: {list} is not in your foods and has no reliable reference — not included in the totals." with an Add this food button that opens the food editor with the ingredient name. While an ingredient is missing, the recipe cannot be added to the diary or plan or saved to My recipes (saving throws MISSING_INGREDIENT).

Example — labneh (لبنة): mapped to null ("no USDA equivalent; must be added/approved by the user"). Recipe lib-labneh-plate is therefore the only one of the 101 library recipes that is unresolved on a new account (docs/RECIPE-AUDIT.md, 2026-11-10). Once the user adds labneh from its label, the recipe resolves with the user's own values.

5. Completing the database from the recipe library

Foods → Complete my food database previews and then adds (after a local backup) every library ingredient missing from the user's foods (USDA values) and every library meal whose ingredients are all known as a ready food with a one-serving portion. On a new account (computed 10 Nov 2026): 68 ingredients to add, 1 missing (labneh), 100 ready meals, 1 skipped (lib-labneh-plate). The message "No verified values for: {names}. Add it yourself in Foods (from the label) to complete: {r}." lists what the user must add. Existing foods (same Arabic name, or for meals the same sourceRef) are not added again. The owner's Hub has the equivalent command node scripts/laptop-setup.mjs --hub-complete-foods. Details: MEGO_Food_Database_Import_and_Update_Procedures §7.

6. Missing names and missing reference data

  • Names: Foods → Arabic & English names fills only empty Arabic or English names from public/fooddb/food-names.json; foods for which no translation exists are listed as "Still missing a name — add these yourself from the food editor". On the Hub, the backend action fillFoodNames fills only empty name_en cells.
  • USDA build: foods without a published energy value or without protein, carbs or fat are skipped (1 in the current build), not estimated.
  • Optional nutrients: a nutrient not reported stays unknown (not 0) in totals; the coach says how many entries lack fibre instead of guessing.
  • Food rankings: catalog ids missing from USDA are skipped; foods with an unmeasured indicator are ranked after all fully measured foods ("partial data" group); only animal foods without a fibre value count as 0 g fibre (animal tissue has none).

7. Preventing duplicate foods

findDuplicateFood treats two non-archived foods as duplicates when they have the same state (raw/cooked/other) and the same Arabic name or the same English name after trimming, collapsing spaces and lower-casing. Creating or renaming a food to such a name is refused with "A food with the same name and raw/cooked state already exists." "Chicken breast" raw and "Chicken breast" cooked are not duplicates.

PathDuplicate protection
Food editor (create / rename)refused by findDuplicateFood
Hub / CSV / Excel importmatched by sheet key (Hub food_id or name), legacy name re-keyed to the stable ID, name-keyed rows matched to Hub foods by name + state; duplicate names inside a file flagged and keyed name#2
Personal foods JSON importsame name + state already present → skipped
USDA pickreuses the existing copy with the same sourceRef
Recipe match approval / Complete my food databaseonly names not already in the user's foods are added; meals checked by sourceRef or Arabic name
Barcodea local food with the same barcode is used instead of a new one
Filling namesa name that would duplicate another food is not written

8. Preventing duplicate diary entries

Adding the same food with the same date, meal, quantity, unit and serving within 1.5 seconds is refused (DUPLICATE_ENTRY), which protects against double taps. Intentional repeats later are allowed.

9. Duplicates report in Data check

Settings → Data check → Run check also reports "Possible duplicates: {e} diary items and {f} foods appear more than once (for example entered again after a data loss)." It was added after the 10 Nov 2026 data-loss incident, when some days could have been re-entered by hand before the cloud copy came back.

ReportGrouping keyExcluded
Diary itemsdate | meal | name (trimmed, lower-case) | grams rounded to whole g; listed when copies > 1 (newest dates first, first 30 shown)deleted entries
FoodsArabic name (or English if none), trimmed, lower-case; listed when copies > 1archived foods and foods from the Hub (sheet) or USDA (usda)

Example: 2026-11-08, Breakfast, "Oats" 40 g logged twice and "oats " 40.2 g once → one group "Oats · 40 g × 3". The note reads: "Nothing was removed. Check these days in the diary and delete the extra copy yourself if it is a duplicate."

Note: the food report groups by name only (not by state), so a raw and a cooked food with the same name appear as a possible duplicate although the editor allows them. Review such cases before acting.

10. Resolving duplicates

  1. Diary items: open the listed day in the Diary, compare the entries and delete the extra one. Deletions sync to the account.
  2. Foods: decide which record to keep; archive the other (archived foods leave lists, duplicate checks and exports; past diary entries keep their snapshot values; archiving is reversible with Restore). Renaming one of them is also possible.
  3. Hub foods: compare via the Hub check (only in Hub / only on phone / different values) and correct in the Food_Database tab, then import again.
  4. Run Data check again to confirm.
