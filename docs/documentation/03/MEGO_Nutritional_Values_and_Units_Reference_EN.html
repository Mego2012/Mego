1. The Macros structure

interface Macros {
  kcal: number;      // energy, kilocalories
  protein: number;   // g
  carbs: number;     // g
  fat: number;       // g
  fiber?: number;    // g    (optional)
  sugar?: number;    // g    (optional)
  sodium?: number;   // mg   (optional)

2. Basis: per 100 g

Food.per100 holds values per 100 g of the food in its stated state (raw, cooked or other). For liquids, per 100 g is still the basis; millilitres are converted to grams with gramsPerMl (density). When a food has no density, 1 ml = 1 g is assumed and this is shown to the user. USDA data is "per 100 g edible portion"; Open Food Facts values come from the *_100g fields; Hub columns are kcal_100g, protein_100g etc.

Recipes are the exception: a recipe entry's basis is perServing (values per recipe serving) and it can only be logged in the unit serving.

3. Optional nutrients and "unknown"

  • An optional nutrient that is undefined means unknown — it is never treated as zero.
  • Scaling (scaleMacros) and rounding keep a field only when the source had it.
  • Adding (addMacros): if either side has the nutrient, the sum contains it, counting the missing side as 0. Reports therefore also keep coverage: the number of entries in a day that actually had each optional nutrient, so a partial sum can be recognised.
  • Required fields kcal/protein/carbs/fat are always numbers. A food whose four required values are all 0 is incomplete.

USDA values are rounded to 2 decimals by the build script. In usda.json a missing optional value is null and is dropped when converted (toRefFood). Hub numbers accept Arabic-Indic digits and a decimal comma such as "2,6" (read as 2.6 and reported); "1,234" is read as 1234.

5. Extra nutrients (rankings only)

public/fooddb/usda-extra.json holds, per 100 g: MUFA g, PUFA g, ALA g, EPA g, DHA g, DPA g, calcium mg, iron mg, magnesium mg, potassium mg, zinc mg, vitamin A µg RAE, vitamin E mg, vitamin C mg, vitamin B12 µg, folate µg DFE, and 11 essential amino acids (g/100 g food: His, Ile, Leu, Lys, Met, Cys, Phe, Tyr, Thr, Trp, Val). These are used only by Food Intelligence rankings; they are not stored on user foods or diary entries.

Rounding uses Math.round((n + Number.EPSILON) × 10^d) / 10^d. Logged grams are rounded to 0.1 g.

8. Value validation limits

validateMacros (per-100 g values) returns these error codes:

  • <field>:nan — required field missing or not finite (optional fields may be undefined).
  • <field>:negative — any value below 0.
  • macros:over100g — protein + carbs + fat > 100.5 g.
  • fiber:overCarbs — fiber > carbs + 0.5 (when carbs > 0).
  • sugar:overCarbs — sugar > carbs + 0.5.
  • kcal:over900 — kcal > 900.5 per 100 g.

Foods failing validation cannot be created (createFood) or imported from a custom-foods file.
