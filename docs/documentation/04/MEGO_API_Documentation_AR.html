الغرض والنطاق

هذه هي المرجعية لواجهة HTTP الخاصة بخادم MEGO: تطبيق الويب المبني على Google Apps Script في apps-script/Code.gs ‏(SCRIPT_VERSION = 8). وتسرد كل إجراء (action) في doPost مع حقول الطلب والرد كما هي منفّذة بالضبط. واجهة بيانات Firestore التي تستخدمها الحسابات المسجلة ليست واجهة HTTP خاصة بـ MEGO، وهي موثقة في MEGO_Firebase_Integration. لا يظهر في هذه الوثيقة أي رابط نشر حقيقي أو رمز سري أو مفتاح أو رمز اتصال؛ وتُستخدم بدلًا منها عناصر نائبة مثل <WEB_APP_URL> و<APP_TOKEN>.

1. النقل وغلاف الرسائل

  • الطريقة: POST <WEB_APP_URL> (النشر: التنفيذ بصلاحية المالك والوصول «لأي أحد»؛ انظر appsscript.json: executeAs: USER_DEPLOYING وaccess: ANYONE_ANONYMOUS).
  • الترويسات: Content-Type: text/plain;charset=utf-8 — طلب «بسيط» فلا يرسل المتصفح طلب CORS تمهيديًا. ويتبع العميل إعادة التوجيه (redirect: 'follow').
  • الجسم: كائن JSON فيه action وحقول الإجراء. تضيف طلبات المالك token، وتضيف الطلبات العامة idToken.
  • الرد: JSON. النجاح: { "ok": true, … }. الإخفاق: { "ok": false, "error": "<code or message>", … }. وأي استثناء غير ملتقط يعود بالشكل { ok: false, error: <exception message> }.
  • غلاف العميل (callScript في src/lib/sync.ts): رمز HTTP غير ناجح ← الخطأ "HTTP <status>"؛ وok: false ← خطأ بنص error مع إرفاق JSON كاملًا في data.
POST <WEB_APP_URL>
Content-Type: text/plain;charset=utf-8

{"action":"ping","token":"<APP_TOKEN>"}

2. المصادقة وترتيب التوجيه

تفحص doPost الطلب بهذا الترتيب بالضبط:

  1. action == "bootstrap" ← bootstrap_ (سرّ لمرة واحدة، القسم 7).
  2. وجود idToken والإجراء أحد analyzeMeal أو aiStats أو aiDiag ← المسار العام (القسم 6).
  3. وإلا يجب أن يكون token نصًا مساويًا لخاصية السكربت APP_TOKEN؛ وإلا يعود { ok: false, error: "unauthorized" }.
  4. خارج قفل السكربت: analyzeMeal وaiDiag وsetAiKey وsetCloudConfig.
  5. داخل قفل السكربت (waitLock(25000)): ping وfoods وpush وpull وsaveFoods وfillFoodNames وbackup وmeta؛ وأي قيمة أخرى ← { ok: false, error: "unknown action" }.

4. إجراءات المالك (رمز التطبيق)

4.1 ping

الطلب: { action: "ping", token }

الرد: ok، وspreadsheet (اسم ملف الـ Hub)، وspreadsheetId (معرّف الـ Hub الحالي)، وsourceId (معرّف ملف Excel الأصلي)، وverified (نتيجة التحقق المخزنة أو null)، وmode ("native" | "xlsx")، وwritable (الوضع أصلي)، وscriptVersion، وaiScanner (يوجد مفتاح Gemini مخزّن)، وaiModel، وfoodSheet ("Food_Database" أو اسم تبويب الأطعمة الأصلي)، وmeta (محتوى Sync_Metadata في الوضع الأصلي، وإلا {}).

4.2 foods

الطلب: { action: "foods", token }

الرد (وضع أصلي وفي Food_Database صفوف): { ok, sheet: "Food_Database", structured: true, rows } — تشمل الصفوف صف العناوين، مقتطعة إلى الأعمدة المقروءة العشرين.
وضع أصلي دون Food_Database: { ok, sheet: <original tab>, structured: false, rows }.
وضع xlsx: { ok, sheet, structured: false, readOnly: true, rows } (تُقرأ عبر نسخة محوّلة مؤقتة تُنقل إلى سلة المهملات بعد ذلك).
خطأ: "food sheet not found".

4.3 push

الطلب: { action: "push", token, changes: Change[], clientSchema }

حقل التغييرالقاعدة
tableأحد: foods، entries، body، days، recipes، templates، plans، plannedDays، fasts، kv، settings، foodChanges
keyنص غير فارغ، 200 حرف كحد أقصى
op"upsert" أو "delete"
payloadفي upsert فقط: كائن (ليس مصفوفة)، وطول JSON ≤ 45,000 حرف؛ في entries يلزم date بصيغة YYYY-MM-DD وmacros.kcal رقمي؛ وفي body يجب أن يكون weight، إن وُجد، رقمًا بين 20 و400
atطابع زمني (مللي ثانية)؛ يُستخدم إذا خلت الحمولة من updatedAt/at

الرد: { ok: true, applied, conflicts: [{ table, key }], dataVersion }.
الأخطاء: "invalid changes" (ليست مصفوفة)، و"too many changes in one request" (أكثر من 500)، و"<n> invalid change(s) rejected"، و"HUB_IS_XLSX: …" (الـ Hub لم يُحوَّل).

4.4 pull

الطلب: { action: "pull", token, since? } — يعيد since (بالمللي ثانية) الصفوف التي updated_at فيها أكبر منه فقط (والتطبيق لا يرسله).

الرد: { ok: true, tables: { <table>: [record, …] }, meta }، والسجلات محلَّلة من عمود json. وفي وضع xlsx: { ok: true, tables: {}, meta: {}, readOnly: true }.

4.5 saveFoods

الطلب: { action: "saveFoods", token, foods: [ … ] } بحد أقصى 200. كل عنصر كما تنتجه foodToSheetRow(): foodId, updatedAt, sheetKey, sheetRow, name, category, kcal, protein, carbs, fat, piece, state, prep, notes, archived (ويُستخدم record الاختياري كحمولة إن وُجد). يجب أن يكون name نصًا غير فارغ، وقيم kcal/protein/carbs/fat أرقامًا من 0 إلى 1000.

الرد: { ok: true, updated, conflicts }. الأخطاء: "invalid foods"، و"food without name"، و"invalid value for <name>". أثر جانبي: نسخة Drive احتياطية واحدة من الـ Hub يوميًا قبل أول كتابة عكسية.

4.5أ fillFoodNames (منذ SCRIPT_VERSION 8)

الطلب: { action: "fillFoodNames", token, names }، حيث names كائن يربط الاسم العربي بالاسم الإنجليزي ({ "<ar>": "<en>" }).

لا تتغير إلا صفوف Food_Database التي فيها name_ar غير فارغ وname_en فارغ، ولاسمها العربي في الخريطة نص إنجليزي غير فارغ طوله 120 حرفًا كحد أقصى؛ ولا تُكتب إلا خلية name_en. تبقى كل الخلايا الأخرى وكل الأسماء غير الفارغة كما هي تمامًا. وإذا كانت ستُكتب خلية واحدة على الأقل تُؤخذ أولًا النسخة الاحتياطية اليومية للـ Hub في Drive (مشتركة مع saveFoods، مرة واحدة يوميًا).

الرد: { ok: true, filled } (عدد الخلايا المكتوبة). الأخطاء: "invalid names" (ليس كائنًا أو كان مصفوفة)، و"Food_Database needs the native Google Sheet" (وضع xlsx)، و"Food_Database not found"، و"name columns not found".

4.6 backup

الطلب: { action: "backup", token, snapshot }، ويجب أن يكون snapshot.format مساويًا لـ "mego-nutrition-backup".

الرد: { ok: true, file, url } — اسم الملف mego-backup-YYYY-MM-DD_HHmmss.json في مجلد Drive ‏«MEGO Nutrition Backups»، وurl رابط ذلك الملف في Drive. خطأ: "invalid backup".

4.7 meta

الطلب: { action: "meta", token }. الرد: { ok: true, meta } — أزواج مفتاح/قيمة من Sync_Metadata (مثل schemaVersion وhubName وmigratedAt وdataVersion وlastWriteAt وappSchemaVersion وlastSyncAt وlastConflicts).

4.8 setAiKey

الطلب: { action: "setAiKey", token, key } أو { action: "setAiKey", token, remove: true }.

يجب أن يطابق المفتاح ^[A-Za-z0-9_.\-]{20,200}$ (صيغ مفاتيح Google القديمة والأحدث)، ثم يُفحص بطلب بيانات وصفية للنموذج لدى Google قبل حفظه باسم GEMINI_API_KEY.

الرد: { ok: true, aiScanner: true, aiModel }؛ وعند الإزالة { ok: true, aiScanner: false }. الأخطاء: AI_KEY_INVALID أو AI_NETWORK أو خطأ Google مُحوَّل (القسم 9).

4.9 setCloudConfig

الطلب: { action: "setCloudConfig", token, apiKey, projectId, userLimit?, globalLimit? }. يجب أن يطابق apiKey النمط ^[A-Za-z0-9_\-]{20,100}$ وprojectId النمط ^[a-z0-9\-]{4,40}$. يحفظ FIREBASE_API_KEY وFIREBASE_PROJECT_ID؛ ويُحصر userLimit بين 1 و50 ← AI_USER_DAILY_LIMIT؛ وglobalLimit بين 1 و1500 ← AI_DAILY_LIMIT.

الرد: { ok: true }. خطأ: "invalid config".

5. إجراءات الذكاء الاصطناعي

5.1 analyzeMeal

الطلب: { action: "analyzeMeal", token | idToken, image, mediaType, foods, lang, note }

الحقلالقاعدة
imagebase64 (الأحرف A–Z a–z 0–9 + / =)، بحد أقصى 2,800,000 حرف
mediaTypeimage/png أو image/webp؛ وأي قيمة أخرى تُعامل كـ image/jpeg (والتطبيق يرسل JPEG)
foodsمصفوفة، يُستخدم أول 800 عنصر؛ كل عنصر { k, ar, en, s, c } = المفتاح، الاسم العربي، الاسم الإنجليزي، الحالة، الفئة (كل منها مقتطع إلى 120 حرفًا)
lang"en" ← الإنجليزية، وإلا العربية
noteاختياري، سطر واحد، 300 حرف كحد أقصى

الرد: { ok: true, model, result, tried }. يتبع result مخطط JSON ‏AI_SCHEMA: is_food، meal_name_ar، meal_name_en، notes، وitems[] بالحقول name_ar, name_en, food_key, grams, grams_low, grams_high, state (raw/cooked/other)، وcooking_method، وkind (food/oil_or_fat/sauce_or_dressing/drink)، وconfidence (0–1)، وreason، وest_per100 { kcal, protein, carbs, fat }. وتسرد tried محاولات النماذج الفاشلة (مثل "model:503").

الأخطاء: AI_NOT_CONFIGURED، AI_BAD_IMAGE، AI_DAILY_LIMIT (السقف العام AI_DAILY_LIMIT، الافتراضي 40)، AI_REFUSED، AI_BAD_OUTPUT، AI_TRUNCATED، وأخطاء Google المحوَّلة (القسم 9) مع google: { http, status, message } وtried. لا يزداد العداد اليومي العام إلا عند النجاح. سلسلة النماذج وإعادة المحاولة: MEGO_Gemini_AI_Integration.

5.2 aiDiag

الطلب: { action: "aiDiag", token | idToken }. يرسل «Reply with the single word OK.» إلى كل نموذج مجاني (دون صورة).

الرد: { ok: true, scriptVersion, configuredModel, models: [{ model, http, error, google, ms }] }. خطأ: AI_NOT_CONFIGURED.

6. إجراءات الحسابات العامة (رمز هوية Firebase)

تستخدمها الحسابات المسجلة (الرابط من aiBackendUrl في firebase-config.json). الخطوات المشتركة: يُتحقق من رمز الهوية عبر Google Identity Toolkit ‏(accounts:lookup) باستخدام FIREBASE_API_KEY المخزّن؛ وتُقرأ مستندات Firestore برمز المستخدم نفسه فتنطبق قواعد الأمان.

الإجراءفحوص إضافيةالرد
analyzeMealيجب وجود ملف شخصي بحالة "active" (وإلا unauthorized)؛ الدولة ضمن القائمة المقيّدة ← AI_REGION_RESTRICTED؛ عدّاد يومي لكل مستخدم AI_U_<date>_<uid> تحت قفل، بحد AI_USER_DAILY_LIMIT (الافتراضي 10) ← { ok: false, error: "AI_USER_LIMIT", limit }؛ والتحليل الفاشل يُستردّ من العدّادكما في 5.1
aiStatsيجب أن يكون admins/{uid} مقروءًا برمز المستخدم (وإلا unauthorized){ ok, model, configured, globalLimit, userLimit, days: [{ date, scans, users }] } لآخر 7 أيام — أعداد فقط
aiDiagيجب أن يكون الملف الشخصي مقروءًاكما في 5.2

أخطاء خاصة بهذا المسار: CLOUD_NOT_CONFIGURED (لا يوجد FIREBASE_API_KEY مخزّن)، وunauthorized (رمز غير صالح أو معطّل، أو ملف شخصي مفقود أو غير نشط).

7. إجراء الإعداد (bootstrap)

الطلب: { action: "bootstrap", secret }. يعمل فقط إذا احتوت النسخة الخاصة من السكربت على BOOTSTRAP_HASH غير فارغ (وهو فارغ في المستودع العام) ولم تُضبط BOOTSTRAP_DONE. يجب أن يساوي SHA-256 للقيمة secret تلك البصمة. يشغّل installMego() مرة واحدة ثم يضبط BOOTSTRAP_DONE.

الرد: { ok: true, token, nativeId, sourceId, verified, log } — token هو رمز التطبيق السري ويجب التعامل معه كسرّ. الأخطاء: unauthorized أو رسالة استثناء installMego (مثل VERIFY_FAILED: …).

8. نقطة GET والدوال الخاصة بالمحرر

GET <WEB_APP_URL> ← { ok: true, app: "mego-nutrition", version: 8 } (دون مصادقة ودون بيانات).

دوال تُشغَّل من محرر Apps Script أو بالمشغّلات الزمنية (غير متاحة عبر HTTP): setup()، rotateToken()، installMego()، migrateHub()، convertHubToGoogleSheets()، authorize()، cleanupAiCounters() (تحذف عدادات الذكاء الاصطناعي الأقدم من 8 أيام؛ مشغّل زمني اختياري).
