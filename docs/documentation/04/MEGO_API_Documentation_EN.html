Purpose and scope

This is the reference for the HTTP interface of the MEGO backend: the Google Apps Script web app in apps-script/Code.gs (SCRIPT_VERSION = 8). It lists every doPost action with its request and response fields exactly as implemented. The Firestore data interface used by signed-in accounts is not an HTTP API of MEGO; it is documented in MEGO_Firebase_Integration. No real deployment URL, token, key or connection code appears in this document; placeholders such as <WEB_APP_URL> and <APP_TOKEN> are used instead.

1. Transport and envelope

  • Method: POST <WEB_APP_URL> (deployment: execute as the owner, access "anyone"; see appsscript.json executeAs: USER_DEPLOYING, access: ANYONE_ANONYMOUS).
  • Headers: Content-Type: text/plain;charset=utf-8 — a "simple" request, so the browser sends no CORS preflight. The client follows redirects (redirect: 'follow').
  • Body: a JSON object with action plus action fields. Owner calls add token; public calls add idToken.
  • Response: JSON. Success: { "ok": true, … }. Failure: { "ok": false, "error": "<code or message>", … }. Any uncaught exception is returned as { ok: false, error: <exception message> }.
  • Client wrapper (callScript in src/lib/sync.ts): non-2xx HTTP → error "HTTP <status>"; ok: false → error with the error text and the full JSON attached as data.
POST <WEB_APP_URL>
Content-Type: text/plain;charset=utf-8

{"action":"ping","token":"<APP_TOKEN>"}

2. Authentication and dispatch order

doPost evaluates the request in this exact order:

  1. action == "bootstrap" → bootstrap_ (one-time secret, section 7).
  2. idToken present and action is analyzeMeal, aiStats or aiDiag → public path (section 6).
  3. Otherwise the token must be a string equal to the APP_TOKEN Script Property; else { ok: false, error: "unauthorized" }.
  4. Outside the script lock: analyzeMeal, aiDiag, setAiKey, setCloudConfig.
  5. Inside the script lock (LockService.getScriptLock().waitLock(25000)): ping, foods, push, pull, saveFoods, fillFoodNames, backup, meta; any other value → { ok: false, error: "unknown action" }.

4. Owner actions (app token)

4.1 ping

Request: { action: "ping", token }

Response: ok, spreadsheet (Hub file name), spreadsheetId (current Hub ID), sourceId (original Excel ID), verified (stored verification result or null), mode ("native" | "xlsx"), writable (mode is native), scriptVersion, aiScanner (a Gemini key is stored), aiModel, foodSheet ("Food_Database" or the original food tab name), meta (Sync_Metadata in native mode, else {}).

4.2 foods

Request: { action: "foods", token }

Response (native, Food_Database has rows): { ok, sheet: "Food_Database", structured: true, rows } — rows include the header row, cut to the 20 readable columns.
Native without Food_Database: { ok, sheet: <original tab>, structured: false, rows }.
xlsx mode: { ok, sheet, structured: false, readOnly: true, rows } (read via a temporary converted copy that is trashed afterwards).
Error: "food sheet not found".

4.3 push

Request: { action: "push", token, changes: Change[], clientSchema }

Change fieldRule
tableone of foods, entries, body, days, recipes, templates, plans, plannedDays, fasts, kv, settings, foodChanges
keynon-empty string, at most 200 characters
op"upsert" or "delete"
payloadupsert only: a non-array object, JSON ≤ 45,000 characters; entries need date = YYYY-MM-DD and numeric macros.kcal; body weight, if set, a number 20–400
attimestamp (ms); used when the payload has no updatedAt/at

Response: { ok: true, applied, conflicts: [{ table, key }], dataVersion }.
Errors: "invalid changes" (not an array), "too many changes in one request" (> 500), "<n> invalid change(s) rejected", "HUB_IS_XLSX: …" (Hub not converted).

4.4 pull

Request: { action: "pull", token, since? } — since (ms) returns only rows with updated_at greater than it (the app does not send it).

Response: { ok: true, tables: { <table>: [record, …] }, meta }, records parsed from the json column. In xlsx mode: { ok: true, tables: {}, meta: {}, readOnly: true }.

4.5 saveFoods

Request: { action: "saveFoods", token, foods: [ … ] }, at most 200. Each item as produced by foodToSheetRow(): foodId, updatedAt, sheetKey, sheetRow, name, category, kcal, protein, carbs, fat, piece, state, prep, notes, archived (optional record is used as the payload if present). name must be a non-empty string; kcal/protein/carbs/fat numbers 0–1000.

Response: { ok: true, updated, conflicts }. Errors: "invalid foods", "food without name", "invalid value for <name>". Side effect: one Drive backup of the Hub per day before the first write-back.

4.5a fillFoodNames (since SCRIPT_VERSION 8)

Request: { action: "fillFoodNames", token, names }, where names is an object mapping Arabic name → English name ({ "<ar>": "<en>" }).

Only rows of Food_Database whose name_ar is non-empty, whose name_en is empty, and whose Arabic name has a non-empty English string of at most 120 characters in the map are changed; only the name_en cell is written. Every other cell and every non-empty name stays exactly as it is. If at least one cell will be written, the daily Drive backup of the Hub (shared with saveFoods, once per day) is made first.

Response: { ok: true, filled } (number of cells written). Errors: "invalid names" (not an object, or an array), "Food_Database needs the native Google Sheet" (xlsx mode), "Food_Database not found", "name columns not found".

4.6 backup

Request: { action: "backup", token, snapshot }, where snapshot.format must be "mego-nutrition-backup".

Response: { ok: true, file, url } — file name mego-backup-YYYY-MM-DD_HHmmss.json in the Drive folder "MEGO Nutrition Backups", url = that Drive file's link. Error: "invalid backup".

4.7 meta

Request: { action: "meta", token }. Response: { ok: true, meta } — key/value pairs of Sync_Metadata (e.g. schemaVersion, hubName, migratedAt, dataVersion, lastWriteAt, appSchemaVersion, lastSyncAt, lastConflicts).

4.8 setAiKey

Request: { action: "setAiKey", token, key } or { action: "setAiKey", token, remove: true }.

The key must match ^[A-Za-z0-9_.\-]{20,200}$ (classic and newer Google key formats); it is then checked with a Google model-metadata request before being stored as GEMINI_API_KEY.

Response: { ok: true, aiScanner: true, aiModel }; remove → { ok: true, aiScanner: false }. Errors: AI_KEY_INVALID, AI_NETWORK, or a mapped Google error (section 9).

4.9 setCloudConfig

Request: { action: "setCloudConfig", token, apiKey, projectId, userLimit?, globalLimit? }. apiKey must match ^[A-Za-z0-9_\-]{20,100}$, projectId ^[a-z0-9\-]{4,40}$. Stores FIREBASE_API_KEY, FIREBASE_PROJECT_ID; userLimit clamped to 1–50 → AI_USER_DAILY_LIMIT; globalLimit clamped to 1–1500 → AI_DAILY_LIMIT.

Response: { ok: true }. Error: "invalid config".

5. AI actions

5.1 analyzeMeal

Request: { action: "analyzeMeal", token | idToken, image, mediaType, foods, lang, note }

FieldRule
imagebase64 (characters A–Z a–z 0–9 + / =), at most 2,800,000 characters
mediaTypeimage/png or image/webp; anything else is treated as image/jpeg (the app sends JPEG)
foodsarray, first 800 used; each { k, ar, en, s, c } = key, Arabic name, English name, state, category (each cut to 120 chars)
lang"en" → English, otherwise Arabic
noteoptional, single line, max 300 characters

Response: { ok: true, model, result, tried }. result follows the JSON schema AI_SCHEMA: is_food, meal_name_ar, meal_name_en, notes, items[] with name_ar, name_en, food_key, grams, grams_low, grams_high, state (raw/cooked/other), cooking_method, kind (food/oil_or_fat/sauce_or_dressing/drink), confidence (0–1), reason, est_per100 { kcal, protein, carbs, fat }. tried lists failed model attempts (e.g. "model:503").

Errors: AI_NOT_CONFIGURED, AI_BAD_IMAGE, AI_DAILY_LIMIT (global cap AI_DAILY_LIMIT, default 40), AI_REFUSED, AI_BAD_OUTPUT, AI_TRUNCATED, and mapped Google errors (section 9) with google: { http, status, message } and tried. The global daily counter increases only on success. Model chain and retries: MEGO_Gemini_AI_Integration.

5.2 aiDiag

Request: { action: "aiDiag", token | idToken }. Sends "Reply with the single word OK." to every free model (no image).

Response: { ok: true, scriptVersion, configuredModel, models: [{ model, http, error, google, ms }] }. Error: AI_NOT_CONFIGURED.

6. Public-account actions (Firebase ID token)

Used by signed-in accounts (URL from aiBackendUrl in firebase-config.json). Common steps: the ID token is verified with Google Identity Toolkit (accounts:lookup) using the stored FIREBASE_API_KEY; Firestore documents are read with the user's own token, so the security rules apply.

ActionExtra checksResponse
analyzeMealprofile must exist with status "active" (else unauthorized); country in the restricted list → AI_REGION_RESTRICTED; per-user daily counter AI_U_<date>_<uid> under a lock, limit AI_USER_DAILY_LIMIT (default 10) → { ok: false, error: "AI_USER_LIMIT", limit }; a failed analysis is refundedas in 5.1
aiStatsadmins/{uid} must be readable with the user's token (else unauthorized){ ok, model, configured, globalLimit, userLimit, days: [{ date, scans, users }] } for the last 7 days — counts only
aiDiagown profile must be readableas in 5.2

Errors specific to this path: CLOUD_NOT_CONFIGURED (no FIREBASE_API_KEY stored), unauthorized (invalid/disabled token, missing or inactive profile).

7. Setup action (bootstrap)

Request: { action: "bootstrap", secret }. Enabled only when the private copy of the script contains a non-empty BOOTSTRAP_HASH (empty in the public repository) and BOOTSTRAP_DONE is not set. The SHA-256 of secret must equal the hash. Runs installMego() once, then sets BOOTSTRAP_DONE.

Response: { ok: true, token, nativeId, sourceId, verified, log } — token is the secret app token and must be handled as a secret. Errors: unauthorized, or the installMego exception message (e.g. VERIFY_FAILED: …).

8. GET endpoint and editor-only functions

GET <WEB_APP_URL> → { ok: true, app: "mego-nutrition", version: 8 } (no authentication, no data).

Functions run from the Apps Script editor or by triggers (not reachable over HTTP): setup(), rotateToken(), installMego(), migrateHub(), convertHubToGoogleSheets(), authorize(), cleanupAiCounters() (deletes AI counters older than 8 days; optional time trigger).
