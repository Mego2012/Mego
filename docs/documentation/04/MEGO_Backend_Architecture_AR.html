الغرض والنطاق

تصف هذه الوثيقة الجانب الخادمي في MEGO. لا يملك MEGO خادماً مخصّصاً؛ إذ تتكوّن الخلفية من: (أ) تطبيق ويب على Google Apps Script هو الملف apps-script/Code.gs (إصدار السكربت 5، وإصدار مخطط الـHub ‏3) يملكه ويشغّله مالك المشروع، و(ب) خدمتَي المصادقة (Firebase Authentication) وقاعدة البيانات السحابية (Cloud Firestore) كخلفية مُدارة تحدّد سلوكَها قواعدُ الأمان. تغطي الوثيقة موزّع الطلبات في Apps Script، والمصادقة، والتثبيت، ونموذج تبويبات الـHub، وقواعد الكتابة والتعارض والحذف، ووسيط Gemini (مسار المالك والمسار العام)، ودور Firebase. أما قوائم حقول الطلب والاستجابة لكل إجراء فموجودة في MEGO_API_Documentation.

1. نظرة عامة على الخلفية

                      +-------------------------------- Google (owner's account) -------------------------+
 PWA (owner device) --| POST {action, token}         +-----------------------------+                       |
                      |  ---------------------------->|  Apps Script web app        |--> Google Sheet Hub  |
 PWA (signed-in user)-| POST {action, idToken}       |  Code.gs  doPost()          |--> Drive (backups)   |
                      |  ---------------------------->|  Script Properties (secrets)|--> Gemini API (free) |
                      |                               +-------------+---------------+                       |
                      |                                             | Identity Toolkit (verify ID token)      |
                      |                                             | Firestore REST (with the user's token)  |
                      +---------------------------------------------v-----------------------------------------+
 PWA (signed-in user) --- Firebase JS SDK ---> Firebase Auth + Cloud Firestore (rules enforce access)

الوصول مفتوح «للجميع» لأن تطبيق الويب التقدّمي لا يستطيع إرسال ملفات تعريف الارتباط الخاصة بتسجيل الدخول إلى Google؛ لذا تتم مصادقة كل طلب داخل السكربت نفسه (القسم 4). السكربت مشروع مستقل. تعيد الدالة doGet() فقط {ok: true, app: "mego-nutrition", version: 5}. يرسل العميل طلبات POST بنوع المحتوى text/plain لتجنّب طلب الفحص المسبق (CORS preflight)، والاستجابات بصيغة JSON عبر ContentService.

3. موزّع الطلبات (doPost)

doPost(e)
  req = JSON.parse(body)
  action == "bootstrap"                      -> bootstrap_(req)            (one-time secret)
  req.idToken and action in {analyzeMeal, aiStats} -> publicAi_(req)      (Firebase user)
  req.token != APP_TOKEN                     -> {ok:false, error:"unauthorized"}
  action == "analyzeMeal"                    -> analyzeMeal_(req)          (no lock)
  action == "setAiKey"                       -> setAiKey_(req)
  action == "setCloudConfig"                 -> setCloudConfig_(req)
  ScriptLock.waitLock(25 s):
     ping | foods | push | pull | saveFoods | backup | meta
     anything else                           -> {ok:false, error:"unknown action"}
  any exception                              -> {ok:false, error: message}
الإجراءالمصادقةالغرض
bootstrapسرّ لمرة واحدة (يجب أن يساوي SHA-256 له القيمة BOOTSTRAP_HASH)يشغّل installMego() للإعداد الآلي من الحاسوب المحمول، ويعيد الرمز ومعرّفات الـHub، ثم يُعطَّل (BOOTSTRAP_DONE)
pingرمز التطبيقهوية الـHub (الاسم، المعرّف الأصلي، معرّف المصدر)، والوضع native/xlsx، وقابلية الكتابة، وإصدار السكربت، وحالة الذكاء الاصطناعي ونموذجه، وتبويب الأطعمة، والبيانات الوصفية
foodsرمز التطبيقصفوف Food_Database (منظّمة) أو تبويب الأطعمة الأصلي
pushرمز التطبيقتطبيق تغييرات التطبيق (إضافة/تحديث أو حذف) مع كشف التعارض

دوال تُشغَّل من المحرر فقط (لا يمكن الوصول إليها عبر HTTP): setup وrotateToken وinstallMego وmigrateHub وauthorize وconvertHubToGoogleSheets وcleanupAiCounters (مُشغِّل زمني اختياري).

4. المصادقة

  • رمز التطبيق (أجهزة المالك). تُنشئ setup() الخاصية APP_TOKEN من معرّفَي UUID دون شرطات (64 محرفاً ست عشرياً) في خصائص السكربت إن لم تكن موجودة، ويُقارَن بـreq.token في كل طلب. تحذفه rotateToken() وتعيد إنشاءه (ويجب عندها إعادة ربط كل الأجهزة). الرمز غير موجود في المستودع إطلاقاً.
  • رمز هوية Firebase (الحسابات العامة). لإجراءَي analyzeMeal وaiStats فقط. تستدعي verifyFirebaseUser_() نقطة accounts:lookup في Google Identity Toolkit باستخدام FIREBASE_API_KEY المحفوظ؛ وأي استجابة غير 200 أو مستخدم غير موجود أو معطَّل تعيد unauthorized. بعد ذلك يقرأ السكربت profiles/{uid} (وadmins/{uid} في حالة aiStats) عبر واجهة Firestore REST برمز المستخدم نفسه، فتُطبَّق قواعد Firestore تماماً كما في التطبيق.
  • سرّ الإقلاع (Bootstrap). قيمة BOOTSTRAP_HASH فارغة في المستودع العام (أي أن الإقلاع الآلي معطَّل). يكتب إعداد الحاسوب المحمول بصمة SHA-256 لسرّ عشوائي في النسخة الخاصة بالمالك فقط، ويعمل السرّ مرة واحدة.

5. التثبيت: setup وinstallMego وbootstrap

installMego()                                   (run from the editor, or via bootstrap)
 1. setup()                -> APP_TOKEN (kept if it already exists)
 2. ensureNativeHub_()     -> convert the Excel Hub (SOURCE_ID) once into a native Google Sheet in the same
                              folder (Drive.Files.create); stored as HUB_PENDING_ID; the .xlsx is not modified
 3. verifyNativeHub_(id)   -> original food tab present, food rows counted, numeric problems counted;
                              fails with VERIFY_FAILED -> the Hub is NOT switched
 4. HUB_NATIVE_ID = id     -> switch only after successful verification; HUB_VERIFIED stored
 5. migrateHub()           -> Drive backup copy, rename to "MEGO Nutrition Hub", create structured and
                              derived tabs, seed Food_Database with stable ids F0001..., Hub_Dashboard,
                              Migration_Report (re-runnable, nothing duplicated)
 6. print the connection code "MEGO1|<web app URL>|<token>" (only once the web app is deployed)

الأوضاع: native (الـHub جدول Google أصلي: مزامنة كاملة ثنائية الاتجاه) وxlsx (لم يُحوَّل بعد: للقراءة فقط؛ يقرأ foods من نسخة محوّلة مؤقتة تُنقل إلى سلة المهملات فوراً، ويعيد pull جداول فارغة مع readOnly: true، وتفشل الكتابة بالخطأ HUB_IS_XLSX). لا يفتح السكربت أي جدول بيانات غير الـHub.

7. قواعد الكتابة: التحقق، والتعارض، والحذف المرن

7.1 التحقق (validChange_)

  • 500 تغيير كحد أقصى لكل طلب؛ وأي تغيير غير صالح يؤدي إلى رفض الطلب كاملاً ("N invalid change(s) rejected").
  • يجب أن يكون الجدول ضمن القائمة المسموح بها، والمفتاح نصاً غير فارغ لا يتجاوز 200 حرف، والعملية upsert أو delete.
  • يجب أن تكون حمولة الإضافة/التحديث كائناً لا يتجاوز 45,000 حرف بصيغة JSON؛ ويحتاج قيد اليوميات تاريخاً بالصيغة YYYY-MM-DD وقيمة رقمية في macros.kcal؛ ويجب أن يكون وزن الجسم، إن وُجد، بين 20 و400.

7.2 قاعدة التعارض

في عملية الإضافة/التحديث يؤخذ الطابع الزمني الوارد من payload.updatedAt ثم payload.at ثم change.at. فإذا كانت قيمة updated_at المخزّنة أكبر، لا يُطبَّق التغيير ويُعاد {table, key} ضمن conflicts (فالنسخة الأقدم لا تستبدل الأحدث أبداً). أما عند تساوي الطابعين فيُطبَّق التغيير.

7.3 الحذف المرن (Soft Delete)

عند الحذف يُنسخ عمود json للصف إلى Deleted_Records (‏table, key, deleted_at, json, recovered="no") قبل حذف الصف. وحذف مفتاح غير موجود لا يفعل شيئاً.

7.4 الإصدارات والبيانات الوصفية

إذا طُبِّق تغيير واحد على الأقل، تُزاد قيمة dataVersion بواحد وتُكتب lastWriteAt (وappSchemaVersion إذا أرسلها العميل). وتُكتب lastSyncAt وlastConflicts مع كل عملية دفع. الاستجابة هي {ok, applied, conflicts, dataVersion}. وكل الإجراءات التي تلمس الـHub تعمل داخل قفل السكربت (انتظار حتى 25 ثانية).

7.5 الكتابة العكسية للأطعمة والنسخ الاحتياطية

يتحقق saveFoods من الأسماء ومن قيم المغذيات الأربع (0–1000)، وينشئ نسخة Drive من الـHub مرة واحدة يومياً على الأكثر (LAST_HUB_BACKUP)، ثم يعيد استخدام منطق الدفع. وتُنشئ migrateHub دائماً نسخة Drive أولاً. وتُسجَّل كل نسخة احتياطية في Backup_Log.

8. وسيط Gemini

8.1 مسار المالك (رمز التطبيق)

تعمل analyzeMeal_ خارج القفل، وتتطلب وجود GEMINI_API_KEY، وصورة بترميز base64 لا تتجاوز 2,800,000 حرف (JPEG أو PNG أو WebP)، وحتى 800 سطر من الأطعمة، وملاحظة لا تتجاوز 300 حرف. وتفرض الحد اليومي العام (AI_DAILY_LIMIT، الافتراضي 40؛ والعدّاد AI_USED_<date> يزداد بعد إرسال طلب Gemini)، ثم تستدعي models/<model>:generateContent مع مخطط استجابة JSON، ودرجة حرارة 0.2، و8,192 رمزاً كحد أقصى للمخرجات، وتعيد {ok, model, result}. النماذج المسموح بها: gemini-3.8-flash (الافتراضي) وgemini-3.6-flash وgemini-3.5-flash-lite (الخاصية AI_MODEL). لا يُخزَّن شيء.

8.2 المسار العام (رمز هوية Firebase)

publicAi_(req)
  verifyFirebaseUser_(idToken)            -> uid, or unauthorized / CLOUD_NOT_CONFIGURED
  action aiStats -> admins/{uid} readable with the user's token? -> 7-day counts, else unauthorized
  profiles/{uid} (user's token): status must be "active"         -> else unauthorized
  country in EU/EEA/UK/CH list                                   -> AI_REGION_RESTRICTED
  lock 10 s; counter AI_U_<date>_<uid> >= AI_USER_DAILY_LIMIT (default 10) -> AI_USER_LIMIT
  counter + 1; analyzeMeal_(req)          (global cap and Gemini call shared with the owner path)

8.3 رموز الأخطاء

AI_NOT_CONFIGURED وAI_BAD_IMAGE وAI_DAILY_LIMIT وAI_USER_LIMIT وAI_REGION_RESTRICTED وAI_QUOTA_DAY وAI_QUOTA_MINUTE (مع retryAfter) وAI_REGION وAI_KEY_INVALID وAI_MODEL_UNAVAILABLE وAI_BUSY (رمز HTTP ‏≥ 500) وAI_HTTP_<code> وAI_NETWORK وAI_REFUSED وAI_TRUNCATED وAI_BAD_OUTPUT. لا توجد إعادة محاولة على نموذج أو خدمة أخرى.

8.4 إدارة المفاتيح

يقبل setAiKey المفاتيح المطابقة للنمط [A-Za-z0-9_.-]{20,200} (الصيغتان الكلاسيكية والأحدث)، ويتحقق منها بطلب GET على نقطة البيانات الوصفية للنموذج، ولا يحفظها إلا إذا أجابت Google بالرمز 200. والقيمة remove: true تحذف المفتاح. ويحفظ setCloudConfig الخاصيتين FIREBASE_API_KEY وFIREBASE_PROJECT_ID (معرّفات عامة)، ويضبط اختيارياً AI_USER_DAILY_LIMIT ضمن 1–50 وAI_DAILY_LIMIT ضمن 1–1500. وتحذف cleanupAiCounters() العدّادات الأقدم من 8 أيام.

9. Firebase كخلفية مُدارة

لا توجد شيفرة خادم للحسابات العامة؛ إذ يستخدم العميل حزمة Firebase مباشرة، ويمثّل الملف firebase/firestore.rules السياسة على جانب الخادم. أهم القواعد: لا يقرأ المستخدم ولا يكتب إلا في users/{uid الخاص به}/**، وفقط ما دامت حالة ملفه active؛ ولا يجوز للتحديث أن يُنقص updatedAt؛ ويُتحقَّق من شكل السجل وأسماء الجداول؛ ويحق للمشرفين (بوجود admins/{uid}، الذي لا يمكن لأحد كتابته من العميل) سرد الملفات الشخصية وتغيير status فقط، دون أي وصول إلى users/**؛ والأطعمة المشتركة foods يقرؤها المستخدمون النشطون ويكتبها المشرفون؛ ولكلٍّ من foodSubmissions وerrorReports قواعده المحدودة. التفاصيل في MEGO_Firebase_Integration.
