Purpose and scope

This document lists every configuration point of MEGO: build-time variables, runtime configuration files, per-device settings, browser storage keys, Apps Script project settings and Script Properties, Firebase project files, and the variables and flags of the setup and test scripts. Values that are secrets (tokens, keys, URLs of the private backend) are named but never reproduced.

The repository contains no .env file; no other VITE_* variable is read by the source code.

3. Runtime configuration file: firebase-config.json

Location: public/firebase-config.json, served at <base>/firebase-config.json and fetched by loadCloudConfig() with cache: 'no-cache'. It is written by scripts/laptop-setup.mjs --cloud and committed ("Enable public accounts (Firebase config: public identifiers only)").

KeyContentSecret?
apiKeyFirebase web API keyPublic identifier (access is enforced by Firestore rules); still never copied into documents
authDomain, projectId, appIdFirebase project identifiersPublic
aiBackendUrlApps Script web app used as the AI proxy by signed-in accounts (they authenticate with their Firebase ID token, not the app token)Not a secret by design, but not reproduced here
emulator (optional){ authUrl, firestoreHost, firestorePort }Tests only; absent in production

Effect: file missing or without apiKey/projectId → guest-only app. File present → welcome screen with sign-in/registration and an optional guest mode.

7. Firebase project configuration

  • firebase.json: rules file firebase/firestore.rules, indexes firebase/firestore.indexes.json (empty), emulators auth 9099 and firestore 8080, UI disabled, single-project mode.
  • Production (brief, verified 7 Nov 2026): project id mego-473920, Firestore (default) in me-central2, Email/Password provider enabled, Spark plan (no billing).
  • Admin role: a document admins/{uid}, which the rules never allow clients to write; created by the setup script with the owner's credentials.

8. Setup and test scripts: variables and flags

8.1 scripts/laptop-setup.mjs

Flag / variableEffect
(none)Full setup or update (safe to run again)
--testOnly the live integration tests against the existing backend
--update-backendUpload the latest Code.gs to the same deployment (same URL, data untouched) and run the AI diagnostic

--verifyRe-run scripts/live-verify.mjs against the deployed site
MEGO_BACKEND_DIRPrivate state folder (default ~/.mego-backend/); state.json is written with file mode 600 and holds script ID, URL and token
MEGO_FAKE_BACKEND, MEGO_FAKE_SECRETTest mode against a local fake backend (used by e2e tests)

8.2 Test scripts

  • E2E_BASE — run e2e/run-e2e.mjs against a deployed URL instead of a local preview.
  • KEEP_PROFILE — keep the browser profile after e2e (used for screenshots).
  • e2e/scroll-test.mjs reads PAGES, PROBE, FIXCSS; e2e/multiuser-test.mjs reads SHOTS. Their exact semantics: Not verified in this document (see the scripts).
