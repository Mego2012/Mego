الغرض والنطاق

تصف هذه الوثيقة كيف يكتشف MEGO الأخطاء ويعرضها ويعيد المحاولة ويسجّلها: الحماية من انهيار الواجهة، والرسائل الظاهرة للمستخدم، وأخطاء التحقق من المدخلات، وأخطاء المزامنة (الـ Hub وFirestore)، ورموز أخطاء ماسح الوجبات الذكي في الخادم والعميل، وأخطاء المصادقة، وآلية reportError، والسجلات الأخرى الموجودة (تبويبات الـ Hub وسجل Apps Script). لا يستخدم MEGO أي خدمة خارجية لتتبع الأخطاء أو للتحليلات؛ والسجل البعيد الوحيد للأخطاء هو مجموعة Firestore ‏errorReports.

1. المبادئ

  • لا يجوز أن يتلف الخطأ البيانات أو يستبدلها بصمت: تُرفض النسخ الأقدم، والحذف في الـ Hub ناعم، وتُؤخذ نسخ احتياطية محلية قبل العمليات الحساسة.
  • الإخفاقات المؤقتة يُعاد تجربتها تلقائيًا مع تراجع زمني؛ أما الدائمة (رمز خاطئ، جدول خاطئ، حصة منتهية، مفتاح غير صالح) فلا يُعاد تجربتها وتُعرض للمستخدم.
  • الإبلاغ عن الخطأ لا يجوز أن يعطّل التطبيق (reportError تبتلع أخطاءها).
  • تقارير الأخطاء لا تحتوي بيانات شخصية ولا مفاتيح ولا رموزًا (تفاصيل google في الخادم تستثني المفتاح).

2. الحماية من انهيار الواجهة (ErrorBoundary)

يلفّ src/components/ErrorBoundary.tsx الصفحات الموجَّهة داخل الإطار، ومفتاحه هو المسار الحالي، فينعدم أثره عند الانتقال لصفحة أخرى. عند حدوث خطأ في العرض:

  • يسجّل console.error('UI error', error) في وحدة تحكم المتصفح؛
  • ويعرض بطاقة استرداد (data-testid="error-screen") بعنوان ونص مترجمين ورسالة الخطأ (من اليسار لليمين)، وزرين: إعادة المحاولة (يمسح الخطأ ويعيد العرض) وإعادة التحميل (ينتقل إلى #/ ويعيد التحميل).

البيانات في IndexedDB ولا تتأثر بخطأ الواجهة. ولا تُرسل انهيارات الواجهة إلى errorReports.

3. الأخطاء الظاهرة للمستخدم والتحقق من المدخلات

تمر معظم الإجراءات عبر useAsync().run() ‏(src/components/ui.tsx): تضبط حالة الانشغال، وتعرض رسالة نجاح اختيارية، وعند الفشل تعرض تنبيهًا «خطأ: <الرسالة>» (ويُعرض خطأ DUPLICATE: برسالة «طعام مكرر» المترجمة).

مصدر الخطأالرسالة
createFood / updateFood (repo.ts)Invalid nutrition values: …، Name is required، DUPLICATE:<food id>، Food not found
saveSettings (repo.ts)Invalid targets: kcal, protein … (يجب أن تكون السعرات > 0 والعناصر الكبرى ≥ 0)
firebase.tsAGE_REQUIRED، NOT_SIGNED_IN، CLOUD_NOT_CONFIGURED

التغييرات الحساسة (مثل تغيّر الـ Hub ‏HUB_CHANGED) تطلب تأكيدًا في نافذة قبل تغيير أي شيء.

4. أخطاء الإقلاع

  • إخفاق preMigrationBackup() أو preUpdateBackup() يُسجَّل بـ console.warn ولا يوقف التطبيق.
  • إخفاق bootAccount() يعود إلى وضع الضيف.
  • غياب firebase-config.json أو أي خطأ في جلبه أو تحليله ← وضع الضيف فقط (دون عرض خطأ).
  • جلسة منتهية أو تخص معرّفًا آخر ← يُمسح الحساب النشط وتُعاد تحميل الصفحة إلى شاشة الترحيب.

5. أخطاء المزامنة: Hub جداول Google

الخطأالمصدرالمعالجة
Sync URL not configuredcallScriptالحالة disabled (ويُتخطى الرفع مسبقًا)
HTTP <status>رد غير ناجحإعادة المحاولة مع التراجع
unauthorizedرمز خاطئدائم — لا يُعاد
WRONG_SPREADSHEET: …checkHub: الخادم غير متصل بالـ Hubدائم — لا يُعاد
HUB_CHANGED: …checkHub: جدول أصلي مختلفتطلب الإعدادات تأكيدًا قبل إعادة التثبيت
HUB_IS_XLSX: …الخادم في وضع Excel للقراءة فقطدائم — لا يُعاد
تحقق الخادم (… invalid change(s) rejected، too many changes in one request)push_يُعاد مع التراجع (غير مُتحقَّق منه ما إذا كانت مثل هذه الدفعة يمكن أن تنجح دون تدخل المستخدم)
التعارضات (conflicts[] في رد الرفع)push_ليست خطأ: تُعدّ في الحالة وتعيد pullAll() السجلات الأحدث

عند الإخفاق: backoffMs(n) = min(300000, 5000 × 2^(n−1))، ويُحفظ sync.lastError في الإعدادات، وتعرض شارة الحالة error (أو offline) مع «إعادة المحاولة خلال N ث». أخطاء مزامنة الـ Hub لا تُرسل إلى errorReports (أجهزة الضيف/المالك عادةً غير مسجلة الدخول).

6. أخطاء المزامنة: Firestore

  • permission-denied عند الرفع: يُعدّ تعارضًا (الخادم يملك نسخة أحدث، أو الحساب موقوف)؛ ويُحذف العنصر من الصادر.
  • أخطاء رفع أخرى: تتوقف الدورة، والحالة error مع الرسالة، وreportError('sync', message).
  • فشل تطبيق سجل وارد: reportError('sync-apply', '<table>/<id>: <message>')؛ ويستمر التنزيل بالسجل التالي.
  • خطأ المستمع: الحالة error مع الرسالة. ومستمع الأطعمة المشتركة يتجاهل الأخطاء (دون اتصال تبقى النسخة المحلية تعمل).
  • دون اتصال: الحالة offline؛ ويُستأنف الرفع بعد 300 مللي ث من عودة الاتصال.

7. أخطاء ماسح الوجبات الذكي

7.1 التحويل في الخادم (Code.gs، الدالة aiError_)

سلسلة النماذج (المستوى المجاني فقط): gemini-3.8-flash ← gemini-3.6-flash ← gemini-3.5-flash-lite، بمهلة إجمالية 240 ث. تُسجَّل كل محاولة فاشلة عبر console.warn('Gemini <model> → <code> …') في Apps Script (تسجيل الاستثناءات: STACKDRIVER). رموز أخرى من الخادم: AI_NOT_CONFIGURED وAI_DAILY_LIMIT وAI_USER_LIMIT وAI_REGION_RESTRICTED وAI_REFUSED وAI_BAD_OUTPUT وAI_TRUNCATED. التحليل الفاشل لا يستهلك الحصة اليومية (العداد العام يزداد عند النجاح فقط، وعداد المستخدم يُستردّ).

7.2 المعالجة في العميل (src/lib/mealScanner.ts وMealScanner.tsx)

  • التحقق من الصورة قبل الإرسال: AI_UNSUPPORTED_FORMAT (ليست صورة أو تعذّر فك ترميزها — لا تُرسل الصورة الأصلية أبدًا)، وAI_IMAGE_TOO_LARGE (أكبر من 30 ميغابايت، أو ما زالت فوق حد الرفع بعد التصغير).
  • قبل الطلب: AI_NO_BACKEND (لا خادم مهيأ / غير مسجل الدخول)، وAI_OFFLINE؛ ومهلة العميل 280 ث ← AI_TIMEOUT.
  • تحويل ردود الخادم: AI_QUOTA_DAY مع وقت إعادة التعيين (منتصف الليل بتوقيت America/Los_Angeles، معروضًا بالتوقيت المحلي)؛ AI_QUOTA_MINUTE مع الثواني؛ AI_USER_LIMIT مع الحد؛ AI_HTTP_* ← AI_SERVER_ERROR؛ unauthorized ← AI_UNAUTHORIZED؛ unknown action ← AI_OLD_BACKEND؛ HTTP 5xx ← AI_SERVER_ERROR؛ HTTP 4xx ← AI_CONFIG؛ وأي شيء آخر ← AI_NETWORK. وتُمرَّر حالة Google ورسالتها كسطر تفصيلي («قالت Google: …»).
  • إعادة المحاولة التلقائية: الرموز المؤقتة (AI_OVERLOADED, AI_SERVER_ERROR, AI_TIMEOUT, AI_NETWORK, AI_BUSY) بعد 3 ث و8 ث (ولا يُعاد AI_NETWORK دون اتصال)؛ وتُنتظر حصة الدقيقة إذا كانت ≤ 20 ث. وتعرض الشاشة «إعادة المحاولة n/2 (السبب)». ولا تُرسل الصورة نفسها مرتين في وقت واحد.
  • عند الفشل النهائي تُعرض الرسالة المترجمة (والرموز غير المعروفة ← AI_ERROR)؛ وفي الأخطاء المؤقتة تُحفظ الصورة ليعيد المستخدم المحاولة يدويًا.
  • يُتحقق من صحة النتائج (AI_BAD_OUTPUT عند الخلل)؛ ولا يُحفظ شيء تلقائيًا.

السبب الجذري لرسالة «الذكاء الاصطناعي مشغول» العامة سابقًا: ضغط 503 لدى Google على النموذج الأساسي، والذي كان الخادم القديم يبلّغ عنه كانشغال دون إعادة محاولة (أُصلح في الإصدار 7 من الخادم).

8. أخطاء المصادقة

تُحوَّل أخطاء Firebase حسب الرمز (auth/…) إلى رسائل مترجمة بالبادئة authErr_؛ والرموز غير المعروفة تستخدم authErr_generic. الرموز المحوَّلة: email_already_in_use وinvalid_credential وinvalid_email وnetwork_request_failed وrequires_recent_login وtoo_many_requests وuser_disabled وuser_not_found وweak_password وwrong_password. وتُتجاهل إخفاقات تحديث الملف الشخصي دون اتصال أو عند الإيقاف (touchProfile).

9. الإبلاغ عن الأخطاء: reportError وerrorReports

reportError(kind, message)
  └─ only if Firebase is initialised AND a user is signed in
  └─ setDoc(errorReports/<auto id>, { at: Date.now(), kind: kind[0..40], message: message[0..400], app: '1' })
  └─ any failure is swallowed
النوع (المستدعون الحاليون)متى
syncفشلت دورة رفع إلى Firestore بخطأ غير permission-denied
sync-applyتعذّر تطبيق سجل وارد محليًا
  • قواعد الأمان: يحق لأي مستخدم مسجل إنشاء تقرير بالمفاتيح at/kind/message/app فقط ورسالة أقل من 500 حرف؛ والقراءة والحذف للمشرفين فقط.
  • لوحة المشرف (#/admin): تعرض adminListErrors(50) أحدث 50 تقريرًا (شارة النوع، الرسالة، التاريخ). لا توجد تنبيهات تلقائية.
  • لا توجد مهمة احتفاظ أو تنظيف لـ errorReports (وحذفها يدويًا غير مُتحقَّق منه).
