الغرض والنطاق

تشرح هذه الوثيقة كيفية بناء تطبيق MEGO من جهة العميل: الأدوات، وبنية المجلدات، والتوجيه (Routing)، والصفحات والمكوّنات، ودعم اللغات والاتجاه من اليمين إلى اليسار (RTL)، ونظام التصميم، وعامل الخدمة في تطبيق الويب التقدّمي (PWA)، والتحميل الكسول (Lazy Loading)، ومخرجات البناء. أما إدارة الحالة ومعالجة الأخطاء فلكل منهما وثيقة مستقلة. تم التحقق من كل المعلومات في package.json وvite.config.ts وindex.html وsrc/main.tsx وsrc/App.tsx وsrc/app/AppContext.tsx وsrc/components/* وsrc/lib/i18n*.ts وsrc/styles.css وsrc/screens.css.

3. هيكل التطبيق والتوجيه

3.1 المزوّدات (Providers)

يغلّف المكوّن App كل شيء داخل AppProvider (سياق React) وموجّه HashRouter (مع خيارَي المستقبل v7_startTransition وv7_relativeSplatPath). يعمل التوجيه بعلامة # (مثل #/diary) على GitHub Pages دون الحاجة لإعادة كتابة المسارات في الخادم. يقرأ AppProvider سجل الإعدادات عبر useLiveQuery من Dexie، فيُعاد رسم التطبيق عند أي تغيير في الإعدادات؛ كما يضبط document.documentElement.lang وdir وdocument.title والسمة data-theme.

3.3 قرار العرض

Routed()
  settings not loaded yet          -> <Skeleton/>   (then the #splash element fades out and is removed)
  mode = welcome or suspended,
    path not /privacy or /terms    -> AccountRouter view "welcome" or "suspended" (no app shell)
  mode = welcome, legal path       -> AccountRouter view "privacy" / "terms" (no app shell)
  otherwise                        -> <Layout> <ErrorBoundary key=path> <Suspense> <Routes/>

يُربط مكوّن حدود الأخطاء (ErrorBoundary) بالمسار كمفتاح، فلا يبقى خطأ شاشةٍ ما بعد الانتقال إلى غيرها؛ ويعرض زرَّي «إعادة المحاولة» و«إعادة التحميل» (الذي يعود إلى #/).

3.4 التخطيط (Layout)

يعرض src/components/Layout.tsx قائمة تنقل جانبية (للشاشات العريضة)، وترويسة ثابتة فيها شارة المزامنة (الحالة، وعدد العناصر المعلّقة، والعدّ التنازلي لإعادة المحاولة؛ والضغط عليها يفتح /settings#sync إن كانت المزامنة معطّلة أو يستدعي pushNow())، وشريط تنبيه عند انقطاع الاتصال، وقائمة تنقل سفلية بأربعة عناصر (اللوحة، اليوميات، الوصفات، التقدم) إضافة إلى لوحة «المزيد» التي تسرد بقية المسارات.

5. تعدد اللغات والاتجاه من اليمين إلى اليسار

  • القواميس: src/lib/i18n.ts وi18n2.ts وi18n3.ts، وتُدمج في DICTS = { ar: {...ar, ...ar2, ...ar3}, en: {...en, ...en2, ...en3} }.
  • تبحث الدالة translate(lang, key, params) في اللغة الحالية، ثم تعود إلى الإنجليزية، ثم إلى المفتاح نفسه؛ وتُستبدل العناصر النائبة مثل {name} من params.
  • الأرقام: تستخدم fmtNum واجهة Intl.NumberFormat بالإعداد المحلي ar-SA-u-nu-latn (عربي بأرقام لاتينية) أو en-US، وتعرض القيم المفقودة بالشرطة «—». التواريخ: تستخدم fmtDate الإعداد ar-SA-u-ca-gregory-nu-latn (التقويم الميلادي) أو en-GB.
  • الاتجاه: يضبط AppProvider القيمة <html dir="rtl"> للعربية وltr للإنجليزية. يبدأ index.html بـlang="ar" dir="rtl"، ويعلن ملف البيان lang: 'ar' وdir: 'auto'.
  • تستخدم أوراق الأنماط الخصائص المنطقية (inline-start/inline-end) مع بعض التخصيصات عبر [dir="rtl"] (تباعد الأحرف، وعكس الأيقونات بالصنف .flip، واتجاه التدرّج اللوني).
  • تُعرض حقول الإدخال ذات الطابع البرمجي (الروابط، والرموز، ورمز الاتصال) بالاتجاه dir="ltr".

6. نظام التصميم

يعرّف الملف src/styles.css نظام التصميم «Calibrated» بمظهرين: Mineral (فاتح) وGraphite (داكن)، كخصائص CSS مخصّصة على :root.

مجموعة الرموز (Tokens)أمثلة
الأسطح والنص--bg و--surface و--surface-2/3 و--text و--muted و--border
اللون المميّز والحالات--primary (الفاتح ‎#0a7c63، الداكن ‎#3ddcb0) و--danger و--good و--warn و--info
ألوان المغذيات--kcal و--protein و--carbs و--fat
الخطوط--font-display (Readex Pro) و--font-text (IBM Plex Sans Arabic)؛ السلّم من --fs-xs ‏11.5px إلى --fs-3xl ‏46px
المسافات والأشكالشبكة 4px ‏--sp-1…--sp-6؛ --radius-s/--radius/--radius-l
التخطيط--nav-h ‏68px و--header-h ‏58px

اختيار المظهر: عند ضبط الإعداد theme = 'system' تُزال السمة data-theme ويُطبَّق Graphite عبر @media (prefers-color-scheme: dark)؛ أما light وdark فيضبطان data-theme صراحة. ويحتوي src/screens.css على أقسام لكل شاشة (صور الأطعمة، اليوميات، منتقي الأطعمة، الأطعمة، المدرب، الترتيب، التفاصيل، التثقيف، التقدم، التقارير، الإعدادات، الحساب والمشرف، الوصفات).

7. تطبيق الويب التقدّمي وقواعد التخزين المؤقت

ملف البيان (من vite.config.ts): الاسم «MEGO — Nutrition»، والاسم المختصر «MEGO»، وdisplay: standalone، وorientation: portrait، ولون السمة والخلفية ‎#080d0f، وقيمتا start_url وscope = المسار الأساسي، وأيقونات 192 و512 و512 قابلة للقص (maskable). عامل الخدمة: registerType: 'autoUpdate'، ويُسجَّل عبر registerSW({ immediate: true }).

8. التحميل الكسول ومخرجات البناء

  • تحميل مباشر: Dashboard وDiary (الشاشتان الأكثر استخداماً) وهيكل التطبيق.
  • تحميل كسول على مستوى المسار: Foods وRecipes وPlanner وProgress وReports وSettings وHabits وCoach وصفحات الحساب، عبر React.lazy وSuspense مع هيكل تحميل (Skeleton) بديل.
  • استيراد ديناميكي على مستوى الوحدات: xlsx (فقط عند تصدير/استيراد Excel)، وcloudSync (فقط في وضع الحساب)، وأجزاء من firebase/firestore وfirebase/auth تُستخدم في إجراءات نادرة، وdemoSeed (فقط عند VITE_DEMO=1، ويُحذف من بناء الإنتاج).
  • البناء: الأمر npm run build = tsc -b && vite build. المسار الأساسي من BASE_PATH (يضبطه سير عمل GitHub إلى /<repository name>/، ومحلياً /). حدّ التحذير لحجم الأجزاء 900 كيلوبايت. المخرجات في dist/: ‏index.html وassets/ (ملفات JS/CSS بأسماء مجزّأة، جزء لكل صفحة كسولة أو وحدة ديناميكية) وsw.js وworkbox-*.js وmanifest.webmanifest ونسخة من ملفات public/ (الأيقونات، وfirebase-config.json، وfooddb/، وfood-img/).
