Purpose and scope

This document describes how the MEGO client application is built: tooling, folder structure, routing, pages and components, internationalisation and right-to-left (RTL) layout, the design system, the Progressive Web App (PWA) service worker, lazy loading and the build output. State management and error handling are covered in their own documents. All facts were checked in package.json, vite.config.ts, index.html, src/main.tsx, src/App.tsx, src/app/AppContext.tsx, src/components/*, src/lib/i18n*.ts, src/styles.css and src/screens.css.

3. Application shell and routing

3.1 Providers

App wraps everything in AppProvider (React context) and a HashRouter (future flags v7_startTransition, v7_relativeSplatPath). Hash routing (#/diary) works on GitHub Pages without server rewrites. AppProvider reads the settings record with useLiveQuery from Dexie, so any change to settings re-renders the app; it also sets document.documentElement.lang, dir, document.title and the data-theme attribute.

3.3 Render decision

Routed()
  settings not loaded yet          -> <Skeleton/>   (then the #splash element fades out and is removed)
  mode = welcome or suspended,
    path not /privacy or /terms    -> AccountRouter view "welcome" or "suspended" (no app shell)
  mode = welcome, legal path       -> AccountRouter view "privacy" / "terms" (no app shell)
  otherwise                        -> <Layout> <ErrorBoundary key=path> <Suspense> <Routes/>

ErrorBoundary is keyed by the path, so an error on one screen does not persist after navigating; it shows "retry" and "reload" (which goes to #/).

3.4 Layout

src/components/Layout.tsx renders a side navigation (wide screens), a sticky header with the sync chip (state, pending count, retry countdown; tapping it opens /settings#sync when sync is disabled or calls pushNow()), an offline banner, and a bottom navigation with four entries (Dashboard, Diary, Recipes, Progress) plus a "More" sheet listing the remaining routes.

5. Internationalisation and RTL

  • Dictionaries: src/lib/i18n.ts, i18n2.ts, i18n3.ts, merged as DICTS = { ar: {...ar, ...ar2, ...ar3}, en: {...en, ...en2, ...en3} }.
  • translate(lang, key, params) looks up the current language, falls back to English, then to the key itself; {name} placeholders are replaced from params.
  • Numbers: fmtNum uses Intl.NumberFormat with ar-SA-u-nu-latn (Arabic locale, Latin digits) or en-US; missing values display "—". Dates: fmtDate uses ar-SA-u-ca-gregory-nu-latn (Gregorian calendar) or en-GB.
  • Direction: AppProvider sets <html dir="rtl"> for Arabic and ltr for English. index.html starts with lang="ar" dir="rtl" and the manifest declares lang: 'ar', dir: 'auto'.
  • CSS uses logical properties (inline-start/inline-end) and a few [dir="rtl"] overrides (letter-spacing, mirrored icons with .flip, gradient direction).
  • Code-like input fields (URLs, tokens, connection code) are rendered with dir="ltr".

Theme selection: with setting theme = 'system' the attribute data-theme is removed and @media (prefers-color-scheme: dark) applies Graphite; light / dark set data-theme explicitly. src/screens.css contains per-screen sections (food photography, Diary, food picker, Foods, Coach, rankings, detail, education, Progress, Reports, Settings, Account & Admin, Recipes).

7. PWA and caching rules

Manifest (from vite.config.ts): name "MEGO — Nutrition", short name "MEGO", display: standalone, orientation: portrait, theme/background #080d0f, start_url and scope = base path, icons 192, 512 and 512 maskable. Service worker: registerType: 'autoUpdate', registered with registerSW({ immediate: true }).

ResourceStrategy
App shell **/*.{js,css,html,svg,png,woff2} + fooddb/usda.jsonPrecache (max 3 MB per file)
NavigationsFallback index.html, except paths matching ^/macros/
fooddb/usda-extra.jsonStaleWhileRevalidate
food-img/*.webpCacheFirst, 200 entries, 1 year
food-img/manifest.jsonStaleWhileRevalidate
fonts.googleapis.com / fonts.gstatic.comStaleWhileRevalidate / CacheFirst (20 entries, 1 year)

index.html contains an inline splash (SVG ring) that is removed once settings are ready, plus light/dark theme-color metas. main.tsx also calls navigator.storage.persist() to reduce the risk of the browser evicting IndexedDB data.

8. Lazy loading and build output

  • Eager: Dashboard and Diary (the two most-used screens) and the shell.
  • Route-level lazy: Foods, Recipes, Planner, Progress, Reports, Settings, Habits, Coach and the Account pages via React.lazy + Suspense with a Skeleton fallback.
  • Module-level dynamic imports: xlsx (only when exporting/importing Excel), cloudSync (only in account mode), parts of firebase/firestore and firebase/auth used by rare actions, and demoSeed (only when VITE_DEMO=1; dropped from production builds).
  • Build: npm run build = tsc -b && vite build. Base path from BASE_PATH (the GitHub workflow sets /<repository name>/; locally /). chunkSizeWarningLimit 900 kB. Output in dist/: index.html, assets/ (hashed JS/CSS, one chunk per lazy page or dynamic module), sw.js, workbox-*.js, manifest.webmanifest, and the copied public/ files (icons, firebase-config.json, fooddb/, food-img/).
