الغرض والنطاق

توضح هذه الوثيقة أين يحتفظ MEGO بحالته وكيف تنتقل التغييرات داخل التطبيق: سياق React ‏(src/app/AppContext.tsx)، وخطافات البيانات (src/app/hooks.ts)، والاستعلامات الحية (live queries) في Dexie فوق IndexedDB، وطبقة المستودع وإشعارات التغيير (src/lib/repo.ts)، وجدول المفتاح/القيمة العام (kv) ومفاتيحه، والمخازن الصغيرة على مستوى الوحدات لحالة الحساب والمزامنة. لا يستخدم MEGO أي مكتبة حالة خارجية (لا Redux ولا Zustand ولا ما يشبههما)؛ فقاعدة البيانات المحلية هي مصدر الحقيقة الوحيد.

1. مبادئ التصميم

  • قاعدة البيانات أولًا: البيانات الدائمة في IndexedDB ‏(Dexie). تقرؤها الشاشات عبر استعلامات حية، فأي كتابة — محلية أو من استقبال الـ Hub أو من مستمع Firestore — تعيد رسم الشاشات المعنية تلقائيًا.
  • مسار كتابة واحد: كل تغيير دائم يمر عبر repo.ts (أو وحدات مبنية عليه)، والذي يضع التغيير أيضًا في outbox للمزامنة.
  • الإعدادات بيانات: سجل الإعدادات (settings/main) يُقرأ باستعلام حي في AppContext، فتتغير اللغة والمظهر والأهداف في كل مكان دفعة واحدة.
  • حالة المكوّن محلية: النماذج والنوافذ والتحديدات تستخدم useState داخل المكوّن.

3. AppContext

يلفّ AppProvider التطبيق كله (خارج الموجّه). يقرأ db.settings.get('main') عبر useLiveQuery ويدمجه فوق defaultSettings() (دمج متداخل للملف الشخصي والأهداف والتسامح والمزامنة)، فيكون لحقول الإعدادات الجديدة قيمة دائمًا.

العضوالمعنى
settingsكائن الإعدادات المدمج
readytrue بعد عودة الاستعلام الحي (تُزال شاشة البداية وتُعرض المسارات)
lang، dir"ar" ← "rtl"، و"en" ← "ltr"؛ ويُطبَّقان على <html lang dir> وعنوان المستند
t(key, params)الترجمة (translate(lang, …))
n(value, digits)، d(iso, opts)تنسيق الأرقام والتواريخ حسب اللغة الحالية
toast(msg, action?)يعرض رسالة حالة (role="status") مع زر إجراء اختياري (مثل التراجع)

ويطبّق تأثير ثانٍ المظهر: system يزيل data-theme، وlight/dark يضبطه. وترمي useApp() الخطأ «useApp outside provider» إذا استُخدمت خارج المزوّد.

4. خطافات البيانات واستعلامات Dexie الحية

5. الكتابة: المستودع وصندوق الصادر وإشعارات التغيير

  1. تستدعي الشاشة دالة من المستودع (مثل addFoodEntry أو saveSettings أو kvSet).
  2. تتحقق الدالة من المدخلات (مثل validateMacros وvalidateTargets وفحص التكرار)، وتكتب جدول Dexie (داخل معاملة عند تغيّر عدة جداول)، وتستدعي enqueue(table, key, op, payload).
  3. تضيف enqueue عنصرًا إلى الصادر { table, key, op, payload, at } وتُخطر كل مستمعي onLocalChange.
  4. المستمعون: المزامنة التلقائية مع الـ Hub ‏(startAutoSync، رفع بعد 2.5 ث) أو مزامنة Firestore ‏(startCloudSync، رفع بعد 1.5 ث) حسب الوضع.
  5. تعيد استعلامات Dexie الحية رسم الشاشات التي تقرأ الجداول المتغيرة.

خصوصية الإعدادات: تنشئ getSettings() السجل الافتراضي بـ updatedAt: 0 عند أول تشغيل، فلا يتقدم إعداد افتراضي غير معدّل على إعدادات الحساب القادمة من السحابة. وتنسخ saveSettings(update) الإعدادات الحالية وتطبّق التحديث وتتحقق من أهداف أيام التمرين والراحة (السعرات > 0 والعناصر الكبرى ≥ 0) وتضبط updatedAt ثم تكتب وتضع السجل في الطابور دون كتلة sync.

التغييرات الواردة: مستمع Firestore ‏(applyRemote) واستقبال الـ Hub ‏(pullAll) يكتبان في Dexie مباشرة (لا عبر الصادر) ويحتفظان بالنسخة الأحدث حسب updatedAt؛ ثم تحدّث الاستعلامات الحية الواجهة.

6. جدول kv ومفاتيحه

يخزّن kv (Dexie الإصدار 2، المفتاح الأساسي key وفهرس updatedAt) سجلات { key, value, updatedAt }. ويُزامن كبقية الجداول (Firestore ‏users/{uid}/kv/{key}؛ وتبويب الـ Hub ‏App_KeyValue). الدوال المساعدة في repo.ts: kvGet(key, fallback) وkvSet(key, value) وkvDelete(key). الميزات الجديدة منذ إصدار 7 نوفمبر تحفظ بياناتها هنا، ولذلك ما زال مخطط Dexie بالإصدار 2.

7. مخازن الوحدات: الحساب وحالة المزامنة

  • account.ts يحتفظ بـ AccountState { mode, cloud, uid?, profile?, admin?, suspended? } مع accountState() وsubscribeAccount(fn) ودالة داخلية set() تُخطر المستمعين. ويقرؤه React عبر useAccount() ‏(src/pages/accountHook.ts، وهو منفصل كي لا تحمّل الحزمة الرئيسية شاشات Firebase مبكرًا). ويستخدمه Routed في App.tsx لعرض صفحات الترحيب أو الإيقاف أو الصفحات القانونية دون إطار التطبيق.
  • sync.ts يحتفظ بـ SyncStatus { state, pending, lastPushAt?, error?, retryIn?, conflicts? } مع subscribeSync وsetStatus. وتبلّغ فيه مزامنة الـ Hub ومزامنة Firestore معًا؛ وتقرؤه شارة الرأس عبر useSyncStatus() ‏(Layout.tsx).
  • تبديل الحساب أو وضع الضيف يعيد تحميل الصفحة دائمًا، فلا تبقى في الذاكرة أي حالة من الحساب السابق.

8. ترتيب الإقلاع واختيار قاعدة البيانات

  1. preMigrationBackup() — لقطة قبل ترقية Dexie (عند الحاجة).
  2. bootAccount() — يختار mego-nutrition أو mego-u-<uid> ‏(useDatabase) قبل أي عرض.
  3. preUpdateBackup() — مرة لكل إصدار (APP_RELEASE).
  4. getSettings() — ينشئ الإعدادات الافتراضية عند أول تشغيل.
  5. يرسم React ‏<App/> داخل StrictMode.
  6. في وضع الحساب: watchSession ← startCloudSync؛ وإلا startAutoSync (الـ Hub). ثم التذكيرات، والنسخة المحلية اليومية، وتسجيل عامل الخدمة.
