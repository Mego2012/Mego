1. نظرة عامة على النظام

MEGO تطبيق ويب تقدّمي (Progressive Web App – PWA) مبني باستخدام Vite وReact 18 وTypeScript، ومنشور كموقع ثابت على صفحات GitHub (GitHub Pages) على العنوان https://mego2012.github.io/Mego/. لا يوجد خادم تطبيقات مخصّص؛ فكل منطق الخادم يعمل على خدمات Google المُدارة:

  • التخزين المحلي أولاً — تُكتب كل بيانات المستخدم أولاً في قاعدة IndexedDB على الجهاز (عبر مكتبة Dexie في src/lib/db.ts)، ويعمل التطبيق بالكامل دون اتصال بالشبكة.
  • Firebase (خطة Spark المجانية) — خدمة المصادقة (Authentication) بالبريد وكلمة المرور، وقاعدة البيانات السحابية (Cloud Firestore) للحسابات المسجّلة. تُفرض صلاحيات الوصول عبر firebase/firestore.rules على خوادم Google.
  • تطبيق ويب على Google Apps Script (apps-script/Code.gs) — الخلفية الخاصة بالمالك: مزامنة ثنائية الاتجاه مع جدول Google «MEGO Nutrition Hub»، ونسخ احتياطية في Drive، ووسيط (Proxy) إلى واجهة Gemini لماسح الوجبات بالذكاء الاصطناعي (للمالك وللحسابات العامة المسجّلة).
  • بيانات مرجعية ثابتة — قاعدة بيانات USDA FoodData Central مضمّنة في التطبيق (public/fooddb/usda.json إضافة إلى usda-extra.json).
  • Open Food Facts — واجهة عامة تُستدعى مباشرة من المتصفح للبحث بالباركود والبحث النصي عن المنتجات المعبّأة (src/lib/barcode.ts).

4. أوضاع التشغيل وتسلسل الإقلاع

4.1 الأوضاع

يعرّف الملف src/lib/account.ts ثلاثة أوضاع في AccountState.mode:

الوضعمتىقاعدة البيانات المحليةالمزامنة البعيدة
guest (ضيف)عند غياب firebase-config.json أو عدم صلاحيته، أو عند اختيار المستخدم «المتابعة كضيف» (المفتاح mego.guest في localStorage)mego-nutritionمزامنة اختيارية مع جدول الـHub عبر Apps Script (أجهزة المالك)
welcome (ترحيب)السحابة مُعدّة، ولا يوجد حساب نشط، ولم يُختر وضع الضيف—لا شيء؛ تُعرض الصفحة العامة (ترحيب، دخول، تسجيل)
account (حساب)عند وجود المفتاح mego.activeUid في localStoragemego-u-<uid> (قاعدة مستقلة لكل حساب على الجهاز)مزامنة Firestore (cloudSync.ts)

4.2 تسلسل الإقلاع (src/main.tsx)

boot()
 1. preMigrationBackup()        copy old IndexedDB stores to "mego-nutrition-premigration" if a schema upgrade is due
 2. bootAccount()               fetch BASE_URL + "firebase-config.json" (no-cache)
       no config  -> mode guest (cloud=false)
       config     -> initCloud(); if mego.activeUid -> select "mego-u-<uid>", optional guest-data import,
                     apply pending registration setup -> mode account
                     else -> mode guest (if chosen) or welcome
 3. getSettings()               creates the default settings record on first run
 4. requestPersistentStorage()  navigator.storage.persist()
 5. render <App/>
 6. refreshPending()            outbox counter for the sync badge
 7. account mode -> watchSession(): confirm Firebase user, load profile/admin flag, then
                    dynamic import cloudSync.startCloudSync(uid)
    otherwise    -> startAutoSync() (Hub sync, only acts if a connection is configured)
 8. startReminders(); autoDailyBackup(); registerSW({ immediate: true })

عند تبديل الحساب (enterAccount وleaveAccount وchooseGuest) يُكتب المفتاح في localStorage ثم تُعاد تحميل الصفحة، بحيث تُختار قاعدة البيانات الصحيحة قبل عرض أي شيء. وإذا انتهت جلسة Firebase أو كانت لمستخدم آخر، تمسح watchSession المفتاح mego.activeUid وتعيد التحميل.

5. تدفقات البيانات

5.1 مسار الكتابة المحلي (في الوضعين)

كل عملية كتابة في src/lib/repo.ts تحفظ السجل في جدول Dexie الخاص به، وتضيف عنصراً {table, key, op: 'upsert'|'delete', payload, at} إلى جدول صندوق الصادر (outbox)، ثم تُبلغ المستمعين عبر onLocalChange. ومحرّك المزامنة الخاص بالوضع الحالي هو من يُفرغ صندوق الصادر.

5.2 جهاز الضيف/المالك — جدول الـHub

UI -> repo.ts -> Dexie table + outbox
                     |
          startAutoSync(): debounce 2.5 s after a change, 0.5 s on "online"/visible, every 60 s
                     v
pushNow(): assertHub(ping) -> batches of 300 outbox items -> coalesce ->
           POST {action:"push", changes, clientSchema, token}  -->  Code.gs push_()
                                                                   - validates, timestamp check
                                                                   - writes structured tabs
                                                                   - soft delete -> Deleted_Records
           <-- {applied, conflicts[], dataVersion}
           conflicts > 0 -> pullAll() (newer sheet copies win)

قيم الأطعمة يملكها تبويب Food_Database في الـHub، وتُستورد عبر pullFoodsFromSheet(). التفاصيل في وثيقة MEGO_Google_Sheets_Integration_and_Sync.

5.3 الحساب المسجّل — Firestore

UI -> repo.ts -> Dexie (mego-u-<uid>) + outbox
                     |
     startCloudSync(): debounce 1.5 s after a change, 0.3 s on "online"
                     v
pushCloud(): coalesce -> setDoc users/{uid}/{table}/{key} = {data: JSON string, updatedAt, deleted?}
             permission-denied -> counted as conflict (server holds a newer copy, or account suspended)

Firestore --onSnapshot(updatedAt > last seen)--> applyRemote(): newer remote copy replaces local
Firestore /foods --onSnapshot--> importParsedFoods(..., "sheet")  (shared verified foods)

التفاصيل في وثيقة MEGO_Firebase_Integration.

5.4 ماسح الوجبات بالذكاء الاصطناعي

يختار الملف src/lib/mealScanner.ts المسار حسب الوضع: في وضع الحساب يُرسل {action: "analyzeMeal", idToken, image, foods, lang, note} إلى العنوان aiBackendUrl المأخوذ من firebase-config.json؛ أما على أجهزة الضيف/المالك فيستخدم خلفية الـHub المُعدّة مع رمز التطبيق. وكلا المسارين يصل إلى الدالة نفسها analyzeMeal_() في Apps Script، والتي تستدعي Gemini بالمفتاح المحفوظ فقط في خصائص السكربت (Script Properties). لا يحفظ الماسح أي شيء تلقائياً. التفاصيل في MEGO_Gemini_AI_Integration وMEGO_Backend_Architecture.

5.5 بيانات الأطعمة المرجعية والخارجية

  • يجلب src/lib/refFoods.ts الملف fooddb/usda.json ويخزّنه عامل الخدمة مسبقاً؛ ويجلب src/lib/foodIntel.ts الملف fooddb/usda-extra.json ويُخزَّن وقت التشغيل.
  • تُستدعى Open Food Facts مباشرة من المتصفح: نقطة المنتج /api/v2/product/{code}.json ونقطة البحث /cgi/search.pl، وتتطلب اتصالاً بالشبكة.

يُولَّد عامل الخدمة بواسطة vite-plugin-pwa مع registerType: 'autoUpdate'، ويُسجَّل في main.tsx عبر registerSW({ immediate: true }). الإعدادات من vite.config.ts:

السلوك دون اتصال: كل القراءات والكتابات تتم على IndexedDB، وتنتظر عناصر صندوق الصادر حتى يُبلغ المتصفح بحالة online. يضبط محرّكا المزامنة الحالة إلى offline عندما تكون navigator.onLine خاطئة. ويعيد محرّك الـHub المحاولة عند الإخفاق بتراجع أُسّي (5 ث، 10 ث، 20 ث… حتى 5 دقائق كحد أقصى) باستثناء الأخطاء الدائمة (unauthorized وWRONG_SPREADSHEET وHUB_IS_XLSX). وتستأنف مستمعات Firestore عملها تلقائياً عند عودة الاتصال. أما البحث بالباركود وبحث Open Food Facts والماسح الذكي فتتطلب الشبكة.

7. حدود الخطط المجانية والقيود

  • لا يُستخدم أي حساب فوترة. تتوقف خطة Firebase Spark والطبقة المجانية من Gemini عن الخدمة عند بلوغ الحصص اليومية؛ ويعرض التطبيق خطأً دون اللجوء إلى خدمة مدفوعة.
  • ينفّذ Apps Script كل طلب بهوية المالك، ويُسلسل الكتابة على الـHub عبر LockService (انتظار حتى 25 ثانية).
  • حدود الذكاء الاصطناعي في Code.gs: الحد اليومي العام AI_DAILY_LIMIT (الافتراضي 40 عند عدم ضبط الخاصية)، والحد لكل مستخدم للحسابات العامة AI_USER_DAILY_LIMIT (الافتراضي 10). ويمكن لـsetCloudConfig ضبطهما ضمن 1–1500 و1–50.
  • تحدّ القواعد سجلات Firestore بنص data أقل من 300,000 حرف؛ وتحدّ طلبات الدفع إلى الـHub بـ500 تغيير و45,000 حرف لكل حمولة.
  • رُفض استخدام Google Sheets قاعدةَ بيانات متعددة المستخدمين (لا أمان على مستوى الصف، وكل طلب يعمل بهوية المالك)، فبقي الـHub شخصياً للمالك (docs/ARCHITECTURE.md).
