Purpose and scope

This document describes the overall system architecture of MEGO: which components exist, where they run, how they talk to each other, and how data flows in the two operating modes (guest/owner device and signed-in account). It is the entry point for developers; each component is described in more detail in the related documents. Everything here was checked against the code on branch claude/nutrition-tracking-app-989rku (mainly src/main.tsx, src/lib/account.ts, src/lib/firebase.ts, src/lib/cloudSync.ts, src/lib/sync.ts, src/lib/db.ts, apps-script/Code.gs, vite.config.ts and .github/workflows/deploy.yml).

1. System overview

MEGO is a Progressive Web App (PWA) built with Vite, React 18 and TypeScript. It is a static site published on GitHub Pages (https://mego2012.github.io/Mego/). There is no custom application server: every piece of server-side logic runs on managed Google services:

  • Local-first storage — all user data is first written to IndexedDB on the device (Dexie, src/lib/db.ts). The app works fully without a network connection.
  • Firebase (Spark plan) — Authentication (e-mail/password) and Cloud Firestore for signed-in accounts. Access control is enforced by firebase/firestore.rules on Google's servers.
  • Google Apps Script web app (apps-script/Code.gs) — the owner's private backend: two-way sync with the Google Sheet "MEGO Nutrition Hub", Drive backups, and the proxy to the Gemini API for the AI meal scanner (for both the owner and signed-in public accounts).
  • Static reference data — USDA FoodData Central database shipped with the app (public/fooddb/usda.json, plus usda-extra.json).
  • Open Food Facts — public API called directly from the browser for barcode lookup and packaged-product text search (src/lib/barcode.ts).

4. Operating modes and boot sequence

4.1 Modes

src/lib/account.ts defines three modes in AccountState.mode:

ModeWhenLocal databaseRemote sync
guestfirebase-config.json is missing/invalid, or the user chose "continue as guest" (localStorage mego.guest)mego-nutritionOptional Google Sheet Hub sync via Apps Script (owner devices)
welcomeCloud is configured, no active account and guest mode not chosen—None; the public landing (welcome, login, registration) is shown
accountlocalStorage mego.activeUid is setmego-u-<uid> (one database per account on the device)Firestore sync (cloudSync.ts)

4.2 Boot sequence (src/main.tsx)

boot()
 1. preMigrationBackup()        copy old IndexedDB stores to "mego-nutrition-premigration" if a schema upgrade is due
 2. bootAccount()               fetch BASE_URL + "firebase-config.json" (no-cache)
       no config  -> mode guest (cloud=false)
       config     -> initCloud(); if mego.activeUid -> select "mego-u-<uid>", optional guest-data import,
                     apply pending registration setup -> mode account
                     else -> mode guest (if chosen) or welcome
 3. getSettings()               creates the default settings record on first run
 4. requestPersistentStorage()  navigator.storage.persist()
 5. render <App/>
 6. refreshPending()            outbox counter for the sync badge
 7. account mode -> watchSession(): confirm Firebase user, load profile/admin flag, then
                    dynamic import cloudSync.startCloudSync(uid)
    otherwise    -> startAutoSync() (Hub sync, only acts if a connection is configured)
 8. startReminders(); autoDailyBackup(); registerSW({ immediate: true })

Switching account (enterAccount, leaveAccount, chooseGuest) writes localStorage and reloads the page, so the correct database is selected before anything renders. If the Firebase session ends or belongs to another user, watchSession clears mego.activeUid and reloads.

5. Data flows

5.1 Local write path (both modes)

Every repository write in src/lib/repo.ts stores the record in its Dexie table and adds an item {table, key, op: 'upsert'|'delete', payload, at} to the outbox table, then notifies onLocalChange listeners. The sync engine of the current mode drains the outbox.

5.2 Guest / owner device — Google Sheet Hub

UI -> repo.ts -> Dexie table + outbox
                     |
          startAutoSync(): debounce 2.5 s after a change, 0.5 s on "online"/visible, every 60 s
                     v
pushNow(): assertHub(ping) -> batches of 300 outbox items -> coalesce ->
           POST {action:"push", changes, clientSchema, token}  -->  Code.gs push_()
                                                                   - validates, timestamp check
                                                                   - writes structured tabs
                                                                   - soft delete -> Deleted_Records
           <-- {applied, conflicts[], dataVersion}
           conflicts > 0 -> pullAll() (newer sheet copies win)

Food values are owned by the Hub's Food_Database tab; foods are imported with pullFoodsFromSheet(). Details: MEGO_Google_Sheets_Integration_and_Sync.

5.3 Signed-in account — Firestore

UI -> repo.ts -> Dexie (mego-u-<uid>) + outbox
                     |
     startCloudSync(): debounce 1.5 s after a change, 0.3 s on "online"
                     v

             permission-denied -> counted as conflict (server holds a newer copy, or account suspended)

Firestore --onSnapshot(updatedAt > last seen)--> applyRemote(): newer remote copy replaces local

Details: MEGO_Firebase_Integration.

5.4 AI meal scanner

src/lib/mealScanner.ts chooses the route by mode: in account mode it POSTs {action: "analyzeMeal", idToken, image, foods, lang, note} to aiBackendUrl from firebase-config.json; on guest/owner devices it uses the configured Hub backend with the app token. Both reach the same Apps Script function analyzeMeal_(), which calls Gemini with the key stored only in Script Properties. The scanner never saves automatically. Details: MEGO_Gemini_AI_Integration and MEGO_Backend_Architecture.

5.5 Reference and external food data

  • fooddb/usda.json is fetched by src/lib/refFoods.ts and precached by the service worker; fooddb/usda-extra.json is fetched by src/lib/foodIntel.ts and cached at runtime.
  • Open Food Facts is called directly from the browser: product endpoint /api/v2/product/{code}.json and search endpoint /cgi/search.pl. These calls need a network connection.

6. Offline operation and the service worker

The service worker is generated by vite-plugin-pwa with registerType: 'autoUpdate' and registered in main.tsx with registerSW({ immediate: true }). Configuration from vite.config.ts:

RuleSetting
Precache**/*.{js,css,html,svg,png,woff2} and fooddb/usda.json; maximum file size 3 MB
Navigation fallbackindex.html; denylist /^\/macros\// (Apps Script paths are never served from cache)
fooddb/usda-extra.jsonStaleWhileRevalidate, cache mego-fooddb-extra
food-img/*.webpCacheFirst, cache mego-food-img, max 200 entries, 1 year
food-img/manifest.jsonStaleWhileRevalidate, cache mego-food-img-manifest
Google Fonts CSS / filesStaleWhileRevalidate (google-fonts-css) / CacheFirst (google-fonts, 20 entries, 1 year)

Offline behaviour: all reads and writes go to IndexedDB; outbox items wait until the browser reports online. Both sync engines set the status offline when navigator.onLine is false. The Hub engine retries failures with exponential backoff (5 s, 10 s, 20 s … capped at 5 minutes) except for permanent errors (unauthorized, WRONG_SPREADSHEET, HUB_IS_XLSX). Firestore listeners resume automatically when the connection returns. Barcode lookup, Open Food Facts search and the AI scanner require a network.

7. Free-tier limits and constraints

  • No billing account is used. Firebase Spark and the Gemini free tier stop serving when their daily quotas are reached; the app shows an error and does not fall back to a paid service.
  • Apps Script runs every request as the owner and serialises Hub writes with LockService (wait up to 25 s).
  • AI limits in Code.gs: global daily cap AI_DAILY_LIMIT (default 40 when the property is unset), per-user cap for public accounts AI_USER_DAILY_LIMIT (default 10). setCloudConfig can set them within 1–1500 and 1–50.
  • Firestore records are limited by the rules to a data string under 300,000 characters; Hub push requests to 500 changes and 45,000 characters per payload.
  • Google Sheets was rejected as the multi-user database (no row-level security; every request runs as the owner) — it remains the owner's personal Hub (docs/ARCHITECTURE.md).
