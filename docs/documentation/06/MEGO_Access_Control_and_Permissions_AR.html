الغرض والنطاق

تشرح هذه الوثيقة، قاعدةً قاعدة، قواعد أمان Firestore في الملف firebase/firestore.rules — وهي الآلية المركزية للتحكم في الوصول في MEGO — وتلخّص الصلاحيات التي تفرضها خلفية Apps Script والعميل. وتتضمن مصفوفة صلاحيات كاملة، والاختبار الذي يغطي كل قاعدة، والثغرات المعروفة في القواعد، وإجراء تعديلها بأمان.

1. المبادئ

  • الرفض افتراضيًا: أي مسار لا تطابقه قاعدة يُرفض (سلوك Firestore).
  • الإنفاذ على الخادم: تقيّم Google القواعد في كل طلب، ولا يستطيع التطبيق تجاوزها.
  • للمالك فقط وللنشط فقط: لا يصل إلى البيانات الخاصة إلا صاحبها، وفقط ما دامت حالة ملفه status == 'active'.
  • أقل صلاحية للمشرفين: يدير المشرفون حالة الحسابات والأطعمة المشتركة، لكن لا يقرؤون السجلات الخاصة.
  • تحديثات أحادية الاتجاه: لا يمكن لنسخة أقدم أن تحل محل نسخة أحدث.

ملاحظة: تنطبق القواعد على طلبات مكتبة العميل أو REST المرسلة برموز المستخدمين. أما بيانات اعتماد Google Cloud الخاصة بمالك المشروع (وحدة التحكم وسكربت الإعداد) فلا تقيّدها هذه القواعد.

2. النص الكامل للقواعد

النسخة المنشورة كما في المستودع (rules_version = '2'):

rules_version = '2';
// MEGO — Firestore security rules (enforced by Google's servers on every request).
//  * users/{uid}/**  : private data. Only the owner, only while the account is active. Admins have NO access.
//                      An older copy can never overwrite a newer one (updatedAt must not go back).
//  * profiles/{uid}  : account card (name, email, status, country, lastActiveAt). Owner reads/creates/updates a
//                      fixed set of fields; admins read all and may change ONLY the status.
//  * admins/{uid}    : admin list. Readable by that user only. Written only from the Firebase console / setup script.
//  * foods/{id}      : shared verified food database. Any signed-in active user reads; only admins write.
//  * foodSubmissions : users propose foods; owner and admins read; admins review.
//  * errorReports    : users may create small error reports (no personal data); only admins read.
service cloud.firestore {
  match /databases/{database}/documents {
    function signedIn() { return request.auth != null; }
    function isAdmin() { return signedIn() && exists(/databases/$(database)/documents/admins/$(request.auth.uid)); }
    function profile(uid) { return get(/databases/$(database)/documents/profiles/$(uid)); }
    function isActive() {
      return signedIn() && exists(/databases/$(database)/documents/profiles/$(request.auth.uid))
        && profile(request.auth.uid).data.status == 'active';
    }
    function isOwner(uid) { return signedIn() && request.auth.uid == uid; }

    match /users/{uid}/{table}/{key} {
      allow read: if isOwner(uid) && isActive();
      allow create: if isOwner(uid) && isActive() && validRecord();
      allow update: if isOwner(uid) && isActive() && validRecord()
        && request.resource.data.updatedAt >= resource.data.updatedAt;
      allow delete: if isOwner(uid) && isActive();
      function validRecord() {
        return request.resource.data.keys().hasOnly(['data', 'updatedAt', 'deleted'])
          && request.resource.data.updatedAt is int
          && request.resource.data.data is string && request.resource.data.data.size() < 300000
          && (!('deleted' in request.resource.data) || request.resource.data.deleted is bool)
          && table in ['entries', 'body', 'days', 'recipes', 'templates', 'plans', 'plannedDays', 'fasts', 'kv', 'settings', 'foodChanges', 'foods'];
      }
    }

    match /profiles/{uid} {
      allow read: if isOwner(uid) || isAdmin();
      allow create: if isOwner(uid)
        && request.resource.data.keys().hasOnly(['displayName', 'email', 'status', 'country', 'ageConfirmed', 'createdAt', 'lastActiveAt'])
        && request.resource.data.status == 'active' && request.resource.data.ageConfirmed == true
        && request.resource.data.email == request.auth.token.email;
      allow update: if (isOwner(uid) && profile(uid).data.status == 'active'
          && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['displayName', 'country', 'lastActiveAt']))
        || (isAdmin() && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['status'])
          && request.resource.data.status in ['active', 'suspended']);
      allow delete: if isOwner(uid);
    }

    match /admins/{uid} {
      allow read: if isOwner(uid);
      allow write: if false;
    }

    match /foods/{id} {
      allow read: if isActive();
      allow write: if isAdmin();
    }

    match /foodSubmissions/{id} {
      allow read: if isAdmin() || (isActive() && resource.data.ownerUid == request.auth.uid);
      allow create: if isActive() && request.resource.data.ownerUid == request.auth.uid && request.resource.data.status == 'pending';
      allow update: if isAdmin();
      allow delete: if isAdmin() || (isActive() && resource.data.ownerUid == request.auth.uid && resource.data.status == 'pending');
    }

    match /errorReports/{id} {
      allow create: if signedIn() && request.resource.data.keys().hasOnly(['at', 'kind', 'message', 'app'])
        && request.resource.data.message is string && request.resource.data.message.size() < 500;
      allow read, delete: if isAdmin();
    }
  }
}

3. الدوال المساعدة

الدالةالمعنىملاحظة التكلفة
signedIn()يحمل الطلب رمز هوية Firebase صالحًا—
isOwner(uid)مسجّل الدخول، وuid في الرمز يساوي uid في المسار—
isAdmin()يوجد مستند admins/{token uid}عملية بحث واحدة عن مستند
profile(uid)يقرأ profiles/{uid}عملية بحث واحدة عن مستند
isActive()مسجّل، ويوجد ملفه الشخصي، وحالته 'active'عمليات بحث عن ملف المتصل

عمليات البحث التي تجريها القواعد تُحتسب قراءاتٍ في Firestore، وعلى خطة Spark تدخل ضمن حصة القراءة اليومية.

4. البيانات الخاصة: users/{uid}/{table}/{key}

العمليةالشرط
القراءة (get، list)isOwner(uid) && isActive()
الإنشاءالمالك، نشط، validRecord()
التحديثالمالك، نشط، validRecord()، وrequest.resource.data.updatedAt >= resource.data.updatedAt
الحذفالمالك، نشط

تشترط validRecord():

  • المفاتيح data وupdatedAt وdeleted فقط؛
  • أن يكون updatedAt عددًا صحيحًا؛
  • أن يكون data نصًا أقصر من 300,000 حرف (يُخزَّن السجل نص JSON)؛
  • أن يكون deleted قيمة منطقية إن وُجد؛
  • أن يكون table واحدًا من 12 اسمًا: entries, body, days, recipes, templates, plans, plannedDays, fasts, kv, settings, foodChanges, foods.

كيف يستخدمها التطبيق: يكتب src/lib/cloudSync.ts كل تغيير محلي عبر setDoc. ويُكتب الحذف «شاهدَ حذف» (tombstone) بالشكل {data: '{}', updatedAt, deleted: true} (وهو تحديث كي تعلم به الأجهزة الأخرى)؛ ولا يُستخدم الحذف الفعلي delete إلا عند حذف الحساب. ويُحتسب الرد permission-denied تعارضًا: الخادم يحمل نسخة أحدث، أو الحساب موقوف.

مثال: الجهاز A (غير متصل) يعدّل الإدخال e1 في الوقت 100، والجهاز B يعدّله في الوقت 200 ويتزامن أولًا. عند عودة A للاتصال تُرفض كتابته ذات updatedAt = 100، ثم يستقبل نسخة B عبر المستمع الحي.

5. الملفات الشخصية: profiles/{uid}

العمليةمنالشرط
القراءةالمالك أو المشرفيستطيع المالك قراءة ملفه حتى وهو موقوف (لازم لشاشة الإيقاف). ولا يستطيع المستخدمون العاديون سرد الملفات.
الإنشاءالمالكالمفاتيح فقط displayName, email, status, country, ageConfirmed, createdAt, lastActiveAt؛ وstatus == 'active'؛ وageConfirmed == true؛ وemail == request.auth.token.email
التحديثالمالكملفه نشط حاليًا، ولا يتغير إلا displayName وcountry وlastActiveAt
التحديثالمشرفلا يتغير إلا status، وإلى 'active' أو 'suspended' فقط
الحذفالمالكدائمًا (حتى وهو موقوف)

النتيجة: لا يستطيع المستخدم تغيير بريده أو حالته ولا إعادة تفعيل نفسه، ولا يستطيع المشرف إعادة تسمية المستخدمين أو ضبط أي حالة غير نشط/موقوف.

6. المشرفون: admins/{uid}

  • القراءة: لصاحب uid فقط (يستخدمها التطبيق لاكتشاف دور المشرف)؛
  • الكتابة: false للجميع — لا يُنشأ إلا ببيانات اعتماد المالك (سكربت الإعداد --cloud أو وحدة تحكم Firebase).

8. تقارير الأخطاء: errorReports/{id}

  • الإنشاء: أي مستخدم مسجّل؛ المفاتيح فقط at, kind, message, app؛ وmessage نص أقصر من 500 حرف؛
  • القراءة والحذف: المشرفون؛ والتحديث: لا أحد.

12. ثغرات معروفة في القواعد

  • تحديثات المالك لملفه لا تتحقق من نوع displayName أو country أو طولهما (يقص التطبيق الاسم إلى 40 حرفًا). ولأن country قابلة للتعديل ويصرّح بها المستخدم، فإن قيد المنطقة في الذكاء الاصطناعي يعتمد على صدق المستخدم.
  • إنشاء foodSubmissions يفحص ownerUid وstatus فقط، لا حقول الطعام.
  • يمكن لأي مستخدم مسجّل، بمن فيهم الموقوفون، إنشاء errorReports؛ ولا يُحدّ إلا طول الرسالة.
  • لا يستطيع المستخدم الموقوف حذف سجلاته الخاصة (الحذف يتطلب isActive())، بل ملفه الشخصي فقط.
  • لا يُفحص email_verified في أي مكان.

هذه البنود متابَعة في MEGO_Security_Audit_and_Known_Risks.

13. تعديل القواعد

  1. عدّل firebase/firestore.rules في فرع مستقل.
  2. أضف الاختبارات أو حدّثها في tests-rules/ وشغّل npm run test:rules (المحاكيات) — ويجب أن تنجح كلها.
  3. انشر ببيانات اعتماد المالك: node scripts/laptop-setup.mjs --cloud <e-mail> (ينفّذ firebase deploy --only firestore:rules,firestore:indexes) أو عبر Firebase CLI مباشرة.
  4. شغّل node scripts/laptop-setup.mjs --verify (التحقق المباشر) وتأكد من نجاح كل الفحوص.
  5. التراجع: أعد نشر النسخة السابقة من الملف من git.
