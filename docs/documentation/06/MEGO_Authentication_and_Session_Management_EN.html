Purpose and scope

This document describes, exactly as implemented in the code, how MEGO authenticates people and keeps their sessions: registration and its validation, password rules, sign-in, persistent sessions, sign-out, password reset, re-authentication before account deletion, suspended accounts, and the separate secret token that protects the owner's Google Sheets Hub backend (Apps Script), including where it is stored and how to rotate it. It covers two independent mechanisms:

  • Public accounts — Firebase Authentication (Email/Password) on the free Spark plan, project mego-473920. Code: src/lib/firebase.ts, src/lib/account.ts, src/pages/Account.tsx.
  • Owner Hub connection — a 256-bit shared secret (APP_TOKEN) checked by apps-script/Code.gs for guest/owner devices that sync with the Google Sheet «MEGO Nutrition Hub». Code: src/lib/sync.ts, apps-script/Code.gs.

No secret value (keys, tokens, URLs of the web app, connection codes, passwords) appears in this document; secrets are referred to by name only.

1. Modes and overview

At start-up bootAccount() (src/lib/account.ts) loads /firebase-config.json. If the file is missing the app runs in guest mode only. If it is present, the app has three modes:

Because every account uses its own local IndexedDB database, two people who share a phone do not see each other's data inside the app.

2. Registration and validation

Registration is a 3-step flow (RegisterFlow in src/pages/Account.tsx).

2.1 Step 1 — identity (client-side checks)

FieldRule enforced in the app
Display nameNot empty; trimmed and cut to 40 characters when saved
E-mailMust match the pattern .+@.+\..+; Firebase validates it again (auth/invalid-email)
PasswordAt least 8 characters, at least one digit and one Latin letter (see section 3)
CountryChosen from a list; "Other" is stored as ZZ. Countries where Google's free-tier Gemini terms do not allow the scanner show a notice
18+ confirmationRequired checkbox; register() also throws AGE_REQUIRED if not confirmed
Privacy policy and termsRequired checkbox (links to the draft pages)

2.2 Steps 2 and 3 — body data and targets

Step 2 requires age ≥ 18, height > 100 cm and weight > 30 kg before continuing. Step 3 shows the recommended targets, which the user may edit. These answers are kept temporarily in localStorage under mego.pendingSetup.<uid> and applied once to the new account's settings at the next start, then removed.

2.3 What happens on "Finish"

  1. createUserWithEmailAndPassword creates the Firebase user (Firebase enforces its own password policy and e-mail uniqueness).
  2. The display name is set on the Firebase user.
  3. A profile document profiles/{uid} is written: displayName, email, status active, country, ageConfirmed, createdAt, lastActiveAt. The Firestore rules accept the creation only if the fields are exactly these, status is active, ageConfirmed is true and the e-mail equals the e-mail in the sign-in token.
  4. A verification e-mail is requested (sendEmailVerification); failures are ignored. E-mail verification is not enforced: neither the app nor the Firestore rules check email_verified (see MEGO_Security_Audit_and_Known_Risks).
  5. Optionally, the device's guest data is copied once into the new account (the guest database itself is left untouched).
  6. enterAccount() stores mego.activeUid and reloads the app.

3. Password rules and error messages

The app's own rule (hint key reg_pwRule): "At least 8 characters, including a letter and a number." The "Next" button stays disabled until the rule is met. Firebase Authentication applies its own server-side policy as well; the project's Firebase password-policy settings were not inspected (Not verified). Passwords are handled only by Firebase Authentication and are never stored by MEGO.

Firebase error codes are mapped to translated messages (authErr_* keys in src/lib/i18n2.ts); unknown codes show authErr_generic.

4. Sign-in and persistent sessions

  1. The user enters e-mail and password (LoginForm); signInWithEmailAndPassword is called.
  2. If the device holds guest diary entries, the user may tick "import guest data" (copied once).
  3. enterAccount(uid) writes mego.activeUid, removes mego.guest and reloads.
  4. On every start, watchSession() waits for Firebase's onAuthStateChanged. If no user is returned, or a different uid, the app removes mego.activeUid and reloads to the welcome screen (session expired or signed out elsewhere).
  5. If the user matches, the profile and admin flag (admins/{uid} exists) are read, lastActiveAt is refreshed, and Firestore sync starts — unless the account is suspended.

Persistence: the code does not call setPersistence, so the Firebase Web SDK default applies (the session is kept in the browser's storage until sign-out). The app does not implement an idle timeout. Firebase ID tokens are short-lived and refreshed automatically by the SDK.

5. Sign-out

"Sign out" in the account card (and on the suspended screen) calls Firebase signOut(), then leaveAccount(), which removes mego.activeUid and reloads.

ItemAfter sign-out
Firebase session on this browserCleared (signOut)
mego.activeUidRemoved
Local database mego-u-<uid>Kept on the device (not encrypted, not deleted). It is reused at the next sign-in of the same account; the app does not show it to other accounts, but anyone with access to the browser's storage could read it.
localStorage sync cursors mego.cloud.<uid>.<table>Kept (timestamps only)
Guest database mego-nutritionUnchanged

Recommendation: on shared devices, users who want no local copy left should use "Delete account" or clear the site data in the browser. A "remove this device's copy on sign-out" option does not exist yet.

6. Password reset (no account enumeration)

  1. "Forgot password?" opens ResetForm; the user enters an e-mail.
  2. sendPasswordResetEmail is called.
  3. On success the app always shows the same text (auth_resetSent): "If an account exists for this email, a reset link has been sent. Check your inbox and spam folder." The code comment states the intent: the same message whether or not the address exists.
  4. On any error only authErr_generic is shown — no code-specific text.

Whether Firebase itself returns an error for unknown addresses depends on the project's e-mail-enumeration-protection setting, which was not inspected (Not verified). Live verification confirmed only that a reset request for an existing account was accepted (HTTP 200); delivery to a real inbox was not checked.

7. Re-authentication before account deletion

Deletion (Settings → Account → "Delete account") requires the current password. deleteMyAccount() first calls reauthenticateWithCredential; nothing is deleted if the password is wrong. Only then are the cloud records, the profile and the Firebase login removed, followed by the local account database. Full details are in MEGO_Data_Retention_and_Deletion.

8. Suspended accounts

  • An administrator can set profiles/{uid}.status to suspended (rules allow admins to change only the status field).
  • Server side: every rule for private data (users/{uid}/**), shared foods and food submissions requires isActive(), so a suspended account can neither read nor write its records — enforced by Google's servers. The Apps Script AI proxy also refuses non-active profiles.
  • Client side: watchSession() sets suspended, sync is not started, and the app shows the "Account suspended" screen: "This account has been suspended by the administrator. Your data is kept and nothing has been deleted." The only action offered is sign-out.
  • Consequence: a suspended user cannot delete their own records through the app, because the delete rule also requires an active account. Reactivation by an administrator restores access.

9. Apps Script token: handling, storage and rotation

The owner Hub backend is an Apps Script web app deployed with "Execute as: owner, access: anyone" (a PWA cannot send Google login cookies). Every request except two must carry the secret APP_TOKEN.

AspectImplementation (verified in code)
Generationsetup() creates it once from two UUIDs without dashes (64 hex characters, 256 bits) and keeps an existing token
Server storageScript Properties of the Apps Script project, key APP_TOKEN — never in the repository or the app's public code
CheckdoPost rejects any request whose token differs (unauthorized). Exceptions: bootstrap (one-time, checked against a SHA-256 hash of a one-time secret, disabled after use by BOOTSTRAP_DONE) and the public-account AI actions analyzeMeal/aiStats sent with a Firebase idToken, which is verified by Google Identity Toolkit
Device storageIn the local IndexedDB settings record (settings.sync.token) of the device that connected
Never exportedBackups (snapshot()) strip settings.sync; Hub upload strips it; Firestore sync strips it; restores keep the local value
Laptop copyscripts/laptop-setup.mjs keeps the URL and token in ~/.mego-backend/ (outside the repository, file mode 600)
TransportHTTPS; delivered to the phone as a connection code (MEGO1|<url>|<token>) or a QR deep link; the app removes the code from the address bar after connecting
Exposure surfacesThe Settings token field is a plain text field; the connection code is printed in the Apps Script log and in the terminal of the laptop setup

The Gemini API key is a separate secret stored only in Script Properties (GEMINI_API_KEY), set through the token-protected action setAiKey; it is never sent to the phone.

10. Credential-rotation procedure

During setup, the owner's Gemini key and the backend connection link were shown in a chat. Rotating both is recommended.

10.1 Rotate the Apps Script token

  1. Open the Apps Script project (script.google.com) under the owner's account.
  2. Run the function rotateToken() — it deletes APP_TOKEN and calls setup(), which creates and logs a new token.
  3. Run installMego() again (safe to re-run) to print the new connection code, or build it from the logged token.
  4. On each owner device: Settings → Hub connection → paste the new code → test connection. Old tokens are refused immediately.
  5. Update ~/.mego-backend/ on the laptop (the stored token is now stale, so laptop-setup.mjs --test will report "unauthorized" until it is updated). The exact update step for that file is Not verified.
  6. Delete any chat messages, notes or screenshots containing the old code.

Optional: creating a new web-app deployment changes the URL as well; the old deployment can then be archived in Apps Script.

10.2 Rotate the Gemini API key

  1. In Google AI Studio create a new API key.
  2. Store it with the owner app (Settings → AI scanner key, which calls setAiKey) or with node scripts/laptop-setup.mjs --ai-key-from-clipboard.
  3. Test one scan, then delete the old key in Google AI Studio.

10.3 Firebase passwords

Users change a password through "Forgot password?". There is no in-app "change password" screen.
