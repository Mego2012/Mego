Purpose and scope

This document states how long each kind of MEGO data is kept, how single records are deleted, and exactly what the in-app account deletion does — traced through the code path in src/pages/Account.tsx (deleteMyAccount). It also lists the data that deletion does not remove. The retention period for inactive accounts is a business and legal decision that has not been taken (item 7 in docs/LEGAL-REVIEW.md).

2. Deleting single records

  • Diary entries, measurements, recipes, saved meals, plans, planned days, cardio/workout items: deleted from the device database at once (repo.ts, e.g. deleteEntry) and queued as a delete in the outbox.
  • Account mode: the outbox writes a tombstone {data: '{}', updatedAt, deleted: true}. Other devices delete their copy when they receive it. The record content is no longer in the cloud.
  • Owner Hub: the row is copied to Deleted_Records and then removed from its tab.
  • Copies in local backups and downloaded backup files are not changed.
  • Progress photos: deleted from the device (db.photos.delete); they were never uploaded.

3. Account deletion: user steps

  1. Settings → Account card → Delete account.
  2. The warning appears: "This permanently deletes your account, your cloud data and this device's copy of it. Export your data first if you want to keep it."
  3. (Recommended) cancel, tap Export my data, then return.
  4. Enter the current password and confirm.
  5. After success the app reloads into the welcome screen.

6. Failure behaviour and edge cases

  • Not atomic: if the connection drops after step 2 started, some records may already be deleted while the account still exists. Running the deletion again completes it (deleting is idempotent). This was not specifically tested.
  • Suspended accounts: the suspended screen offers only sign-out, and the rules require an active account to delete private records. A suspended user therefore cannot delete their data in the app; an administrator must reactivate the account first, or the owner deletes it in the Firebase console.
  • Recent sign-in: handled by the re-authentication with the password.
  • Offline: the Firestore calls fail and the error is shown; nothing is reported as deleted.
  • Other devices that were signed in to the deleted account: their Firebase session ends; their local database mego-u-<uid> stays on those devices until site data is cleared (Not verified on a real second device).

7. Administrator and owner actions

  • Administrators cannot delete user accounts or private data in the app; they can only suspend/reactivate, delete error reports and manage submissions.
  • For a deletion request that the user cannot perform (e.g. lost password, suspended account), the owner can use the Firebase console: delete users/{uid} sub-collections, profiles/{uid}, the user's foodSubmissions, and the user in Authentication. Record the request without copying personal data into tickets.
  • Lost password: the user first uses "Forgot password?", then deletes the account normally.

8. Open decisions and recommendations

  • Decide a retention period for inactive accounts (legal item 7) and, if adopted, implement a scheduled clean-up.
  • Extend deleteMyAccount to delete the user's foodSubmissions and the mego.cloud2.<uid>.* markers.
  • Allow suspended users to delete their data, or document an owner-assisted process in the privacy policy.
  • Set the time trigger for cleanupAiCounters in Apps Script.
  • Define a retention period for error reports.
