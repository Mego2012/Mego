Purpose and scope

This document gives the complete security picture of MEGO: the components and trust boundaries, the security controls at each layer, where secrets live, how data moves between components, and which threats each control addresses. Detailed rules, data-protection measures and open risks are in the related documents listed above.

2. Security layers and controls

2.1 Transport

  • All endpoints are HTTPS: GitHub Pages, Firebase, Apps Script (script.google.com), Gemini, Open Food Facts, Google Fonts. The connection-code parser accepts only https://script.google.com/… URLs (parseConnectionCode in src/lib/sync.ts).

2.2 Identity

  • Firebase Email/Password; passwords are processed only by Firebase and never stored by MEGO. App-side password rule: ≥ 8 characters with a letter and a digit.
  • Password reset shows the same message whether or not an address exists.
  • Deletion requires re-entering the password (re-authentication).

2.3 Authorization (server side)

  • Firestore rules: owner-only access to users/{uid}/** while the profile is active; record shape and size validated; older copies cannot overwrite newer ones; admins see account cards and counts only; nobody can create an admin from the app. Details: MEGO_Access_Control_and_Permissions.
  • Apps Script: every Hub action requires APP_TOKEN; AI actions for public accounts require a Google-verified Firebase ID token and an active profile read with that same token.

2.4 Input validation

  • Firestore: only the fields data (string < 300,000 characters), updatedAt (integer) and optional deleted (boolean); only 12 known table names.
  • Apps Script validChange_: known tables, key ≤ 200 characters, payload ≤ 45,000 characters, ≤ 500 changes per request, diary dates YYYY-MM-DD with numeric kcal, weight 20–400 kg.
  • AI: image must be base64 of JPEG/PNG/WebP within a size limit; user note cut to 300 characters; food list capped.
  • Backup restore: file format and every record's key and nutrition values are checked before anything is written; restore merges (newer wins) and never deletes.

2.5 Client-side data isolation

  • Each account has its own IndexedDB database (mego-u-<uid>); guest data stays in mego-nutrition. Switching accounts reloads the app before anything renders.
  • Local data is not encrypted by the app; it is protected only by the device and browser.

2.6 Privacy-by-design controls

  • Meal photos are re-encoded through a canvas before upload, which removes EXIF metadata (location, device, time); photos are not stored by MEGO.
  • Progress photos stay on the device only (not synced, not in backup files).
  • Error reports contain an error kind and message only (≤ 500 characters), no diary content.
  • No analytics and no advertising code.

2.7 Abuse limits

  • AI scanner: per-user daily limit (Script Property AI_USER_DAILY_LIMIT, default 10) and global daily limit (AI_DAILY_LIMIT, default 40 in code; the setup script sets 200); failed analyses do not consume the allowance.
  • Accounts in countries where the Gemini free-tier terms do not allow the service (EU/EEA, UK, Switzerland list in AI_RESTRICTED) are refused the scanner.
  • Firebase Authentication applies its own throttling (too-many-requests).

6. Availability and free-tier limits

All services run on free tiers without billing (Firebase Spark, Apps Script, Gemini free tier, GitHub Pages). When a quota is reached the service stops until the quota resets; it cannot generate charges. Limits recorded in docs/ARCHITECTURE.md (subject to change by Google): Firebase Authentication 3,000 daily active users, 150 password-reset e-mails/day, 100 sign-ups/hour per IP; Firestore 1 GiB stored, 50,000 reads, 20,000 writes and 20,000 deletes per day. Gemini free tier may return overload (503) or quota (429) errors; the backend switches between free models and the client retries temporary errors. Data on the device remains usable offline.

7. Build and deployment security

  • GitHub Actions workflow .github/workflows/deploy.yml: npm ci (lock-file install), npm test must pass before npm run build; workflow permissions are limited to contents: read, pages: write, id-token: write.
  • Firestore rules are deployed from firebase/firestore.rules by scripts/laptop-setup.mjs (firebase deploy --only firestore:rules,firestore:indexes).
  • Apps Script updates: node scripts/laptop-setup.mjs --update-backend uploads Code.gs to the same deployment.
  • The repository ignores tests/private/; a secret scan on 7 Nov 2026 found no real key or token in the repository. Two old commits still expose a private CSV (see MEGO_Security_Audit_and_Known_Risks).
