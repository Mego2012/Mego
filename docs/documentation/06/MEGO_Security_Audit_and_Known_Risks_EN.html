Purpose and scope

This document records the result of an internal security review of the MEGO code and configuration as of 10 November 2026 and keeps a register of known risks with severity, status and the action required. It is a code-and-configuration review by the documentation author, not an independent penetration test. Severity is a qualitative judgement (High / Medium / Low) based on likelihood and impact for a small free-tier deployment.

1. Audit method and scope

  • Reviewed: firebase/firestore.rules, src/lib/firebase.ts, account.ts, cloudSync.ts, sync.ts, backup.ts, localBackup.ts, mealScanner.ts, src/pages/Account.tsx, apps-script/Code.gs and appsscript.json, .github/workflows/deploy.yml, index.html, existing reports in docs/.
  • Evidence of behaviour: rules tests (14, emulators), multi-user browser checks (8, emulators), live verification against production (14/14), laptop-setup live tests, storage-loss emulator scenario.
  • Not in scope / not performed: penetration test, dependency vulnerability scan (npm audit results not reviewed — Not verified), Firebase console settings, Google Cloud IAM members.

2. Summary

The core access-control design is sound: private data is isolated per user by server-side rules, administrators have no access to private records, nobody can promote themselves, and the AI key never reaches the device. The most important open items are operational: two credentials that were exposed in a chat must be rotated, two old public commits still expose a private CSV file, and the free-tier limits cap capacity. Several medium/low hardening items are listed below.

5. Credential rotation procedures

5.1 Gemini API key (R-01)

  1. In Google AI Studio (owner's account) create a new API key. Do not enable billing.
  2. Copy the key to the laptop clipboard and run node scripts/laptop-setup.mjs --ai-key-from-clipboard, or store it from the owner device (Settings → AI scanner key, which calls setAiKey). The backend checks the key with Google before saving it to Script Properties (GEMINI_API_KEY).
  3. Test one meal scan.
  4. Delete the old key in Google AI Studio.
  5. Never paste keys into chats, tickets or documents.

5.2 Backend token APP_TOKEN (R-02)

  1. Open the Apps Script project under the owner's account and run rotateToken() (deletes APP_TOKEN and creates a new 256-bit token via setup(); the new value is written to the execution log).
  2. Obtain the new connection code (run installMego() again — safe to re-run — or assemble it from the log). Treat the log as secret.
  3. On each owner device: Settings → Hub connection → paste the new code → test. The old token is refused immediately.
  4. Update the laptop copy in ~/.mego-backend/ (exact update step Not verified; --test reports "unauthorized" while it is stale).
  5. Optional: create a new web-app deployment to change the URL and archive the old deployment.
  6. Delete chat messages, screenshots or notes containing the old link.

Public accounts are not affected by either rotation: they authenticate to the AI proxy with their own Firebase ID token.

6. Old public commits exposing a CSV (R-03)

  • File: tests/fixtures/foods-160.csv (13,451 bytes) — the owner's private food table.
  • Checked 7 Nov 2026: still downloadable (HTTP 200) through commits a7b5bbb… and 3fb3c82…; not present in the current branch (history rewritten and force-pushed); commits 2523513 and 5bc5b6b return 404.
  • Reason it persists: GitHub keeps unreferenced objects; old Actions runs #2 and #3 reference those commits.
  • Action: the owner sends the prepared text in docs/GITHUB-SUPPORT-REQUEST.md while signed in as the repository owner; optionally deletes Actions runs #2 and #3 first; then re-checks that both URLs return 404.
  • Prevention: tests/private/ is in .gitignore; keep private fixtures there.

8. Positive findings

  • Server-side isolation verified live: other user's data 403, anonymous 403, no self-promotion, regular users cannot list profiles or suspend others.
  • Admins cannot read private records; admin writes to profiles limited to status.
  • Monotonic updatedAt prevents stale overwrites, in Firestore and in the Hub.
  • Gemini key stays server-side; AI proxy reads profile with the user's own token.
  • Sync token removed from backups, exports and cloud copies.
  • Meal photos re-encoded (EXIF removed) and not stored.
  • Password reset gives no account-existence signal in the app.
  • CI runs tests before every deploy; secret scan (7 Nov 2026) found no real secrets in the repository.
