Purpose and scope

This guide explains how the owner's Google Apps Script backend is installed and updated. The backend (apps-script/Code.gs, SCRIPT_VERSION 8) connects the app to the Google Sheet "MEGO Nutrition Hub", and it is the only component that talks to the Gemini API. The automated way is scripts/laptop-setup.mjs; the guide gives click-by-click Windows PowerShell steps for a non-technical owner, the Google screens to approve, what the script checks, and how to update the backend with --update-backend and complete the Hub food list with --hub-complete-foods.

2. Windows: preparing the laptop (once)

  1. Press the Start button, type PowerShell, open Windows PowerShell.
  2. Install Git and Node.js (type each line, press Enter, accept any prompt): 
    winget install --id Git.Git -e
winget install --id OpenJS.NodeJS.LTS -e
  3. Close PowerShell and open it again (so the new programs are found). Check: git --version and node -v must each print a version.
  4. If PowerShell says "running scripts is disabled on this system", run once: 
    Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
  5. Download the project into your user folder: 
    cd $HOME
git clone -b claude/nutrition-tracking-app-989rku https://github.com/Mego2012/Mego.git
cd Mego

Important: while the script runs, do not click inside the PowerShell window. With QuickEdit mode a click pauses the program and it looks frozen; press Enter or Esc to continue.

3. Windows: running the setup

cd $HOME\Mego
node scripts/laptop-setup.mjs

The script prints each step with ▶ and each check with ✅ or ❌. When it needs you, it shows "👉" with an instruction and waits for Enter. Keep your Google account open in the browser. Safe to run again: an existing project, deployment and token are reused.

5. What the script does and checks

  1. Upload: copies Code.gs and appsscript.json to the private project. On the first install it writes into your private copy only the SHA-256 hash of a random one-time secret (BOOTSTRAP_HASH); the secret never leaves the laptop.
  2. Deploy: creates the web app deployment (later runs update the same deployment id).
  3. One-time install (bootstrap): runs installMego() — Drive backup, Excel → native Google Sheet conversion, verification of all foods, migration to structured tabs. It then disables itself (BOOTSTRAP_DONE) and returns the app token, which is stored only in ~/.mego-backend/state.json.
  4. Live tests (10): token accepted; Hub identity is the original Excel file; Hub is native and writable; installMego verification; wrong token refused; Food_Database has every food with readable values; write phone → Hub (test record); read Hub → phone; an older copy never overwrites a newer one; test record soft-deleted into Deleted_Records.
  5. Gemini (optional): stores a free key and runs one real photo analysis.
  6. Connect the app: prints a QR code and a link that connects the app on the phone. Keep it private — it contains the token. Reprint with node scripts/laptop-setup.mjs --test.
  7. Report: written to ~/.mego-backend/report-<time>.md.

Live result of the owner's run (7 Nov 2026): all checks ✅; Hub "MEGO Nutrition Hub" with 160 foods and 0 numeric problems; backup "BACKUP MEGO Nutrition Hub — before migrateHub — 2026-11-07 1425".

6. Updating the backend (--update-backend)

When a new Code.gs is released (for example SCRIPT_VERSION 7 with the improved AI error handling, or SCRIPT_VERSION 8 with fillFoodNames), run in PowerShell:

cd $HOME\Mego
git pull
node scripts/laptop-setup.mjs --update-backend

What happens: the latest Code.gs is uploaded and deployed to the same deployment (same web-app URL, same token, Hub data untouched), then the AI diagnostic (aiDiag) sends a tiny text-only request to every free model and prints for each one ✅/❌, the HTTP code and Google's message, plus the backend version and configured model. The live tests are not run in this mode; run node scripts/laptop-setup.mjs --test afterwards if you want them.

7. Other options and maintenance

Command / functionUse
--hub-complete-foodsImplies --update-backend (uploads and deploys the latest Code.gs to the same deployment), then needs backend version 8 or newer and the structured Food_Database. It ADDS only: every recipe-library ingredient missing from the Hub (hand-checked USDA values from public/fooddb/library-recipes.json; an ingredient without a verified reference is listed and never estimated), every library meal as a ready food computed from the Hub's own values (per 100 g of raw ingredients, 1 serving as the portion; a meal is skipped if an ingredient has no usable values), and fills only EMPTY English names (public/fooddb/food-names.json). Existing rows and values are never changed; a daily Drive backup of the Hub is taken first; running it again adds nothing. The AI diagnostic is not run in this mode
--testOnly the live tests against the existing backend (+ Gemini step, + connect link)
--autoNo keyboard prompts; waits by polling every 10 s
--photo meal.jpgUse your own photo for the AI test
rotateToken() (in the editor)Creates a new app token; the app must be connected again. Recommended because the connection link was shown in a chat during setup
cleanupAiCounters()Removes AI usage counters older than 8 days (optional time trigger)
Manual alternativePaste Code.gs and appsscript.json in the editor, Deploy → Manage deployments → Edit → New version (docs/SETUP.md, docs/PHONE-SETUP.md)

Network errors when calling the backend are retried 4 times (3, 6, 9, 12 s) and then Google's real error is shown.
