3. البناء

npm ci
npm run build          # = tsc -b && vite build
BASE_PATH=/Mego/ npm run build   # the production path, as CI builds it
  • يفحص tsc -b الأنواع أولًا؛ وأي خطأ نوع يوقف البناء.
  • يكتب Vite المجلد dist/؛ وتضيف vite-plugin-pwa الملفين sw.js وmanifest.webmanifest (الاسم «MEGO — Nutrition»، وضع مستقل، اتجاه عمودي، وstart_url/scope = المسار الأساسي).
  • الملفات المخزّنة مسبقًا: **/*.{js,css,html,svg,png,woff2} وfooddb/usda.json (حد 3 ميغابايت للملف). صور الأطعمة وusda-extra.json وخطوط Google تُخزَّن أثناء التشغيل. أما استدعاءات Apps Script فلا تُخزَّن أبدًا.
  • تُفصل مكتبتا Recharts/d3 في جزء مستقل باسم charts.

6. إجراء الإصدار خطوة بخطوة

  1. قرّر هل يغيّر الإصدار البيانات المخزنة؛ وإن كان كذلك فغيّر APP_RELEASE (نسخة احتياطية قبل التحديث على كل جهاز).
  2. شغّل الفحوص المناسبة من القسم 5.
  3. حدّث الوثائق (docs/PROGRESS-LOG.md وأعداد الاختبارات ووثائق المنهجية عند الحاجة).
  4. احفظ التغييرات وادفعها إلى claude/nutrition-tracking-app-989rku.
  5. انتظر حتى يصبح تشغيل «Test & deploy to GitHub Pages» أخضر.
  6. نفّذ فحوص الإنتاج (MEGO_Production_Verification_Checklist): مجموعتا المتصفح والتمرير على الموقع الحي، وأداة التحقق الحي.
  7. إذا تغيّر الخادم فأصدره (القسم 7) وشغّل تشخيص الذكاء الاصطناعي.
  8. يتلقى المستخدمون الإصدار الجديد تلقائيًا (عامل الخدمة autoUpdate)؛ وفي الإعدادات ← فحص البيانات (Data check) تُقارن أعداد السجلات بالنسخة الاحتياطية قبل التحديث.

7. إصدار الخادم

git pull
node scripts/laptop-setup.mjs --update-backend

يرفع Code.gs إلى النشر نفسه (الرابط والرمز دون تغيير)، ثم يطبع تشخيص الذكاء الاصطناعي متضمنًا إصدار الخادم. استخدم بدلًا منه --hub-complete-foods إذا كان الإصدار يجب أن يضيف أيضًا أطعمة مكتبة الوصفات إلى الـ Hub (وهو يتضمن --update-backend). ويُبلغ التطبيق عن خادم قديم («unknown action» ← AI_OLD_BACKEND) إذا احتاجت ميزةٌ سكربتًا أحدث.

8. سجلات الإصدار

  • سجل Git (رسائل الإيداع تصف كل إصدار).

  • التقارير الحية على اللابتوب: ~/.mego-backend/report-*.md وlive-verify-*.md (خاصة، خارج المستودع).
