Purpose and scope

This document defines how a MEGO release is built, which version identifiers exist and when they change, the checks that must pass before a release is pushed, and how the release reaches users (static app) and the owner's backend (Apps Script). It covers the frontend PWA, the generated data files and the backend script.

3. The build

npm ci
npm run build          # = tsc -b && vite build
BASE_PATH=/Mego/ npm run build   # the production path, as CI builds it
  • tsc -b type-checks first; any type error stops the build.
  • Vite writes dist/; vite-plugin-pwa adds sw.js and manifest.webmanifest (name "MEGO — Nutrition", standalone, portrait, start_url/scope = base path).
  • Pre-cached files: **/*.{js,css,html,svg,png,woff2} and fooddb/usda.json (cache limit 3 MB per file). Food photos, usda-extra.json and Google Fonts are cached at runtime. Apps Script calls are never cached.
  • Recharts/d3 are split into a separate charts chunk.

6. Release procedure, step by step

  1. Decide whether the release changes stored data; if so, change APP_RELEASE (pre-update backup on every device).
  2. Run the checks of section 5 that apply.
  3. Update docs (docs/PROGRESS-LOG.md, test counts, methodology docs where relevant).
  4. Commit and push to claude/nutrition-tracking-app-989rku.
  5. Wait for the "Test & deploy to GitHub Pages" run to be green.
  6. Run the production checks (MEGO_Production_Verification_Checklist): live e2e and scroll suites, live verifier.
  7. If the backend changed, release it (section 7) and run the AI diagnostic.
  8. Users receive the new version automatically (service worker autoUpdate); Settings → Data check compares record counts with the pre-update backup.

7. Backend release

git pull
node scripts/laptop-setup.mjs --update-backend

Uploads Code.gs to the same deployment (URL and token unchanged), then prints the AI diagnostic including the backend version. Use --hub-complete-foods instead when the release should also add the recipe-library foods to the Hub (it implies --update-backend). The app reports an outdated backend ("unknown action" → AI_OLD_BACKEND) if a feature needs a newer script.

8. Release records

  • Git history (commit messages describe each release).
  • docs/PROGRESS-LOG.md, docs/TEST-REPORT.md, docs/PRODUCTION-STATUS.md.
  • Live reports on the laptop: ~/.mego-backend/report-*.md and live-verify-*.md (private, not in the repository).
