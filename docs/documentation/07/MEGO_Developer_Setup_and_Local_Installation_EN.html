Purpose and scope

This guide explains how to get the MEGO source code onto a computer, install its dependencies, run the app locally, build it, preview the production build and run every automated test suite, including the suites that use the Firebase emulators. It also records practical Windows notes from the owner's real laptop run on 7 November 2026. Cloud setup (Firebase, Apps Script, Gemini) is covered in the related guides.

2. Getting the code

The working branch is claude/nutrition-tracking-app-989rku on https://github.com/Mego2012/Mego:

git clone -b claude/nutrition-tracking-app-989rku https://github.com/Mego2012/Mego.git
cd Mego

3. Installing dependencies

Use npm ci (exact versions from package-lock.json, the same command CI runs):

npm ci

The browser test suites and the live verifier need Playwright, which is deliberately not a project dependency. Install it without changing package.json:

npm install --no-save playwright@1.63.0
npx playwright install chromium

npm install (README.md) also works but may update the lock file; prefer npm ci.

4. Running, building and previewing

CommandWhat it runs (package.json)Result
npm run devviteDevelopment server, http://localhost:5173 (README.md)

npm run buildtsc -b && vite buildProduction bundle in dist/ incl. service worker sw.js and manifest.webmanifest
npm run previewvite preview --port 4173Serves dist/ at http://localhost:4173/

Locally BASE_PATH is not set, so the app is built for /. CI sets BASE_PATH=/Mego/ (see MEGO_Production_Deployment_Guide). To reproduce the production path locally:

BASE_PATH=/Mego/ npm run build

Accounts: the app reads ./firebase-config.json at runtime (src/lib/firebase.ts). If the file is absent the app runs in guest mode only. The repository contains the public production config in public/firebase-config.json, so a local dev server talks to the production Firebase project when you register or sign in — use disposable accounts or the emulators for experiments.

6. Firebase emulators

firebase-tools is a dev dependency, so no global install is needed. firebase.json defines the emulators:

EmulatorPort
Authentication9099
Firestore8080
Emulator UIdisabled

The scripts start and stop the emulators automatically with the demo project demo-mego (no Google account needed):

npx firebase emulators:exec --project demo-mego --only firestore,auth "vitest run --config vitest.rules.config.ts"

To keep them running for manual work: npx firebase emulators:start --project demo-mego --only firestore,auth.

7. Windows notes

7.1 Installing Git and Node.js with winget

winget install --id Git.Git -e
winget install --id OpenJS.NodeJS.LTS -e

7.2 Refreshing PATH

After installing, close the PowerShell window and open a new one so git, node and npm are found. Check with git --version and node -v.

7.3 PowerShell QuickEdit freeze

Clicking inside a PowerShell/console window with QuickEdit mode starts a text selection and pauses the running program; the setup looks frozen. Press Enter or Esc to resume, and avoid clicking in the window while the script runs (or disable QuickEdit in the window's Properties).

7.4 Execution policy

If PowerShell refuses to run npm/npx because "running scripts is disabled on this system", allow local scripts for your user only:

Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

Alternatively call npm.cmd / npx.cmd, or run the commands from Command Prompt.

7.5 npx.cmd spawning (fixed in code)

Node 18.20+/20.12+ refuses to spawn npx.cmd/npm.cmd without a shell (EINVAL). scripts/laptop-setup.mjs therefore starts the npm CLI bundled with Node directly through node.exe (commit 65f86ad).

7.6 Git identity

A fresh Git install has no user name/e-mail. The setup script commits the Firebase config with a neutral identity (MEGO setup, a GitHub noreply address) and then checks that GitHub received it.

8. Local files and private state

  • ~/.mego-backend/ (or MEGO_BACKEND_DIR): private state of the setup script (script id, web-app URL, token), file mode 600, outside the repository. Never commit or share it.
  • Ignored by Git (.gitignore): node_modules, dist, dev-dist, e2e/screens, *.log, tests/private/.
  • Some unit value tests use a private real-food file in tests/private/; without it those tests skip (docs/TEST-REPORT.md).
