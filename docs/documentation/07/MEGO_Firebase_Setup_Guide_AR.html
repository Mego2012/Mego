الغرض والنطاق

يشرح هذا الدليل كيف تُعَدّ المنصة العامة متعددة المستخدمين في MEGO (الحسابات، والبيانات السحابية الخاصة، ودور المسؤول) على خطة Spark المجانية من Firebase (دون حساب فوترة) بأمر واحد: node scripts/laptop-setup.mjs --cloud [admin-email]. ويعرض كل خطوة ينفّذها السكربت، والإجراءات التي لا يستطيع القيام بها إلا المالك، وقيم الإنتاج الناتجة، وكيفية إعادة التشغيل أو التحقق.

1. قبل البدء

  • لابتوب عليه Git وNode.js، والمستودع منسوخ على الفرع claude/nutrition-tracking-app-989rku (انظر MEGO_Developer_Setup_and_Local_Installation).
  • صلاحية الدفع (Push) إلى مستودع GitHub، لأن السكربت يحفظ ملف الإعداد العام ويرفعه.
  • عادةً يُثبَّت خادم Apps Script أولًا (node scripts/laptop-setup.mjs): فمرحلة --cloud تعمل بعد الاختبارات الحية للخادم، وتعرّف الخادم بمشروع Firebase حتى يستطيع المستخدمون المسجلون استخدام الماسح الذكي.
  • لا حاجة لحساب فوترة ولا يُنشأ أي حساب فوترة. تنطبق حدود خطة Spark (الحصص الدقيقة في صفحة أسعار Firebase لدى Google — لم تُنقل هنا).

2. تشغيل الأمر

node scripts/laptop-setup.mjs --cloud                  # platform without an admin yet
node scripts/laptop-setup.mjs --cloud <your e-mail>     # also grants the admin role (account must already exist)

أضف --auto لتجنب أسئلة لوحة المفاتيح (حينها يعيد السكربت الفحص كل 10 ثوانٍ أثناء انتظارك على صفحة Google).

3. ما يفعله السكربت خطوة بخطوة

#الخطوةالتفاصيل (scripts/laptop-setup.mjs، الدالة setupCloud)إجراء المالك
1firebase-toolsإذا لم يوجد node_modules/firebase-tools يشغّل npm ci—
2تسجيل الدخولfirebase login إذا لم يكن هناك حساب مسجلاختر حسابك في Google واضغط Allow
3المشروعيعيد استخدام مشروع Firebase باسم «MEGO Nutrition» أو مشروع Cloud من محاولة سابقة؛ وإلا ينشئ mego-<6 hex> باسم العرض «MEGO Nutrition»أول مرة فقط: اقبل شروط Firebase في وحدة التحكم (اتفاق قانوني لا يقبله إلا المالك). إذا لم يظهر حوار: «Create a project» ← «Add Firebase to a Google Cloud project» ← «MEGO Nutrition» ← Continue (مع إيقاف Google Analytics)
4تطبيق الويبينشئ تطبيق الويب «MEGO Web» ويقرأ إعداد SDK الخاص به—
5Firestoreيفعّل واجهة Cloud Firestore API (عبر Service Usage API)، وينتظر 15 ثانية، ثم ينشئ قاعدة البيانات (default) في أول موقع متاح: me-central2 (الدمام) ← me-central1 (الدوحة) ← eur3 (أوروبا)؛ ويكرر حتى 4 جولات بفاصل 30 ثانية، وينتظر حتى تستجيب القاعدة. الموقع دائم ولا يمكن تغييره.—
6القواعدfirebase deploy --only firestore:rules,firestore:indexes (الملفات المحددة في firebase.json)—
7الدخول بالبريديفعّل Email/Password ويضبط النطاقات المصرّح بها: localhost، <project>.firebaseapp.com، <project>.web.app، mego2012.github.ioفقط إذا فشل الاستدعاء: Authentication ← Get started ← Email/Password ← Enable ← Save
8الإعداد العاميكتب public/firebase-config.json (apiKey وauthDomain وprojectId وappId وaiBackendUrl — معرّفات عامة)—
9ربط الخادميستدعي إجراء الخادم setCloudConfig: يحفظ معرّفات Firebase العامة في خصائص السكربت مع حد للذكاء الاصطناعي قدره 10 عمليات مسح لكل مستخدم يوميًا و200 يوميًا إجمالًا (يحصر الخادم القيمتين ضمن 1–50 و1–1500)—
10المسؤولإذا أُعطي بريد: يبحث عن الحساب ويكتب admins/{uid} بصلاحيات المالكسجّل في التطبيق أولًا
11النشريحفظ الإعداد بهوية «MEGO setup» (عنوان GitHub من نوع noreply) ويرفعه، ثم يتحقق أن الفرع البعيد يحتوي الإيداع الجديد—
12التحقق الحيينتظر (حتى 10 دقائق) إلى أن يقدّم الموقع الحي الإعداد الجديد، ويثبّت Playwright عند الحاجة، ثم يشغّل scripts/live-verify.mjs—

يُحفظ التقدم (معرّف المشروع، ومعرّف تطبيق الويب، وموقع قاعدة البيانات) في ~/.mego-backend/state.json، لذا يمكن إعادة تشغيل أي محاولة متوقفة فتكمل من حيث توقفت.

4. قواعد الأمان المنشورة

من الملف firebase/firestore.rules (ملف الفهارس فارغ):

المسارمن يحق له ماذا
users/{uid}/{table}/{key}المالك فقط وطالما حالة ملفه نشطة؛ المسؤولون لا يصلون إليها؛ لا يجوز أن يعيد التحديث قيمة updatedAt إلى الوراء؛ جداول محددة فقط وحجم السجل أقل من 300,000 حرف
profiles/{uid}المالك يقرأ وينشئ (حالة نشطة، تأكيد العمر، بريده نفسه) ويعدّل الاسم والدولة وlastActiveAt؛ المسؤولون يقرؤون الجميع ولا يغيّرون إلا status (نشط/موقوف)
admins/{uid}يقرؤه صاحبه فقط؛ لا كتابة من العميل (سكربت الإعداد أو وحدة التحكم فقط)
foods/{id}المستخدمون النشطون يقرؤون؛ المسؤولون يكتبون
foodSubmissions/{id}المستخدمون يقترحون (بحالة pending) ويقرؤون اقتراحاتهم؛ المسؤولون يراجعون
errorReports/{id}المستخدمون المسجلون ينشئون تقارير قصيرة؛ المسؤولون يقرؤون ويحذفون

تُختبر القواعد بالأمر npm run test:rules (14/14 على المحاكيات) وتُطبَّق حيًّا (أداة التحقق الحي: بيانات المستخدمين الآخرين وإجراءات المسؤول تعيد 403).

5. منح المالك صلاحية المسؤول

  1. افتح https://mego2012.github.io/Mego/ وسجّل ببريدك (تسجيل من 3 خطوات).
  2. على اللابتوب: node scripts/laptop-setup.mjs --cloud <that e-mail>.
  3. يطبع السكربت «administrator role for …» مع ✅. وإذا لم يوجد الحساب بعد يخبرك بذلك ولا يكتب شيئًا.

الحالة في 10 نوفمبر 2026: لم يُنفَّذ — بانتظار المالك؛ لا يوجد مسؤول حتى الآن.

6. إعادة التشغيل والاستئناف وحل المشكلات

الحالةما العمل
«Failed to add Firebase»اقبل شروط Firebase في صفحة وحدة التحكم التي يفتحها السكربت ثم اضغط Enter؛ يعيد السكربت استخدام مشروع Cloud نفسه
تعذّر إنشاء قاعدة البياناتيعرض السكربت رسالة Google، وينتظر أثناء تفعيل واجهة Firestore API. أعد التشغيل لاحقًا
الإعداد لم يظهر على الموقع الحي بعديحتاج GitHub Pages نحو 1–3 دقائق؛ شغّل لاحقًا node scripts/laptop-setup.mjs --verify
فشل الدفع إلى GitHubيعرض سطر النتيجة رسالة Git؛ أصلح الصلاحية وأعد تشغيل --cloud
تغيّرت القواعد فقطإعادة تشغيل --cloud تعيد نشر القواعد (بأمر firebase deploy نفسه)
