Purpose and scope

This guide explains how the public multi-user platform of MEGO (accounts, private cloud data, admin role) is set up on Firebase's free Spark plan (no billing account) with one command, node scripts/laptop-setup.mjs --cloud [admin-email]. It lists every step the script performs, the one-time actions only the owner can do, the resulting production values and how to re-run or verify the setup.

1. Before you start

  • A laptop with Git and Node.js, and the repository cloned on branch claude/nutrition-tracking-app-989rku (see MEGO_Developer_Setup_and_Local_Installation).
  • Push rights to the GitHub repository (the script commits and pushes the public config).
  • Normally the Apps Script backend is installed first (node scripts/laptop-setup.mjs): the --cloud phase runs after the backend's live tests, and it tells the backend about the Firebase project so signed-in users can use the AI scanner.
  • No billing account is needed or created. Spark plan limits apply (exact quotas: see Google's Firebase pricing page — not reproduced here).

2. Running the command

node scripts/laptop-setup.mjs --cloud                  # platform without an admin yet
node scripts/laptop-setup.mjs --cloud <your e-mail>     # also grants the admin role (account must already exist)

Add --auto to avoid keyboard prompts (the script then polls every 10 seconds while it waits for you on a Google page).

3. What the script does, step by step

#StepDetail (scripts/laptop-setup.mjs, setupCloud)Owner action
1firebase-toolsIf node_modules/firebase-tools is missing, runs npm ci—
2Sign-infirebase login if no account is listedChoose your Google account, click Allow
3ProjectReuses a Firebase project named "MEGO Nutrition", or a Cloud project from an earlier attempt; otherwise creates mego-<6 hex> with display name "MEGO Nutrition"First time only: accept the Firebase terms in the console (a legal agreement only the owner can accept). If no dialog: "Create a project" → "Add Firebase to a Google Cloud project" → "MEGO Nutrition" → Continue (Google Analytics off)
4Web appCreates the web app "MEGO Web" and reads its SDK config—
5FirestoreEnables the Cloud Firestore API (Service Usage API), waits 15 s, then creates the (default) database in the first available location: me-central2 (Dammam) → me-central1 (Doha) → eur3 (Europe); retries up to 4 rounds, 30 s apart; waits until it answers. The location is permanent.—
6Rulesfirebase deploy --only firestore:rules,firestore:indexes (files from firebase.json)—
7E-mail sign-inEnables Email/Password and sets the authorised domains localhost, <project>.firebaseapp.com, <project>.web.app, mego2012.github.ioOnly if the API call fails: Authentication → Get started → Email/Password → Enable → Save
8Public configWrites public/firebase-config.json (apiKey, authDomain, projectId, appId, aiBackendUrl — public identifiers)—
9Backend linkCalls the backend action setCloudConfig: stores the public Firebase identifiers in Script Properties with an AI limit of 10 scans per user per day and 200 per day overall (the backend clamps these to 1–50 and 1–1500)—
10AdminIf an e-mail is given: looks up the account and writes admins/{uid} with the owner's credentialsRegister in the app first
11PublishCommits the config as "MEGO setup" (GitHub noreply address), pushes, and checks the remote branch has the new commit—
12Live verificationWaits (up to 10 minutes) until the live site serves the new config, installs Playwright if needed, runs scripts/live-verify.mjs—

Progress (project id, web-app id, database location) is saved in ~/.mego-backend/state.json, so a run that stops can be repeated and continues where it stopped.

4. Security rules that are deployed

From firebase/firestore.rules (indexes file is empty):

PathWho may do what
users/{uid}/{table}/{key}Only the owner, only while the profile status is active; admins have no access; an update may not move updatedAt back; only listed tables, record < 300,000 characters
profiles/{uid}Owner reads/creates (status active, age confirmed, own e-mail) and updates name, country, lastActiveAt; admins read all and may change only status (active/suspended)
admins/{uid}Readable by that user only; no client writes (setup script / console only)
foods/{id}Active users read; admins write
foodSubmissions/{id}Users propose (pending) and read their own; admins review
errorReports/{id}Signed-in users create small reports; admins read/delete

Rules are tested by npm run test:rules (14/14 on the emulators) and enforced live (live verifier: other users' data and admin actions return 403).

5. Making the owner an administrator

  1. Open https://mego2012.github.io/Mego/ and register with your e-mail (3-step registration).
  2. On the laptop: node scripts/laptop-setup.mjs --cloud <that e-mail>.
  3. The script prints "administrator role for …" with ✅. If the account does not exist yet, it says so and nothing is written.

6. Re-running, resuming and troubleshooting

SituationWhat to do
"Failed to add Firebase"Accept the Firebase terms in the console page the script opens, then press Enter; the script reuses the same Cloud project
Database cannot be createdThe script shows Google's message; it waits while the Firestore API is switching on. Run again later
Config not on the live site yetGitHub Pages takes ~1–3 minutes; run node scripts/laptop-setup.mjs --verify later
Push failedThe result line shows Git's message; fix access and run --cloud again
Only the rules changedRunning --cloud again redeploys the rules (same firebase deploy command)
