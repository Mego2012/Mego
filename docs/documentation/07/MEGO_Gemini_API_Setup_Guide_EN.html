Purpose and scope

This guide explains how to switch on MEGO's AI meal scanner with a free-tier Google Gemini API key, where the key is stored, which limits and models apply, how to test it and how to replace or remove it. MEGO uses only the free tier: never add a billing account to the key's project. The key is stored only in the Apps Script backend's Script Properties — never on the phone, never in GitHub.

1. Rules: free tier only

  • Create the key in Google AI Studio without clicking "Set up billing". The backend comment states that a key without billing can only use the free tier and cannot be charged.
  • Only free Flash models are allowed (AI_FREE_MODELS in apps-script/Code.gs): gemini-3.8-flash → gemini-3.6-flash → gemini-3.5-flash-lite. No paid model and no other provider is ever called.
  • When the free quota is used up, Google answers 429 and the app shows a message (the daily quota resets at midnight Pacific time); nothing is retried elsewhere.

2. Creating the key in Google AI Studio

  1. Open https://aistudio.google.com/apikey and sign in with the owner's Google account.
  2. Accept Google's terms if asked. Click Create API key.
  3. Do not click "Set up billing".
  4. Copy the key. Both formats are accepted: classic keys starting with AIza and Google's newer keys starting with AQ.. Never paste it into a chat, e-mail or document.

3. Storing the key

WaySteps
A. During laptop setupnode scripts/laptop-setup.mjs opens the AI Studio page and asks you to paste the key (Enter = skip)
B. From the clipboard (recommended)Copy the key, then run node scripts/laptop-setup.mjs --test --ai-key-from-clipboard. The script reads the clipboard (Windows: PowerShell Get-Clipboard), so the key is never typed or shown
C. In the app (owner device connected to the Hub)Settings → AI meal scanner → paste the key → Check & save key in my backend

In every case the backend action setAiKey checks the key with Google first (a model metadata request, not a generation) and only then saves it as GEMINI_API_KEY in Script Properties. The laptop script prints "Gemini key accepted by Google and stored only in Script Properties" with ✅. Signed-in Firebase users do not need a key of their own: their scans go through the owner's backend (aiBackendUrl in the public config) with their Firebase sign-in token.

4. How the backend uses the key

  • The app sends a downscaled JPEG (location data removed), the list of food names (short key, names, state, category) and an optional note. The model identifies foods and estimates grams; the app computes nutrition from the database. Nothing is auto-saved.
  • Model chain (introduced in SCRIPT_VERSION 7, unchanged in 8): the configured model (optional Script Property AI_MODEL, default gemini-3.8-flash) first, then the other free models. A 503 "overloaded" moves at once to the next model; 500/504 are retried on the same model after 2 s and 4 s; quota, key and configuration errors are never retried.
  • The phone client also retries temporary errors automatically after 3 s and 8 s, keeps the image for a manual retry and sends one request at a time.

6. Testing: AI diagnostic and a real photo

  1. Diagnostic: git pull && node scripts/laptop-setup.mjs --update-backend ends with a text-only check of every free model and prints the HTTP code and Google's message per model.
  2. Real photo: node scripts/laptop-setup.mjs --test analyses a public Wikimedia Commons meal photo (or yours with --photo meal.jpg) and prints the items, grams, confidence and database matches.
  3. In the app: Home → camera → analyse → review → confirm.

Live results: 7 Nov 2026 one photo analysis succeeded (6 items, ≈ 72 s); 10 Nov 2026 a real meal photo was analysed through the live app UI with a disposable account (≈ 64 s, 4 items). The free tier remains slow at peak times.

8. Replacing, rotating or removing the key

  • Replace / rotate: create a new key in AI Studio, store it with way B or C (the new key overwrites GEMINI_API_KEY), then delete the old key in AI Studio. Rotation is recommended now, because the owner's key was shown in a chat during setup.
  • Remove: app Settings → Remove key (deletes the Script Property).

9. Privacy notes

On the free tier Google may use requests to improve its products and human reviewers may see them (disconnected from the account). MEGO therefore sends only the meal photo (without location/EXIF) and food names — no diary, weight or profile data — and the backend stores nothing about the meal. Avoid people or documents in the photo.
