الغرض والنطاق

يصف هذا الدليل طريقة نشر منظومة MEGO في الإنتاج: تطبيق الويب التقدّمي (PWA) الثابت على GitHub Pages، وملف إعداد Firebase العام الذي يفعّل الحسابات، وخادم Google Apps Script الخاص بالمالك (مزامنة الـ Hub وماسح الوجبات الذكي)، والترتيب الذي تُطلَق به هذه الأجزاء. التفاصيل الكاملة لكل خدمة سحابية موجودة في أدلتها المخصصة؛ أما هذه الوثيقة فهي النظرة العامة وإجراء GitHub Pages.

2. مسار عمل GitHub Pages ‏(deploy.yml)

اسم مسار العمل (Workflow): "Test & deploy to GitHub Pages".

الإعدادالقيمة في الملف
المشغّلاتالدفع (push) إلى main أو claude/nutrition-tracking-app-989rku؛ والتشغيل اليدوي workflow_dispatch
الصلاحياتcontents: read، pages: write، id-token: write
التزامنالمجموعة pages مع cancel-in-progress: true (الدفع الأحدث يلغي التشغيل الأقدم)
مهمة build ‏(ubuntu-latest)checkout@v4 → setup-node@v4 (Node 22, npm cache) → npm ci → npm test → npm run build with BASE_PATH=/<repository name>/ → upload-pages-artifact@v3 (dist)
مهمة deployتعتمد على build؛ البيئة github-pages؛ deploy-pages@v4

نتائج مهمة:

  • فشل أي اختبار وحدة يوقف النشر: لا يُنشر شيء ما لم ينجح npm test والبناء.
  • مجموعات المتصفح واللمس والقواعد وتعدد المستخدمين لا تُشغَّل في CI؛ يجب تشغيلها قبل الدفع (انظر MEGO_Build_and_Release_Procedures).
  • يُشتق BASE_PATH من اسم المستودع، فيُبنى التطبيق للمسار /Mego/. ويستخدمه vite.config.ts بوصفه base وstart_url وscope لتطبيق PWA.

3. إعدادات GitHub لمرة واحدة

  1. في GitHub: المستودع ← Settings → Pages → Source: GitHub Actions (docs/SETUP.md).
  2. شغّل مسار العمل مرة واحدة (Actions ← «Test & deploy to GitHub Pages» ← Run workflow).
  3. تعرض خطوة deploy رابط الصفحة. رابط الإنتاج: https://mego2012.github.io/Mego/.

يذكر docs/SETUP.md أن GitHub Pages على مستودع خاص يتطلب خطة GitHub مدفوعة، وأن أي استضافة ثابتة يمكنها تقديم dist/ بدلًا منه (مع BASE_PATH=/). المستخدم والمُتحقَّق منه لـ MEGO هو GitHub Pages فقط.

4. نشر تغيير جديد

  1. شغّل الفحوص المحلية (على الأقل npm test وnpm run build وnpm run e2e وnpm run e2e:scroll).
  2. احفظ التغييرات وادفعها إلى claude/nutrition-tracking-app-989rku.
  3. راقب التشغيل في تبويب Actions؛ يجب أن تكون المهمتان باللون الأخضر.
  4. التطبيقات المثبّتة تتحدث ذاتيًا: بُني تطبيق PWA بالخيار registerType: 'autoUpdate'، فيتولى عامل الخدمة الجديد العمل في تشغيل لاحق.
  5. نفّذ فحوص الإنتاج في MEGO_Production_Verification_Checklist.

عند تغيير معرّف الإصدار APP_RELEASE ‏(src/lib/localBackup.ts، حاليًا '1.3-training') يأخذ كل جهاز يحتوي بيانات نسخة احتياطية قبل التحديث واحدة داخل قاعدة بياناته المحلية عند أول فتح للإصدار الجديد (src/main.tsx).

5. إعداد Firebase العام

يجلب التطبيق الملف ./firebase-config.json عند بدء التشغيل (src/lib/firebase.ts). إذا لم يوجد يعمل النشر بوضع الضيف فقط. يحتوي الملف معرّفات عامة فقط: apiKey وauthDomain وprojectId وappId وaiBackendUrl. الحماية تفرضها القواعد في firebase/firestore.rules وليس إخفاء هذه القيم. يولّد الملفَ الأمرُ laptop-setup --cloud، ثم يحفظه بالهوية المحايدة «MEGO setup» ويرفعه ويتحقق من أن GitHub استلم الإيداع؛ بعدها يعيد GitHub Pages النشر (نحو 1–3 دقائق، وينتظر السكربت ذلك).

6. نشر الخادم والذكاء الاصطناعي (Apps Script)

لا يبني مسار العمل الخادم. يُنشر الخادم من لابتوب المالك بأداة سطر الأوامر الرسمية لـ Apps Script ‏(clasp 3.4.1 عبر npx):

node scripts/laptop-setup.mjs                    # first install or full update + live tests
git pull && node scripts/laptop-setup.mjs --update-backend   # upload the latest Code.gs to the SAME deployment + AI diagnostic
node scripts/laptop-setup.mjs --hub-complete-foods            # update the backend, then add missing library foods to the Hub (adds only)

تعيد عمليات النشر اللاحقة استخدام معرّف النشر المحفوظ، فيبقى رابط تطبيق الويب ورمز التطبيق كما هما. انظر MEGO_Apps_Script_Setup_Guide وMEGO_Gemini_API_Setup_Guide.

7. ترتيب النشر الموصى به (بيئة جديدة)

  1. GitHub Pages: فعّل Pages وادفع ← التطبيق الثابت يعمل بوضع الضيف.
  2. خادم Apps Script والـ Hub: node scripts/laptop-setup.mjs.
  3. مفتاح Gemini (اختياري، الفئة المجانية): أثناء الخطوة 2، أو عبر --test --ai-key-from-clipboard.
  4. Firebase: node scripts/laptop-setup.mjs --cloud ← نشر ملف الإعداد ← تشغيل التحقق الحي تلقائيًا.
  5. المسؤول (Admin): يسجّل المالك حسابه في التطبيق، ثم يشغّل --cloud <e-mail> مرة أخرى (ما زال معلّقًا حتى 10 نوفمبر 2026).

8. بعد النشر

  • نفّذ قائمة فحص الإنتاج (أداة التحقق الحي، مجموعات المتصفح على الموقع الحي، تشخيص الذكاء الاصطناعي).
  • حافظ على سرية ~/.mego-backend/؛ ففيه رابط الخادم والرمز.
  • يُوصى (وفق حقائق الحالة) بتدوير مفتاح Gemini ورابط اتصال الخادم، لأنهما ظهرا في محادثة أثناء الإعداد.
