Purpose and scope

This guide describes how the MEGO production system is deployed: the static Progressive Web App (PWA) on GitHub Pages, the public Firebase configuration that switches on accounts, the owner's Google Apps Script backend (Hub sync and AI meal scanner) and the order in which these pieces are put live. Detailed set-up of each cloud service is in the dedicated guides; this document is the overview and the GitHub Pages procedure.

2. GitHub Pages workflow (deploy.yml)

Workflow name: "Test & deploy to GitHub Pages".

SettingValue in the file
Triggerspush to main or claude/nutrition-tracking-app-989rku; manual workflow_dispatch
Permissionscontents: read, pages: write, id-token: write
Concurrencygroup pages, cancel-in-progress: true (a newer push cancels an older run)
Job build (ubuntu-latest)checkout@v4 → setup-node@v4 (Node 22, npm cache) → npm ci → npm test → npm run build with BASE_PATH=/<repository name>/ → upload-pages-artifact@v3 (dist)
Job deployneeds build; environment github-pages; deploy-pages@v4

Important consequences:

  • A failing unit test stops the deployment: nothing is published unless npm test and the build succeed.
  • The browser, touch, rules and multi-user suites are not run in CI; they must be run before pushing (see MEGO_Build_and_Release_Procedures).
  • BASE_PATH comes from the repository name, so the app is built for /Mego/. vite.config.ts uses it as base, PWA start_url and scope.

3. One-time GitHub settings

  1. GitHub → repository Settings → Pages → Source: GitHub Actions (docs/SETUP.md).
  2. Run the workflow once (Actions → "Test & deploy to GitHub Pages" → Run workflow).
  3. The deploy step shows the page URL. Production: https://mego2012.github.io/Mego/.

docs/SETUP.md notes that GitHub Pages on a private repository requires a paid GitHub plan; any static host can serve dist/ instead (with BASE_PATH=/). Only GitHub Pages is used and verified for MEGO.

4. Deploying a change

  1. Run the local checks (at least npm test, npm run build, npm run e2e, npm run e2e:scroll).
  2. Commit and push to claude/nutrition-tracking-app-989rku.
  3. Watch the run in the Actions tab; both jobs must be green.
  4. Installed apps update themselves: the PWA is built with registerType: 'autoUpdate', so the new service worker takes over on a later launch.
  5. Run the production checks in MEGO_Production_Verification_Checklist.

When the release identifier APP_RELEASE (src/lib/localBackup.ts, currently '1.3-training') changes, every device that has data takes one pre-update backup inside its local database the first time the new version opens (src/main.tsx).

5. Public Firebase configuration

The app fetches ./firebase-config.json at start-up (src/lib/firebase.ts). If it is missing, the deployment is guest-only. The file contains public identifiers only: apiKey, authDomain, projectId, appId and aiBackendUrl. Access is enforced by firebase/firestore.rules, not by keeping these values secret. The file is generated by laptop-setup --cloud, committed with the neutral identity "MEGO setup", pushed, and the script checks that GitHub received the commit; GitHub Pages then redeploys (about 1–3 minutes, as the script waits for it).

6. Backend and AI deployment (Apps Script)

The backend is not built by the workflow. It is deployed from the owner's laptop with the official Apps Script CLI (clasp 3.4.1, run through npx):

node scripts/laptop-setup.mjs                    # first install or full update + live tests
git pull && node scripts/laptop-setup.mjs --update-backend   # upload the latest Code.gs to the SAME deployment + AI diagnostic
node scripts/laptop-setup.mjs --hub-complete-foods            # update the backend, then add missing library foods to the Hub (adds only)

Re-deploys reuse the stored deployment id, so the web-app URL and the app token stay the same. See MEGO_Apps_Script_Setup_Guide and MEGO_Gemini_API_Setup_Guide.

7. Recommended deployment order (fresh environment)

  1. GitHub Pages: enable Pages, push → static app live in guest mode.
  2. Apps Script backend + Hub: node scripts/laptop-setup.mjs.
  3. Gemini key (optional, free tier): during step 2, or --test --ai-key-from-clipboard.
  4. Firebase: node scripts/laptop-setup.mjs --cloud → config published → live verification runs automatically.
  5. Admin: the owner registers in the app, then runs --cloud <e-mail> again (still pending as of 10 Nov 2026).

8. After deployment

  • Run the production checklist (live verifier, live browser suites, AI diagnostic).
  • Keep ~/.mego-backend/ private; it contains the backend URL and token.
  • Recommended (status facts): rotate the Gemini key and the backend connection link, because both were shown in a chat during setup.
