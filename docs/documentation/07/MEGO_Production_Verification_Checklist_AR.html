الغرض والنطاق

تُنفَّذ هذه القائمة بعد كل نشر في الإنتاج (التطبيق أو الخادم أو القواعد) لإثبات أن النظام الحي يعمل: موقع GitHub Pages، والحسابات وعزل البيانات على مشروع Firebase الحقيقي، ومجموعتا المتصفح واللمس على الموقع الحي، وصفحات التمارين الـ 54 الحية، وخادم Apps Script، وماسح الوجبات Gemini. لكل بند الأمر والنتيجة المتوقعة وآخر نتيجة مسجلة. ولا يُوصف أي بند بأنه «يعمل حيًّا» إلا إذا حصل على ✅ في تشغيل حي.

1. طريقة استخدام القائمة

  • نفّذها على لابتوب المالك والمستودع محدَّث (git pull) وPlaywright مثبّت (npm install --no-save playwright@1.63.0 && npx playwright install chromium).
  • الأقسام المطلوبة: إصدار التطبيق ← 2 و3 و4؛ إصدار الخادم ← 5 و6 (و3 إذا تغيّر وسيط الذكاء الاصطناعي)؛ إصدار القواعد ← 3.
  • سجّل كل نتيجة في القسم 9. أي بند فاشل يوقف الإصدار؛ واتبع MEGO_Update_and_Rollback_Procedures.

3. الحسابات والسحابة: scripts/live-verify.mjs

node scripts/live-verify.mjs                  # production
node scripts/laptop-setup.mjs --verify        # same, started by the setup script

تشغّل أداة التحقق التطبيقَ المنشور في متصفح حقيقي (ملف Pixel 7) على مشروع Firebase الحقيقي، وتنشئ حسابين مؤقتين (mego-verify-<random>-a/b@example.com)، ولا تستخدم إلا رموزهما (فكل سماح أو رفض هو عمل قواعد الإنتاج نفسها)، ثم تحذف الحسابين في النهاية حتى لو فشل فحص. التقرير: ~/.mego-backend/live-verify-<time>.md. يعرّف السكربت الحالي 17 فحصًا:

  1. الموقع الحي يقدّم التطبيق وإعداد Firebase العام
  2. تسجيل الحساب A على الموقع الحي
  3. تسجيل الحساب B — حساب مستقل
  4. الملفات الشخصية محفوظة على الخادم؛ وكل مستخدم يقرأ ملفه فقط
  5. تسجيل طعام (الحساب A) ومزامنته مع السحابة
  6. عزل البيانات يفرضه الخادم
  7. مكتبة الوصفات تعرض السعرات والمغذيات لحساب جديد بقائمة أطعمة فارغة (الحساب B)
  8. تسجيل الكارديو (الحساب A): يُزامَن لصاحبه فقط ولا يراه الحساب B
  9. التمارين (الحساب A): البرنامج وجلسة مسجلة يُزامَنان لصاحبهما فقط
  10. المزامنة السحابية إلى جهاز ثانٍ (الحساب A يسجّل الدخول في مكان آخر)
  11. التقرير الأسبوعي من اليوم المسجل
  12. التقرير الشهري من اليوم المسجل
  13. وظائف المسؤول يفرضها الخادم (حساب عادي)
  14. قبول Firebase لطلب استعادة كلمة المرور (من شاشة التطبيق)
  15. تسجيل الخروج ثم الدخول مجددًا (حساب دائم)
  16. حذف الحساب التجريبي A — إزالة الدخول والملف والسجلات
  17. حذف الحساب التجريبي B

المتوقع: «17/17 live checks passed». آخر نتيجة إنتاج مسجلة: 14/14 في 7 نوفمبر 2026 (نسخة السكربت قبل إضافة الفحوص 7–9). ولاختبار الأداة نفسها دون لمس الإنتاج: node scripts/live-verify.mjs --emulator.

#الفحصالطريقةالمتوقع

6.3صورة حقيقية عبر واجهة التطبيق الحيسجّل الدخول (حساب مؤقت)، الرئيسية ← الكاميرا ← حلّل ← راجعتظهر العناصر المتعرَّف عليها للمراجعة؛ ولا يُحفظ شيء قبل التأكيد. آخر نتيجة 10 نوفمبر 2026: نحو 64 ثانية، 4 عناصر

قد تكون الفئة المجانية بطيئة أو مشغولة في أوقات الذروة؛ والخطأ المؤقت لا يُعد فشلًا للإصدار إذا أظهر التشخيص أن المفتاح والنماذج صالحة.

7. الفحوص اليدوية وفحوص الأجهزة

  • هاتف Android حقيقي: اتبع docs/ANDROID-TEST.md (التثبيت، العمل دون اتصال، الكاميرا، الباركود، التمرير). لم يُنفَّذ بعد.
  • العربية من اليمين لليسار والإنجليزية من اليسار لليمين، والسمة الفاتحة والداكنة: فحص سريع للرئيسية واليوميات والتقارير.
  • لوحة المسؤول: فقط بعد وجود حساب المسؤول للمالك (معلّق).

8. فحوص الأمان

  • لا مفاتيح ولا رموز ولا روابط /exec ولا رموز اتصال ولا بيانات شخصية في التغييرات المدفوعة.
  • البندان 6 و13 في أداة التحقق الحي يُظهران 403 للإجراءات بين الحسابات وإجراءات المسؤول.
  • بنود مفتوحة: تدوير مفتاح Gemini ورمز الخادم (ظهرا في محادثة أثناء الإعداد)؛ وطلب دعم GitHub للإيداعات القديمة (docs/GITHUB-SUPPORT-REQUEST.md).
