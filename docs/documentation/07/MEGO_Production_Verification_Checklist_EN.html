Purpose and scope

This checklist is run after every production deployment (app, backend or rules) to prove that the live system works: the GitHub Pages site, accounts and data isolation on the real Firebase project, the live browser and touch suites, the 54 live exercise pages, the Apps Script backend and the Gemini AI scanner. Each item names the command, the expected result and the last recorded result. Only items with a ✅ in a live run may be called "live".

1. How to use this checklist

  • Run on the owner's laptop with the repository up to date (git pull) and Playwright installed (npm install --no-save playwright@1.63.0 && npx playwright install chromium).
  • Which sections are required: app release → 2, 3, 4; backend release → 5, 6 (and 3 if the AI proxy changed); rules release → 3.
  • Record each result in section 9. A failed item blocks the release; follow MEGO_Update_and_Rollback_Procedures.

3. Accounts and cloud: scripts/live-verify.mjs

node scripts/live-verify.mjs                  # production
node scripts/laptop-setup.mjs --verify        # same, started by the setup script

The verifier runs the deployed app in a real browser (Pixel 7 profile) against the real Firebase project, creates two disposable accounts (mego-verify-<random>-a/b@example.com), uses only their own tokens (so every allow/deny is the production rules at work) and deletes both accounts at the end, also when a check fails. Report: ~/.mego-backend/live-verify-<time>.md. The current script defines 17 checks:

  1. Live site serves the app and the public Firebase config
  2. Registration (account A) on the live site
  3. Registration (account B) — an independent account
  4. Profiles stored on the server; each user reads only their own
  5. Food logging (account A) and sync to the cloud
  6. Data isolation enforced by the server
  7. Recipe library shows calories and macros for a new account with an empty food list (account B)
  8. Cardio logging (account A): synced to the owner only, invisible to account B
  9. Workouts (account A): program and a logged session sync to the owner only
  10. Cloud sync to a second device (account A signs in elsewhere)
  11. Weekly report from the logged day
  12. Monthly report from the logged day
  13. Admin functions are enforced by the server (regular account)
  14. Password recovery request accepted by Firebase (from the app screen)
  15. Sign-out and sign-in again (persistent account)
  16. Account deletion (test account A) — login, profile and records removed
  17. Account deletion (test account B)

Expected: "17/17 live checks passed". Last recorded production result: 14/14 on 7 Nov 2026 (version of the script before checks 7–9 were added). To test the verifier itself without touching production: node scripts/live-verify.mjs --emulator.

8. Security checks

  • No keys, tokens, /exec URLs, connection codes or personal data in the pushed diff.
  • Live verifier items 6 and 13 show 403 for cross-account and admin actions.
  • Open items: rotate the Gemini key and the backend token (both shown in a chat during setup); GitHub support request for old commits (docs/GITHUB-SUPPORT-REQUEST.md).
