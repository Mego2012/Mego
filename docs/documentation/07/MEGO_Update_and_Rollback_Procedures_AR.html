الغرض والنطاق

تصف هذه الوثيقة كيف يُحدَّث كل جزء من MEGO بأمان وكيف يُتراجع عن تحديث معيب: تطبيق PWA على GitHub Pages، وبيانات المستخدمين على الأجهزة وفي السحابة، وخادم Apps Script (يُعاد نشره على النشر نفسه)، وجدول الـ Hub في Google Sheets، وقواعد Firestore. وتشرح النسخ الاحتياطية التي تُؤخذ تلقائيًا قبل التحديث وكيفية استخدامها.

1. مبادئ الأمان

  • التحديثات لا تحذف بيانات المستخدم أبدًا: الاستعادة والمزامنة تدمجان البيانات (لا يُستبدل السجل إلا بنسخة updatedAt فيها مساوٍ أو أحدث)؛ والـ Hub وFirestore يرفضان النسخ الأقدم.
  • تُؤخذ نسخة احتياطية قبل كل خطوة خطرة (القسمان 2 و7).
  • إعادة نشر الخادم تحتفظ بمعرّف النشر نفسه، فلا يتغير رابط تطبيق الويب ولا الرمز ولا يحتاج أي جهاز إلى إعادة الربط.
  • يُفضَّل «التقدم للأمام» (إيداع جديد يصلح المشكلة) على إعادة كتابة السجل.

3. تحديث التطبيق (PWA)

  1. ادفع الإصدار (MEGO_Build_and_Release_Procedures)؛ فيختبر CI ويبني وينشر.
  2. تحمّل الأجهزة عامل الخدمة الجديد (registerType: 'autoUpdate')؛ ويصبح الإصدار الجديد فعّالًا من تشغيل لاحق.
  3. عند أول تشغيل تُحفظ نسخة ما قبل التحديث (إذا تغيّر APP_RELEASE).
  4. التحقق: الإعدادات ← فحص البيانات (Data check) يقارن أعداد السجلات الحالية (اليوميات، القياسات، الأيام، الأطعمة) بأحدث نسخة قبل التحديث ويبيّن هل ما زال كل جدول يحوي العدد نفسه على الأقل؛ ويعرض أيضًا الأطعمة المشبوهة المسجلة لكل حصة والتكرارات المحتملة. وهو للقراءة فقط.

4. التراجع عن تحديث التطبيق

  1. حدّد الإيداع المعيب (git log --oneline).
  2. أنشئ إيداعًا عكسيًا وادفعه: 
    git revert <commit>
git push origin claude/nutrition-tracking-app-989rku
  3. يعيد مسار العمل نشر الشيفرة السابقة؛ وتتحدث التطبيقات المثبّتة تلقائيًا.
  4. إذا بدت البيانات خاطئة على جهاز: الإعدادات ← نسخ احتياطية تلقائية على الهاتف ← اختر نسخة ما قبل التحديث ← استعادة (تُؤخذ نسخة ما قبل الاستعادة أولًا؛ والاستعادة تدمج ولا تحذف). ويمكن للمستخدمين المسجلين أيضًا تسجيل الدخول مجددًا فتُنزَّل النسخة السحابية (انظر حادثة 10 نوفمبر 2026 في MEGO_Data_Backup_and_Recovery).

ملاحظات: البيانات التي كتبها الإصدار الأحدث (مثلًا في جدول kv) تبقى على الجهاز وفي السحابة؛ ولم يُختبر هل يتجاهلها الإصدار الأقدم بشكل صحيح. وإعادة APP_RELEASE إلى قيمة سابقة لا تنشئ نسخة جديدة قبل التحديث إذا كانت هناك نسخة لتلك القيمة من قبل.

5. تحديث الخادم (النشر نفسه)

cd $HOME\Mego        (Windows; on macOS/Linux: cd ~/Mego)
git pull
node scripts/laptop-setup.mjs --update-backend
  • يرفع أحدث Code.gs وappsscript.json وينفّذ clasp create-deployment --deploymentId <stored id>: الرابط نفسه والرمز نفسه، وخصائص السكربت (المفاتيح والحدود ومعرّف الـ Hub) وبيانات الـ Hub دون مساس.
  • ينتهي بتشخيص الذكاء الاصطناعي ويطبع إصدار الخادم (يجب أن يكون 8 للمستودع الحالي).
  • --hub-complete-foods ينفّذ التحديث نفسه ثم يضيف أطعمة المكتبة إلى الـ Hub (إضافة فقط؛ نسخة Drive يومية أولًا؛ وإعادة التشغيل لا تضيف شيئًا).
  • اختياري: node scripts/laptop-setup.mjs --test لمجموعة الاختبارات الحية الكاملة.

6. التراجع عن تحديث الخادم

الخيار أ — إعادة نشر Code.gs أقدم على النشر نفسه:

git checkout <good commit> -- apps-script/Code.gs apps-script/appsscript.json
node scripts/laptop-setup.mjs --update-backend
git checkout HEAD -- apps-script/Code.gs apps-script/appsscript.json

الخيار ب — من محرر Apps Script: Deploy ← Manage deployments ← Edit (القلم) ← Version: اختر إصدارًا سابقًا ← Deploy (الرابط نفسه). كل تنفيذ لـ clasp create-deployment أنشأ إصدارًا، لذا توجد إصدارات سابقة في المشروع.

بعد التراجع، تُبلغ ميزات التطبيق التي تحتاج خادمًا أحدث عن خادم قديم (AI_OLD_BACKEND)؛ ويرفض --hub-complete-foods العمل مع إصدار أقل من 8.

7. استعادة بيانات الـ Hub

  • السجلات المحذوفة تُحذف حذفًا ناعمًا إلى تبويب Deleted_Records (الجدول، المفتاح، وقت الحذف، json، recovered).
  • يمكن فتح نسخ Drive الاحتياطية (القسم 2) ومقارنتها؛ كما يمكن عبر ملف ← سجل الإصدارات (Version history) في Google Sheets استعادة حالة سابقة للـ Hub.
  • ملف Excel الأصلي لم يُعدَّل قط ويبقى النسخة المرجعية الأخيرة.

8. قواعد Firestore والإعداد العام

  • القواعد: تراجع عن التغيير في firebase/firestore.rules، وشغّل npm run test:rules، ثم node scripts/laptop-setup.mjs --cloud لإعادة النشر (والأمر يعيد أيضًا تشغيل التحقق الحي).
  • الإعداد العام: public/firebase-config.json ملف عادي في المستودع؛ والتراجع عنه يُنشر مع التطبيق. وبدونه يعمل الموقع بوضع الضيف فقط.
