Purpose and scope

This document describes MEGO's automated acceptance suite e2e/run-e2e.mjs: the environment it simulates, all 57 checks it performs in a real browser, how to run it locally or against the live site, and how to read the results. It also covers the touch-scrolling acceptance suite e2e/scroll-test.mjs (103 checks). Multi-user acceptance is in MEGO_Multi_User_Testing; the manual phone checklist is in MEGO_Android_Device_Testing.

1. Acceptance approach

The suite started from the 15 acceptance scenarios in the original project brief (TEST 1 to TEST 15) and has grown with the releases: new features added checks that drive the real user interface the way a person would (tapping, typing, choosing from lists) and asserts what the person sees. Checks use stable data-testid attributes, not visual positions. Screenshots of key screens are saved to e2e/screens/.

4. Touch-scrolling acceptance (scroll-test.mjs)

A separate suite proves that a finger swipe scrolls every screen on Samsung-sized phones. It uses raw Chrome DevTools Protocol touch events (touchStart → touchMove… → touchEnd), which Chrome turns into compositor scrolling like a real finger; a control page first proves the method works.

  • Viewports: Galaxy S23 (360×780), Galaxy A54 (412×915), Galaxy S9+ (320×658), each in Arabic (RTL) and English (LTR), Android Chrome user agent.
  • Screens: Home, Diary, Recipes (four tabs), Foods, Planner, Progress, Habits, weekly and monthly reports, Settings.
  • Also: sheet flows (open/close nested sheets, Escape/Back) must never leave the page scroll-locked.
  • Result: 103/103, also against the live URL.

5. Running the suites and reading results

npm run build
npm run e2e                                         # local build, 57 checks
E2E_BASE=https://mego2012.github.io/Mego/ npm run e2e   # same checks on the live site
npm run e2e:scroll                                  # 103 touch checks (local)
node e2e/scroll-test.mjs https://mego2012.github.io/Mego/

A FAIL line contains the first line of the error and, when relevant, the Playwright reason (element not visible, outside the viewport, intercepted by another element). Screenshots are in e2e/screens/.

6. Acceptance criteria for a release

  • npm run e2e: 57/57 on the local production build.
  • npm run e2e:scroll: 103/103.
  • After deployment: both suites against the live URL, plus scripts/live-verify.mjs (see MEGO_Release_Readiness_Checklist).
  • Any failure blocks the release until fixed or explicitly documented in MEGO_Known_Bugs_and_Limitations.

7. Verification status

  • Tested (emulated device, local build): 57/57 browser checks and 103/103 touch checks — latest recorded results (10 Nov 2026).
  • Verified live: 44/44 browser checks against the live URL on 7 Nov 2026 (before the 1.2/1.3 checks existed); 103/103 touch checks against the live URL; the 54 exercise pages 54/54 on the live site (10 Nov 2026).
  • Not verified: a full 57-check run against the live URL is not recorded; Gemini and Open Food Facts are simulated in this suite; camera, barcode scanning hardware and home-screen installation on a physical phone (see MEGO_Android_Device_Testing). The suite was not re-run while writing this document.
