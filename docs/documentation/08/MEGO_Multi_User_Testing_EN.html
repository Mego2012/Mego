Purpose and scope

MEGO is a public multi-user app: each person registers an account (Firebase Email/Password) and their records are stored under their own user id in Cloud Firestore. This document describes how the guarantees of a multi-user system are tested — data isolation, simultaneous devices, administrator limits, suspension, per-user AI limits, password reset and account deletion — at three levels: security rules on emulators, real browsers against emulators, and production.

1. Multi-user guarantees under test

  1. A user can read and write only their own records; changing the user id in a request does not help; signed-out requests are refused.
  2. Each account has a separate local database on the device (mego-u-<uid>), so data of one account never appears in another.
  3. Several devices of the same account receive changes live; an older offline copy never overwrites a newer one.
  4. An administrator sees account cards and counts but never private records; can suspend or reactivate but change nothing else; nobody can make themselves an administrator.
  5. A suspended user is blocked by the server and sees the suspended screen.
  6. Shared foods: everyone reads, only administrators write; user submissions wait for review.
  7. AI meal scanning is limited per user per day, plus a global daily cap.
  8. Deleting an account removes its login, profile and records and leaves other users untouched.

2. Level 1 — security rules and SDK sync (emulators)

tests-rules/rules.test.ts (10 tests) seeds three users (alice, bob, carol) and one administrator and checks every rule above with assertSucceeds/assertFails against Google's Firestore emulator running the real firebase/firestore.rules. tests-rules/cloud.test.ts (4 tests) uses the app's real sync code with the Firebase SDK: registration with age confirmation, records only under the own uid, a second device of the same user receiving data live while other users' data never appears, and the older-copy rule. Result: 14/14. Details in MEGO_Integration_Testing.

3. Level 2 — browser multi-user suite (e2e/multiuser-test.mjs)

3.1 Environment

  • Several isolated Chromium contexts with the Playwright "Pixel 7" profile = several phones used at the same time (Alice in Arabic, Bob in English, Carol registered from country DE).
  • The built app served by vite preview (port 4188) with a demo Firebase config pointing to the Auth (9099) and Firestore (8080) emulators, project demo-mego.
  • AI backend = the real apps-script/Code.gs in e2e/gas-mock.mjs with AI_USER_DAILY_LIMIT set to 1 for the test; Gemini is a scripted stand-in.
  • Test accounts use @example.com addresses; SHOTS=1 also captures the welcome, registration, account and admin screenshots.

Result: 8/8 (latest recorded run).

4. Level 3 — production verification (scripts/live-verify.mjs)

Runs against the live site and the real Firebase project with two disposable accounts (A and B) that are deleted at the end. Its multi-user checks: two independent registrations; profiles stored on the server, each user reads only their own; food logging synced to the cloud; data isolation enforced by the server (cross-account read and anonymous read refused, 403); second-device sync; administrator functions refused for a regular account (cannot list profiles, cannot promote itself, cannot suspend others); deletion of both accounts. The run of 7 Nov 2026 passed 14/14. The script has since gained checks that cardio and workout records sync to the owner only and stay invisible to account B; a production run of that version is not recorded (Not verified).

6. Running the tests

npm run build
npm run test:rules     # 14 — Level 1
npm run e2e:multi      # 8  — Level 2 (firebase emulators:exec … node e2e/multiuser-test.mjs)
SHOTS=1 npm run e2e:multi   # also refreshes account/admin screenshots
node scripts/live-verify.mjs   # Level 3 — production, disposable accounts

7. Verification status

  • Tested on emulators: rules + cloud 14/14; browser multi-user 8/8.
  • Verified live: isolation (403), second-device sync, admin enforcement for regular accounts, password-reset request, deletion — live-verify 14/14 (7 Nov 2026).
  • Not verified: administrator functions on production (the owner has not yet created the admin account); suspension and shared-food review on production; per-user AI limit on production; behaviour with many concurrent users or near Firebase Spark free-tier limits; delivery of the reset e-mail to a real inbox. These suites were not re-run while writing this document.
