Purpose and scope

This document describes how MEGO is tested: the layers of the test pyramid, each automated suite in the repository, what each suite runs against (real code, official emulators, scripted stand-ins or the live production services) and which runs were executed against the live site. It covers the repository Mego2012/Mego, branch claude/nutrition-tracking-app-989rku, as of 7 November 2026.

1. Testing principles

  • Real code first. Tests import the real application modules (src/lib/*) and, for the backend, execute the real apps-script/Code.gs inside an in-memory emulation of Google Apps Script (e2e/gas-mock.mjs).
  • Exact expected values. Nutrition tests assert exact numbers (for example 100 g raw chicken breast = 120 kcal), never "approximately right".
  • No invented data. Tests check that missing values are never filled in (incomplete foods cannot be logged; missing amino-acid data stays missing).
  • Server-side security is tested on the server. Firestore security rules are tested with Google's official Firebase emulators, and on production by scripts/live-verify.mjs using only the test accounts' own tokens.
  • Honest labelling. Every result is labelled as verified live, tested on emulators, or not verified.
  • Private data stays private. The owner's real 160-food table (tests/private/foods-160.csv) is git-ignored; without it a synthetic fixture with the same names but made-up values is used and value-specific tests are skipped.

5. Live-site runs

  • The guest browser suite can target any deployment: E2E_BASE=https://mego2012.github.io/Mego/ npm run e2e → 44/44 against the live URL.
  • The touch suite accepts a base URL: node e2e/scroll-test.mjs https://mego2012.github.io/Mego/ → 103/103 against the live URL.
  • scripts/live-verify.mjs → 14/14 against production (two disposable mego-verify-…@example.com accounts, both deleted at the end). It writes a Markdown report to ~/.mego-backend/.
  • Guest-mode suites run without the production Firebase config (the production app shows the account welcome screen when Firebase is configured).

7. How to run the suites

npx tsc -b                      # TypeScript: 0 errors expected
npm test                        # unit, 109
npm run build
npm run e2e                     # 44 browser checks (starts vite preview)
npm run e2e:scroll              # 103 touch checks
npm run test:rules              # 14, needs firebase-tools (emulators)
npm run e2e:multi               # 8, needs firebase-tools (emulators)
npm run e2e:laptop              # 10
node e2e/migration-test.mjs <dir>   # dist-v1 + dist-v2 builds in <dir>
node scripts/live-verify.mjs    # production, 14

Browser suites use the pre-installed Playwright + Chromium.

8. Verification status

  • Verified live: e2e 44/44 and touch 103/103 against https://mego2012.github.io/Mego/; live verification 14/14 against Firebase project mego-473920; laptop-setup live checks on the owner's laptop.
  • Tested on emulators only: rules + cloud 14/14, multi-user 8/8, laptop-setup test 10/10, unit 109/109 (backend and Gemini emulated/simulated).
  • Not verified: physical Android device, real camera/barcode, PWA install on hardware, delivery of password-reset e-mail to a real inbox, Open Food Facts against the live service in an automated test.
