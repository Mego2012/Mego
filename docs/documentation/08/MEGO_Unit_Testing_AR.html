4. أساليب الاختبار المستخدمة

  • وحدات حقيقية وقاعدة بيانات في الذاكرة: دوال المستودع (addFoodEntry وsaveSettings…) تكتب في Dexie على fake-indexeddb تمامًا كما في المتصفح.
  • خادم حقيقي داخل محاكٍ: يحمّل e2e/gas-mock.mjs الملف apps-script/Code.gs ويحاكي SpreadsheetApp وDriveApp وPropertiesService وLockService وUrlFetchApp.
  • خدمات خارجية مبرمجة: استجابات Gemini وأخطاؤه (500، 503، 504، 400، 429) مبرمجة مسبقًا؛ وOpen Food Facts محاكى؛ ولا يتصل أي اختبار بخدمة خارجية.
  • أرقام دقيقة: مثلًا يجب أن تساوي roundMacros(e.macros) القيمة { kcal: 120, protein: 23, carbs: 0, fat: 2.6 }.
  • اختبارات سلبية: ما يجب ألا يحدث أبدًا (تطبيق التوصيات تلقائيًا، ملء البيانات الناقصة، نماذج ذكاء اصطناعي مدفوعة، حذف المكررات تلقائيًا).

5. تشغيل المجموعة وقراءة النتائج

npm test                     # whole suite
npx vitest run tests/core.test.ts          # one file
npx vitest run -t "TEST 1"                 # tests whose name matches

الملخص المتوقع: Test Files 14 passed (14) وTests 199 passed (199). تطبع اختبارات الماسح عمدًا أسطرًا مثل Gemini gemini-3.8-flash → 503 … في مخرج الأخطاء — وهي سيناريوهات الأخطاء المبرمجة وليست إخفاقات. استغرق التشغيل الكامل نحو 7 ثوانٍ.

6. كتابة اختبار وحدة جديد

  1. ضع الملف في tests/ بلاحقة .test.ts.
  2. استدعِ useDatabase('اسم-فريد') في beforeEach إذا كان الاختبار يستخدم قاعدة البيانات.
  3. استخدم البيانات من tests/fixtures/، ولا تُدرج أي بيانات شخصية أبدًا. احمِ الاختبارات التي تحتاج الجدول الخاص بـ it.skipIf.
  4. تحقق من قيم دقيقة، وأضف تأكيدًا واحدًا على الأقل لما «يجب ألا يحدث».
  5. شغّل npm test وnpx tsc -b قبل الإيداع؛ إذ يمنع CI النشر عند فشل أي اختبار.

7. حالة التحقق

  • مُتحقَّق منه (نُفِّذ لهذه الوثيقة): npx vitest run في 10 نوفمبر 2026 ← 14 ملفًا و199 اختبارًا ناجحًا؛ الأعداد لكل ملف أعلاه من ذلك التشغيل.
  • مُتحقَّق منه في الكود: الإعدادات، البيانات التجريبية، منطق التخطّي، خطوة CI ‏(.github/workflows/deploy.yml يشغّل npm test قبل البناء).
  • الحدود: لا تشغّل اختبارات الوحدة متصفحًا حقيقيًا ولا Firebase حقيقيًا ولا خدمات Google حقيقية ولا هاتفًا فعليًا؛ انظر MEGO_Integration_Testing وMEGO_Acceptance_Testing. نسبة تغطية الكود (Code Coverage) غير مقيسة (لا توجد أداة تغطية مهيأة) — غير مُتحقَّق منه.
