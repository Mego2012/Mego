Purpose and scope

This manual explains how an administrator account is created and how the administration dashboard (#/admin) of the MEGO app is used: the KPI tiles, the accounts list, suspending and reactivating accounts, reviewing food submissions, reading error reports and publishing verified foods to the shared database. It also states clearly what an administrator cannot see or do. Everything here is taken from src/pages/Account.tsx (AdminPage), src/lib/firebase.ts, firebase/firestore.rules and scripts/laptop-setup.mjs.

Important status note: as of 7 November 2026 no administrator account exists yet. The admin role is waiting for the owner (see section 2). The dashboard has only been exercised on the Firebase emulators and in the screenshot run, not by a real admin in production.

2. How an administrator is created

The admin role cannot be requested or granted from inside the app. The rule match /admins/{uid} { allow write: if false; } forbids every app client (including existing admins) from writing the admin list. It is written only with the owner's own Google credentials, by the setup script or the Firebase console.

2.1 Procedure (owner only)

  1. Open the live app https://mego2012.github.io/Mego/ and register a normal account with the e-mail address that should become admin (3-step registration).
  2. On the owner's laptop, in the MEGO repository folder, run:
    node scripts/laptop-setup.mjs --cloud <admin e-mail>
  3. The script looks up the e-mail in Firebase Authentication (Identity Toolkit accounts:lookup). If the account does not exist yet it prints "has no account yet: register in the app, then run again"; nothing is written.
  4. If it exists, the script writes the document admins/{uid} with one field since (timestamp) through the Firestore REST API using the owner's credentials, and reports "administrator role for <e-mail>" ✅ or ❌.
  5. In the app, sign out and sign in again (or reload). At start-up the app checks admins/{uid}; the button Administration then appears in the account card under Settings.

2.2 Removing an admin

There is no script flag and no in-app button to remove an admin. The owner deletes the document admins/{uid} in the Firebase console (Firestore → Data). This manual procedure is Not verified in production.

3. Opening the administration dashboard

  1. Sign in with the admin account.
  2. Go to Settings; in the account card press Administration (shield icon). Alternatively open #/admin directly, e.g. https://mego2012.github.io/Mego/#/admin.
  3. If the signed-in user is not an admin the page shows only "Administrators only." and loads nothing.

The dashboard loads four data sets at once (statistics, accounts, error reports, pending submissions). If any request fails, the error message is shown in a red banner at the top. The admin screen exists only in Arabic screenshots:

4. Dashboard tour: KPI tiles

The tiles use Firestore count aggregations (getCountFromServer) — only numbers are transferred.

TileExact definition (adminStats)

Active (7 days)Profiles with lastActiveAt ≥ now − 7 days (the app refreshes lastActiveAt when a signed-in user opens it)
SuspendedProfiles with status == "suspended"

When at least one account exists, a bar under the tiles shows the share of active accounts: round(active7d ÷ total × 100) %. Example: 40 registered, 10 active → 25 %.

5. Accounts list, suspend and reactivate

The Accounts card lists up to 100 profiles, newest first (orderBy createdAt desc, limit 100). Each row shows: initial avatar, display name, e-mail, country code, "since" (registration date), "last active" date and a status chip (Active / Suspended). There is no search or paging; accounts beyond the newest 100 are not shown (limitation).

5.1 Suspend an account

  1. Find the account row and press Suspend.
  2. The app writes status: "suspended" to profiles/{uid}. The security rules allow an admin to change only the status field and only to active or suspended.
  3. The list and tiles reload; "Saved" is confirmed.

Effect for the suspended user: the rules function isActive() becomes false, so the server refuses every read and write of the user's private data (users/{uid}/…), the shared foods and new submissions; the app shows the screen "Account suspended — This account has been suspended by the administrator. Your data is kept and nothing has been deleted." with only a Sign-out button. The AI meal-scanner proxy also refuses non-active accounts. The Firebase sign-in itself is not disabled, and no data is deleted.

5.2 Reactivate

Press Reactivate on a suspended row; status returns to active and the user regains access at next start.

5.3 Safeguard

The Suspend/Reactivate button is hidden on the admin's own row, so an admin cannot lock themself out from the UI.

6. Food submissions: approve or reject

A signed-in user can press "Suggest for the shared database" in the food editor of one of their own foods. This creates a foodSubmissions document (status: "pending", ownerUid, time, food values). Nothing is published automatically.

The card Food submissions to review lists up to 100 pending submissions with name, raw/cooked state, kcal, protein (P), carbs (C), fat (F) per 100 g, optional source reference and notes.

  1. Check the values against the label or a reliable source (the card reminds: "Approved foods become visible to every user").
  2. Approve: the food is copied to foods/U-<submissionId> with the note "user submission reviewed by admin", and the submission is marked approved. Every signed-in device receives it through its live listener on foods.
  3. Reject: the submission is only marked rejected; nothing is published.

Limitations: values cannot be edited in the dashboard (approve as-is or reject); the submitter is not notified in the app; there is no "unpublish" button (see MEGO_Food_Database_Administration).

7. Error reports

The Error reports card shows the latest 50 reports (kind chip, message, date). Reports are created automatically by the app; in the current code the only source is a failed cloud-sync push (kind: "sync"). The rules allow only the fields at, kind, message, app, a message under 500 characters (the app truncates to 400) and no personal fields. Only admins can read them. The rules also allow admins to delete reports, but the dashboard has no delete button.

8. Shared food database: publish verified foods

The Shared food database card has the button Publish verified foods. It takes the foods on this device whose source is the Hub/imported sheet (source: "sheet"), that are not archived and not incomplete, and writes each one to foods/{id} (id = the Hub's stable F0001… key when present). The message "Published N foods." confirms the count. USDA foods are built into the app and are not published this way. Details and preconditions: MEGO_Food_Database_Administration.

9. AI usage statistics

The dashboard does not show AI statistics. The Apps Script backend has an admin-only action aiStats (verifies the Firebase ID token and the admins/{uid} document) that returns, for the last 7 days, the number of scans and of distinct users per day, the model name, whether a key is configured and the per-user / global daily limits — but no screen in the app calls it. Until a screen exists, the owner can read the daily counters (AI_USED_<date>) in the Apps Script editor's Script Properties (never share a screenshot of that page: it also holds the Gemini key and the app token).

10. What administrators can NOT see or do

Not possible for an adminEnforced by
Read any user's diary, weights, measurements, recipes, plans, settings or any record under users/{uid}Rule: only the owner of the uid, while active
See progress photosPhotos are never uploaded at all
Change a user's name, e-mail, country or datesRule: admin may change only status
Delete accounts or profiles, reset passwordsNo such function in the app; profile delete is owner-only in the rules
Grant or remove the admin roleadmins write is false for all clients
See meal photos sent to the AI scannerThe backend stores nothing about the meal
Read the Hub (Google Sheet) of the ownerThe Hub is reachable only through the owner's Apps Script with the secret token

The dashboard repeats this at the top: "Administrators see account cards and totals only. Diaries, weights, photos and other personal records are never accessible here — the server rules forbid it." Note: the Project Owner, through the Firebase console, has technical access beyond these rules; that access is governed by MEGO_Access_Control_and_Permissions.
